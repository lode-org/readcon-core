\begin{frontmatter} \input{authors.tex} \begin{abstract} This supplement gives the normative specification of CON 3.1.
CON is a geometry format used in eOn, ASE and other codes, and CON 3.1 formalizes and extends it.
The supplement gives the reader rules, the test run of the release with the source lines of each step of its reader, the CON 3.1 corpus with the cross-check and the header variants, and the survey and drift files with the mechanism given to each library.
It also gives the records beside a checkpoint with what the specification of each format states, the restart protocol, the velocity unit and the identifiers, the timing method and tables, the measured versions, and the commands that rebuild the paper.
\end{abstract} \end{frontmatter}

The source of each generated table names the script that writes it, and Table~\ref{tab:versionmap} names the record behind each result.
Each reader rule gives an input and the outcome that follows from it.
We take a wall time as the median of at least six repeats and report the type 7 interquartile range.
We compare the readers on the same file and the same host, one cell at a time.
Two reads are equal when their coordinates match, and we count the frames that a reader returns and the bytes that it keeps.
We draw each restored figure from a stored record.
We build the library from the commit named in Data availability of the manuscript, and we name no version deposit before its record exists.
The machine line of a record gives only the architecture, the processor count and the processor string.

\section{Normative specification}\label{sec:spec-normative} The typeset normative specification is \texttt{docs/orgmode/spec.org} of commit \texttt{e8abd818}, git blob \texttt{\specTextBlob}, with its version line, its date and its \specClauses{} numbered clauses.
A script of the paper typesets that file, and its check mode fails unless the typeset text matches the file.
The version line names readcon-core~\specTextRelease{}, and that version is not a release tag.
The \readconcommitrole{} \texttt{\readconcommitshort} (readcon-core~\rcMeasuredVersion{}) has specification source git blob \texttt{\rcMeasuredSpecBlob}, and that blob is not the typeset text.
Two informative sentences of its units section round the value the parser gives the natural time unit and its difference from the value of eOn, and the supplement omits them.
The parser reads \texttt{(amu*angstrom\^{}2/eV)\^{}0.5} as the binary64 number \(\velNaturalFsBinary\,\mathrm{fs}\), eOn hard-codes \(\velEonFs\,\mathrm{fs}\), and their difference relative to the parsed value, computed in binary64, is \(\velEonRelDiff\) (Section~\ref{sec:supp-velocity}).
readcon-core~\readconCargoVersion{} is the program this paper describes, and the reader it ships follows blob \texttt{\rcMeasuredSpecBlob}, not the typeset text.
Each clause keeps its identifier, so a clause that the corpus manifest or an error message cites has the same text in the supplement.
The manuscript measures the clauses against the reader on the conformance corpus (Section~\ref{sec:conformance}).
The specification also points to an informative parsing expression grammar (PEG) that the library ships, which is not reproduced.
The reader-compatibility notes and the references of the source are omitted, because they describe other programs.

\FloatBarrier \section{The CON 3.1 corpus, the cross-check and the header variants}\label{sec:supp-corpus31} The CON 3.1 corpus, the second corpus of Section~\ref{sec:conformance}, has \cthreeoneFiles{} files in the records of the paper, which a script of the paper writes byte for byte, and its manifest names for each file the outcome, the clauses that decide it and the basis of that outcome in the released text.
Its results record holds the outcome of every file at one, two and eight threads and the default, from the \texttt{corpus31\_report} example of readcon-core, and the build that read the files.
The corpus-path run reads the \cpathsFiles{} files of both corpora through the string, file, mapped, gzip and iterator reads and the frame count of the readcon module and of the C library.
The C library is read in its serial C library build and built with \texttt{parallel}, as the release archives build it, and the module also reads the plain and the gzip file through its stream reader, \texttt{iter\_con(stream=True)}.
Every file takes \cpathsReadKinds{} reads, except that the \cpathsNotText{} files that are not UTF-8 take no \texttt{read\_con\_string} read.
All \cpathsMatch{} of the \cpathsReads{} reads return the outcome of the manifest entry of their file, with its frame count or error class (Table~\ref{tab:corpus-paths}).
The record keeps the verdict of every read with the builds that made them.
The every-path count runs the \everyPathTestFiles{} reader-path test files of readcon-core with the \texttt{zstd} and \texttt{parallel} features, \everyPathTests{} tests in all, and counts the \everyPathInputs{} inputs that passed every path, each logged once as given and once padded.
Table~\ref{tab:corpus31-open} lists the \cthreeoneNotExplicit{} entries whose outcome no clause decides by name, each with the reading that its manifest entry records and that readcon-core follows.
Table~\ref{tab:corpus-crosscheck} is the cross-check run over both corpora, beside the independent reader of Section~\ref{sec:conformance} of the manuscript; its two records keep the outcome of every reader on every file.

The mutant differential reads edited copies of corpus files with readcon-core and with the independent reader.
A case takes one of the \mutantFiles{} files of the CON 3.1 corpus under \mutantMaxBytes{} bytes and makes one to three edits at random places: it inserts a token, deletes one to eight characters or replaces one character with a token.
The tokens are whitespace and line ends, digits, signs and JSON punctuation, component headers, keys of line 2, element symbols and a whole velocity block, and the record lists them.
\texttt{random.Random} draws the file, the edits and the tokens from the seed.
Each of the \mutantSeeds{} seeds gives the same \mutantPerSeed{} cases on every run, and a check run repeats them.
The comparison covers the verdicts and the frame counts or error classes and leaves out the lines, since the exceptions of the readcon module carry none.
The record still keeps the error line of each reader.
All \mutantDiffer{} differing cases fall in one group, and a variant of the independent reader that follows readcon-core on the rule of that group returns the verdict and class of readcon-core on each of them.
In each case, line 2 contains a number such as \texttt{1e999}, which the JSON grammar of Request for Comments (RFC)~8259 admits and binary64 cannot represent.
The independent reader rejects such a number anywhere in line 2, and readcon-core keeps it in an unreserved key and reads on; no clause requires either reading.
The clause-coverage record lists for each of the \clauseTotal{} clauses the corpus files whose manifest entries name it, the probes whose rules name it, the tests of the library whose names or documentation name it and whether the independent reader names it.
No file, probe or test names CON-file.6, CON-header.1, CON-count.5, CON-count.6, CON-mask.6, CON-mask.7, CON-id.2, CON-id.7, CON-section.3, CON-section.5, CON-section.6, CON-section.10, CON-section.11, CON-section.18, CON-section.19, CON-validate.2, CON-bonds.1, CON-bonds.2, CON-units.15, CON-num.4, CON-compress.4, CON-compress.5 and CON-token.1; \texttt{paper/cpc/scripts/clause\_coverage.py} writes this list from the specification, corpus manifests, probes and test sources.

\FloatBarrier \section{Survey frame, grading and drift files}\label{sec:supp-failure} The survey frame of Table~\ref{tab:survey} is a Pt(100) slab of \(2\times2\times2\) atoms with 6\hspace*{.2em}\AA{} of vacuum and one Pt adatom 1.8\hspace*{.2em}\AA{} above the hollow site; Listing~\ref{lst:frame} prints it.
Every coordinate carries a uniform offset of up to \(10^{-3}\,\text{\AA}\) from a fixed seed, so writing it back takes all seventeen significant digits.
The bottom four atoms are held in every component, and the adatom is held in \(z\).
The identifiers are 17, 3, 11, 5, 23, 2, 13, 7 and 41 in row order.
Velocities are normal deviates of standard deviation \(4\times10^{-3}\) in the natural unit, zero on held components.

Each library is given each field through the mechanism its own documentation names, Table~\ref{tab:mechanisms}.
A field counts as kept when it reads back equal.
A velocity is declared when the file names its unit and the values agree after conversion to within \(10^{-6}\) relative.
A velocity has ``no unit'' when it comes back from a file that names no time unit, whatever unit the reader then applies.
Read as \(\text{\AA}/\mathrm{fs}\), the natural-unit velocities of the frame give a kinetic energy \(\velFactorSq\) times too large.
One rule labels a field that came back.
It is fixed by the format when the format's own specification defines the name and meaning of the place it was stored in, and a convention when only a library's documented layout defines that place, so only readers that share the layout get it back.
A label is an identifier that came back only inside the site name of a Crystallographic Information File (CIF).
A file is named ``H5MD, private mask dataset'' when it has the H5MD root group and its version and keeps the mask in a dataset that H5MD does not define.

\FloatBarrier \section{Python bindings and thread safety}\label{sec:supp-threads}
The PyO3 module declares that it does not need the global interpreter lock (\texttt{gil\_used = false}).
Continuous integration runs the tests on free-threaded Python \texttt{3.13t} and \texttt{3.14t}, and on the standard builds.
Parsing, formatting, file writes and correspondence checks detach the Python thread state with \texttt{py.detach}, so other Python threads run while they do.
Each write path first copies or converts whatever input Python can reach, while still attached, and only then formats, compresses and writes while detached.
This includes compressed writes of frame lists that do not keep their parsed frames, plain writes after indexing, and appends of \texttt{ConFrame} lists.
\texttt{touch\_checksum()} needs the shared coordinate slab, so it copies the slab element by element while attached and then walks the frames detached.
On a frame that Python has not indexed, \texttt{coords\_array()} copies the coordinates from the parsed buffer into a new NumPy array without building a Python object for each atom.
Once the atom list of a frame exists, \texttt{coords\_array()} reads that list, so edits made in place remain visible.

\texttt{ConFrameList} keeps its parsed frames behind a read-write lock of its own.
When every frame is still in the list, plain writes, compressed writes, string output, identifier checks and \texttt{touch\_checksum()} hold one read lock across the detached call instead of moving frames out, so other threads see the full list and a panic leaves the frames intact.
When indexing has moved a frame out into a Python object, the writers go through the list frame by frame.
A thread that waits for the list lock or the frame cache detaches before it blocks, so a detached holder can attach again without deadlock.
Indexing a frame locks the cache before the list and caches the indexed frame object.
Under the write lock of the list, indexing also marks any shared coordinate slab as reachable from Python before it moves that slot out.
\texttt{columns()} takes the write lock, so detached readers finish before Python receives the shared coordinate array.

When Python can reach the coordinates of a frame, through the shared array of \texttt{columns()} or the \texttt{xyz} array of the frame, the attached thread copies them into a private buffer before the detached work starts, and the other fields are borrowed from the frames.
Each aligned double is copied with one relaxed \texttt{AtomicU64} load \cite{bosRustAtomicsLocks2023}, so no single value is torn.
The loads are not atomic across elements, and a thread that writes during the copy can leave the buffer holding elements from different instants.
Frames whose coordinates Python cannot reach are written without the copy.
When a shared list is written again, the writer keeps the copied buffer of the previous write and reuses its packed frame lengths while every frame matches that buffer bit for bit.
From the first frame that differs, the writer makes a fresh copy.

\texttt{write\_columns}, \texttt{write\_extxyz} and \texttt{write\_conbin\_columns} treat NumPy arrays the same way, copying them in runs of about \(4\) MiB while attached, validating each run there where the format requires it, and formatting or writing each run while detached.
No Rust slice is ever formed over numeric memory that Python owns and can change.

The fourth campaign asks for shuffle-zstd on every read, so it measures what the codec trades.
On the membrane-protein trajectory the shuffled cache stores its frames in \num{\rdbMembraneFrameShare} of the raw bytes and the whole corpus in \num{\rdbMembraneCorpusShare} of them.
On one thread the median warm full read of the shuffled cache takes \num{\rdbMembraneRatio} of the median raw time, and the paired interval of the shuffled over the raw time runs from \num{\rdbMembraneColdLo} to \num{\rdbMembraneColdHi} for a cold full read and from \num{\rdbMembraneWarmLo} to \num{\rdbMembraneWarmHi} for a warm full read, each from \rdbMembranePairs{} pairs (\rdbMembraneCIMethod).
The codec saves storage and cold read time and costs warm decode time.

The timing scripts run their cells in interleaved rounds, one untimed round and then the timed rounds, each round a new shuffle of the cells from a fixed seed and each run of a cell a new process, and each timing record keeps its seed and its number of rounds.
