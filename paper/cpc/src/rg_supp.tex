\section{Normative specification}\label{sec:spec-normative}
This section states the CON 3.1 specification as readcon-core 0.22.0 distributes it.
The relative difference between the parsed natural time unit and the eOn constant is \(2.07\times 10^{-8}\).
Each clause keeps its identifier, so a clause cited in the corpus manifest or an error message names the same text here.
Section~\ref{sec:conformance} of the manuscript measures the clauses against the reader on the conformance corpus.
The distributed text cites an informative parsing expression grammar (PEG), the surface grammar, and the clauses in this section are the specification.

\FloatBarrier \section{The CON 3.1 corpus, the cross-check and the header variants}\label{sec:supp-corpus31}
The corpus writer produces the \cthreeoneFiles{} files of that corpus byte for byte, and the manifest names for each file the outcome, the clauses that decide it and the basis of that outcome in the released text.
All \cthreeoneMatch{} files return the outcome of their entry at one, two and eight threads and at the default.
The path check reads the \cpathsFiles{} files of both corpora through the string, file, mapped, gzip and iterator reads and the frame count of the readcon module and of the C library.
The C library is read in its default build and built with \texttt{parallel}, as the release archives build it, and the module also reads the plain and the gzip file through its stream reader, \texttt{iter\_con(stream=True)}.
Every file takes \cpathsReadKinds{} reads, except that the \cpathsNotText{} files that are not UTF-8 take no \texttt{read\_con\_string} read.
All \cpathsMatch{} of the \cpathsReads{} reads return the outcome of the manifest entry of their file, with its frame count or error class (Table~\ref{tab:corpus-paths}).
The default build and the parallel build both return that verdict.
The path count runs the \everyPathTestFiles{} reader-path test files of readcon-core with the \texttt{zstd} and \texttt{parallel} features, \everyPathTests{} tests in all, and counts the \everyPathInputs{} inputs that passed every path, each read once as given and once padded.
Table~\ref{tab:corpus31-open} lists the \cthreeoneNotExplicit{} entries whose outcome no clause decides by name, each with the reading that its manifest entry records and that readcon-core follows.
Table~\ref{tab:corpus-crosscheck} is the cross-check over both corpora, beside the independent reader, and it records the outcome of every reader on every file.

A case takes one of the \mutantFiles{} files of \texttt{corpus31} under \mutantMaxBytes{} bytes and makes one to three edits at random places: it inserts a token, deletes one to eight characters or replaces one character with a token.
The tokens are whitespace and line ends, digits, signs and JSON punctuation, component headers, keys of line 2, element symbols and a whole velocity block.
\texttt{random.Random} draws the file, the edits and the tokens from the seed.
Each of the \mutantSeeds{} seeds gives the same \mutantPerSeed{} cases on every run, and \texttt{\texttt{-}\texttt{-}check} reruns them.
The comparison covers the verdicts and the frame counts or error classes.
readcon-core reports an error line on each failed read, and the comparison leaves that line out, because the exceptions of the readcon module carry none.
Each group has a variant of the independent reader that follows readcon-core on one rule.
A differing case belongs to the first group whose variant returns the verdict and class of readcon-core.
All \(\mutantDiffer\) differing cases fall in the count-line group.
The first variant is a count line with the wrong number of tokens and a token that is not an unsigned integer, so it breaks CON-error.3 and CON-num.9 on one line; CON-error.4 orders errors by line alone, and readcon-core checks the number of tokens first, the independent reader each token first.
The second variant is line 2 with a number such as \texttt{1e999}, which the JSON grammar of Request for Comments (RFC)~8259 admits and binary64 cannot represent.
The independent reader rejects such a number anywhere in line 2, and readcon-core keeps it in an unreserved key and reads on; no clause requires either reading.
The third variant is a last byte that is a carriage return, of which CON-file.3 states nothing: readcon-core reads it as a line end, so the input ends in trailing whitespace, and the independent reader takes it for line 1 of a further frame, which ends before its line 2.
The clause coverage lists for each of the \clauseTotal{} clauses the corpus files whose manifest entries name it, the probes whose rules name it, the tests of the library whose names or documentation name it and whether the independent reader names it.
No file, probe or test names CON-count.5, a SHOULD NOT on writing for a given consumer, since no writer of readcon-core takes a consumer or a target version; CON-section.10 and CON-section.11, which govern how a later revision adds a reserved section name; and CON-section.18, a SHOULD on the energies a producer stores, whose reader side CON-section.19, accepting a frame whose energy differs from the sum of its energies rows, the energy-sum mismatch test reads.

The test \texttt{differential\_\allowbreak corpus\_\allowbreak mutations\_\allowbreak agree\_\allowbreak across\_\allowbreak entry\_\allowbreak points} of the iterator tests draws 140 cases, each conformance file and each test file with one of four edits: a form feed, a no-break space, two blank lines, or a further section at its end.
Each case is read from a string and from bytes at one to sixteen threads, by the stream reader at read sizes of 1 and 61 bytes and 1~MiB, and by the column reader with the positions alone and with every section, from bytes and streamed from the file.
It is then written to a plain and a gzip file, and each file is read again at the same thread counts, with the stream reader and through the indexed trajectory.
Every read returns the frame count, the coordinates and the section presence of the one-thread string read or stops with its error at the same line, and the trajectory refuses to open a file only when the string read rejects the case.
One case in every 305 is also padded with blank lines past the mapping threshold and read as a mapped file at one to sixteen threads, and each read returns the outcome of a one-thread read of the padded text.
\texttt{cargo test \texttt{-}\texttt{-}release --lib differential\_corpus} runs it.

\FloatBarrier \section{Survey frame, grading and drift files}\label{sec:supp-failure} The survey frame of Table~\ref{tab:survey} is a Pt(100) slab of \(2\times2\times2\) atoms with 6\hspace*{.2em}\AA{} of vacuum and one Pt adatom 1.8\hspace*{.2em}\AA{} above the hollow site; Listing~\ref{lst:frame} prints it.
In this supplement, \(1\,\text{\AA}=10^{-10}\,\mathrm{m}\) and \(1\,\mathrm{eV}=1.602176634\times10^{-19}\,\mathrm{J}\).
A millielectronvolt is \(10^{-3}\) of that electronvolt, and a compound such as \(\mathrm{eV}/\text{\AA}\) uses the same two equivalents.
Every coordinate carries a uniform offset of up to \(10^{-3}\,\text{\AA}\) from a fixed seed, so writing it back takes all seventeen significant digits.
The bottom four atoms are held in every component, and the adatom is held in \(z\).
The identifiers are 17, 3, 11, 5, 23, 2, 13, 7 and 41 in row order.
Velocities are normal deviates of standard deviation \(4\times10^{-3}\) in the natural unit, zero on held components.

Each library is given each field through the mechanism its own documentation names, Table~\ref{tab:mechanisms}.
A field counts as kept when it reads back equal.
A velocity is declared when the file names its unit and the values agree after conversion to within \(10^{-6}\) relative.
A velocity has ``no unit'' when it comes back from a file that names no time unit, whatever unit the reader then applies.
Read as \(\text{\AA}/\mathrm{fs}\), the natural-unit velocities of the frame give a kinetic energy \(\velFactorSq\) times too large.
One rule labels a field that came back.
It is fixed by the format when the format's own specification defines the name and meaning of the place it was stored in, and a convention when only a library's documented layout defines that place, so only readers that share the layout get it back.
A label is an identifier that came back only inside the site name of a Crystallographic Information File (CIF).

\subsection{Same-file and nearest-native panel}\label{sec:h2h} The
same-file comparison reads one con file.
The readers are readcon from C, Fortran, and Python, the upstream eon
client, eon Python, and the Atomic Simulation Environment (ASE) with the
eon format.
The nearest-native panel reads different files that carry the same atoms
and the same cell.
NumPy reads an npy coordinate array, which has no cell.
ASE and chemfiles read extended xyz.
OVITO reads extended xyz.
pymatgen reads a POSCAR.
MDAnalysis reads a protein data bank file with a crystal record.
That panel is separate from the con table.
A row passes only when the atom count, the cell, and the coordinates
match.
NumPy has no cell, so that row fails the cell check.

The extended XYZ head-to-head uses one copper grid for every arm.
The files are 10 atoms in 1 frame and in 8 frames, 1000 atoms in 1
frame, 100 atoms in 100 frames, \(10^{6}\) atoms in 1 frame, and 100
atoms in 10000 frames.
The run is pinned with \texttt{taskset -c 0}, with one thread.
One warmup call is excluded.
The six repeats are serial.
A time in Table~\ref{tab:extxyz-h2h} and Table~\ref{tab:extxyz-h2h-write}
is the type 7 median, and the spread is the type 7 interquartile range.
Before the clock, every arm is compared with the grid on species,
positions, masses, forces and the cell.
Those fields agree for every reader that finishes.
The largest absolute difference is 0.
readcon writes species, positions, the lattice and every per-atom
column, including forces.
The Python writer formats the caller's numeric columns in place.
On the million-atom file the Rust writer takes 0.487~s and the Python
writer takes 0.442~s.
On the 10000-frame file those medians are 0.431 and 0.411~s.
A write's RSS and massif are measured in a fresh process after the

A gzip or zstd member index is rejected when its plain length overflows the member sum, when a row span skips an atom, or when the plain length is shorter than the inflated member.
Lengths that do not fit the file fall back to the full parser or return an error.
Truncation, a bad count, a non-finite coordinate, a CRLF line and a missing newline are checked at one thread and at eight.
Miri does not model file-backed mmap, \texttt{mincore}, \texttt{readahead} or \texttt{MADV\_POPULATE\_READ}, so those calls are not what the Miri run executes.
The pread that fills a binary coordinate file runs under Miri with \texttt{-Zmiri-disable-isolation}.
