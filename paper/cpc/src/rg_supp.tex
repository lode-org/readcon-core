\begin{frontmatter} \input{authors.tex} \begin{abstract} This supplement gives the normative specification of CON 3.1.
CON is a geometry format used in many codes, and readcon-core formalizes it.
The supplement also states the reader rules.
It then gives the test run of the release with the source lines of each step of its reader, the CON 3.1 corpus with the cross-check and the header variants, and the survey and drift files with the mechanism given to each library.
The last sections give the records beside a checkpoint with what the specification of each format states, the restart protocol, the velocity unit and the identifiers, the timing method and tables, the measured versions, and the commands that rebuild the paper.
\end{abstract} \end{frontmatter}

We keep the specification, the corpora and the timing records in this supplement.
We name the script that writes each table.
We state a reader rule as an input and the outcome that follows from it.
We measure a wall time as the median of at least six repeats.
We place the type 7 interquartile range next to that median.
We compare each peer on the same file and the same host.
We call two reads equal when their coordinates match.
We count the frames a reader returns and the bytes it keeps.
We draw each restored figure from a record in this directory.
We leave a version deposit unnamed until the record exists.
We build the library from the public commit named in the manuscript.
We run one cell at a time on one host.
We keep the machine line to the architecture, the processor count and the processor string.

\section{Normative specification}\label{sec:spec-normative} This section is the specification of CON 3.1 as readcon-core~\readconversion{} distributes it, the file \texttt{docs/\allowbreak orgmode/\allowbreak spec.org} of the \readconcommitrole{} \texttt{\readconcommitshort} at git blob \texttt{\specTextBlob}.
\texttt{scripts/\allowbreak gen\_spec\_supp.py -{}-as-is} typesets that file, and its \texttt{-{}-check} fails unless the typeset text matches the file.
That file is byte for byte the CON 3.1 text of readcon-core~\specTextRelease{}, the first release that includes it, with its version line, its date and its \specClauses{} numbered clauses.
The library test \texttt{tests/\allowbreak ci\_gates.rs} runs \texttt{scripts/\allowbreak check\_spec\_text.sh}, which fails when the two differ.
Two informative sentences of its units section round the value the parser gives the natural time unit and its difference from the value of eOn, and they are left out here.
The parser reads \texttt{(amu*angstrom\^{}2/eV)\^{}0.5} as the binary64 number \(\velNaturalFsBinary\,\mathrm{fs}\), eOn hard-codes \(\velEonFs\,\mathrm{fs}\), and their difference relative to the parsed value, computed in binary64, is \(\velEonRelDiff\) (\texttt{bench/\allowbreak results/\allowbreak velocity\_case.json}).
The reader it specifies is readcon-core~\readconversion{}.
Each clause keeps its identifier, so a clause cited in the corpus manifest or an error message names the same text here.
Section~\ref{sec:conformance} of the manuscript measures the clauses against the reader on the conformance corpus.
The specification also points to an informative parsing expression grammar (PEG), \texttt{grammar/\allowbreak readcon.pest}, which is not reproduced.
The reader-compatibility notes and the references of the source are omitted, because they describe other programs.

\FloatBarrier \section{The CON 3.1 corpus, the cross-check and the header variants}\label{sec:supp-corpus31} This section describes the second corpus of Section~\ref{sec:conformance}, the cross-check of both corpora and the seven headers of Table~\ref{tab:versionsafety}.
\path{paper/cpc/data/corpus31} contains the \cthreeoneFiles{} files of that corpus, which \texttt{scripts/\allowbreak make\_corpus31.py} writes byte for byte, and its \texttt{manifest.toml} names for each file the outcome, the clauses that decide it and the basis of that outcome in the released text.
\path{paper/cpc/data/corpus31-results.json} is the record of \texttt{scripts/\allowbreak corpus31\_results.py}: the outcome of every file at one, two and eight threads and the default, from the \texttt{corpus31\_report} example of readcon-core, and the build that read the files.
\texttt{scripts/\allowbreak corpus\_paths.py} writes \path{paper/cpc/data/corpus_paths.json}.
It reads the \cpathsFiles{} files of both corpora through the string, file, mapped, gzip and iterator reads and the frame count of the readcon module and of the C library.
The C library is read in its default build and built with \texttt{parallel}, as the release archives build it, and the module also reads the plain and the gzip file through its stream reader, \texttt{iter\_con(stream=True)}.
Every file takes \cpathsReadKinds{} reads, except that the \cpathsNotText{} files that are not UTF-8 take no \texttt{read\_con\_string} read.
All \cpathsMatch{} of the \cpathsReads{} reads return the outcome of the manifest entry of their file, with its frame count or error class (Table~\ref{tab:corpus-paths}).
The record keeps the verdict of every read with the builds that made them.
\path{paper/cpc/data/every_path.json} is the record of \texttt{scripts/\allowbreak every\_path\_count.py}, which runs the \everyPathTestFiles{} reader-path test files of readcon-core with the \texttt{zstd} and \texttt{parallel} features, \everyPathTests{} tests in all, and counts the \everyPathInputs{} inputs that passed every path, each logged once as given and once padded.
Table~\ref{tab:corpus31-open} lists the \cthreeoneNotExplicit{} entries whose outcome no clause decides by name, each with the reading that its manifest entry records and that readcon-core follows.
Table~\ref{tab:corpus-crosscheck} is the run of \texttt{scripts/\allowbreak corpus\_crosscheck.py} over both corpora, beside the independent reader \texttt{scripts/\allowbreak indep\_reader.py}; \path{paper/cpc/data/corpus_crosscheck.json} and \path{paper/cpc/data/corpus_crosscheck.csv} record the outcome of every reader on every file.

\path{paper/cpc/data/spec/mutant_differential.json} is the record of \texttt{scripts/\allowbreak mutant\_differential.py}.
A case takes one of the \mutantFiles{} files of \path{paper/cpc/data/corpus31} under \mutantMaxBytes{} bytes and makes one to three edits at random places: it inserts a token, deletes one to eight characters or replaces one character with a token.
The tokens are whitespace and line ends, digits, signs and JSON punctuation, component headers, keys of line 2, element symbols and a whole velocity block, and the record lists them.
\texttt{random.Random} draws the file, the edits and the tokens from the seed.
Each of the \mutantSeeds{} seeds gives the same \mutantPerSeed{} cases on every run, and \texttt{-{}-check} reruns them.
The comparison covers the verdicts and the frame counts or error classes and leaves out the lines, since the exceptions of the readcon module carry none.
The record still keeps the error line of each reader.
Each group has a variant of the independent reader that follows readcon-core on one rule.
A differing case belongs to the first group whose variant returns the verdict and class of readcon-core.
In the first group, a count line has the wrong number of tokens and a token that is not an unsigned integer, so it breaks CON-error.3 and CON-num.9 on one line; CON-error.4 orders errors by line alone, and readcon-core checks the number of tokens first, the independent reader each token first.
In the second, line 2 contains a number such as \texttt{1e999}, which the JSON grammar of Request for Comments (RFC)~8259 admits and binary64 cannot represent.
The independent reader rejects such a number anywhere in line 2, and readcon-core keeps it in an unreserved key and reads on; no clause requires either reading.
In the third, the last byte of the input is a carriage return, of which CON-file.3 states nothing: readcon-core reads it as a line end, so the input ends in trailing whitespace, and the independent reader takes it for line 1 of a further frame, which ends before its line 2.
\path{paper/cpc/data/spec/clause_coverage.json}, the record of \texttt{scripts/\allowbreak clause\_coverage.py}, lists for each of the \clauseTotal{} clauses the corpus files whose manifest entries name it, the probes whose rules name it, the tests of the library whose names or documentation name it and whether the independent reader names it.
No file, probe or test names CON-count.5, a SHOULD NOT on writing for a given consumer, since no writer of readcon-core takes a consumer or a target version; CON-section.10 and CON-section.11, which govern how a later revision adds a reserved section name; and CON-section.18, a SHOULD on the energies a producer stores, whose reader side CON-section.19, accepting a frame whose energy differs from the sum of its energies rows, \texttt{tests/\allowbreak clause\_coverage.rs} reads.

The test \texttt{differential\_\allowbreak 19545\_\allowbreak agree\_\allowbreak across\_\allowbreak entry\_\allowbreak points\_\allowbreak and\_\allowbreak thread\_\allowbreak counts} of \texttt{src/\allowbreak iterators.rs} draws 19,545 cases from a fixed seed, each a test file or a conformance file of the release with one edit, such as a form feed, a no-break space, two blank lines or a further section at its end.
Each case is read from a string and from bytes at one to sixteen threads, by the stream reader at read sizes of 1 and 61 bytes and 1~MiB, and by the column reader with the positions alone and with every section, from bytes and streamed from the file.
It is then written to a plain and a gzip file, and each file is read again at the same thread counts, with the stream reader and through the indexed trajectory.
Every read returns the frame count, the coordinates and the section presence of the one-thread string read or stops with its error at the same line, and the trajectory refuses to open a file only when the string read rejects the case.
One case in every 305 is also padded with blank lines past the mapping threshold and read as a mapped file at one to sixteen threads, and each read returns the outcome of a one-thread read of the padded text.
\texttt{cargo test -{}-release -{}-lib differential\_19545} runs it.

\FloatBarrier \section{Survey frame, grading and drift files}\label{sec:supp-failure} The survey frame of Table~\ref{tab:survey} is a Pt(100) slab of \(2\times2\times2\) atoms with 6\hspace*{.2em}\AA{} of vacuum and one Pt adatom 1.8\hspace*{.2em}\AA{} above the hollow site; Listing~\ref{lst:frame} prints it.
Every coordinate carries a uniform offset of up to \(10^{-3}\,\text{\AA}\) from a fixed seed, so writing it back takes all seventeen significant digits.
The bottom four atoms are held in every component, and the adatom is held in \(z\).
The identifiers are 17, 3, 11, 5, 23, 2, 13, 7 and 41 in row order.
Velocities are normal deviates of standard deviation \(4\times10^{-3}\) in the natural unit, zero on held components.

Each library is given each field through the mechanism its own documentation names, Table~\ref{tab:mechanisms}.
A field counts as kept when it reads back equal.
A velocity is declared when the file names its unit and the values agree after conversion to within \(10^{-6}\) relative.
A velocity has ``no unit'' when it comes back from a file that names no time unit, whatever unit the reader then applies.
Read as \(\text{\AA}/\mathrm{fs}\), the natural-unit velocities of the frame give a kinetic energy \(\velFactorSq\) times too large.
One rule labels a field that came back.
It is fixed by the format when the format's own specification defines the name and meaning of the place it was stored in, and a convention when only a library's documented layout defines that place, so only readers that share the layout get it back.
A label is an identifier that came back only inside the site name of a Crystallographic Information File (CIF).
A file is named ``H5MD, private mask dataset'' when it has the H5MD root group and its version and keeps the mask in a dataset that H5MD does not define.
