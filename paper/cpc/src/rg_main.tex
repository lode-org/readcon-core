\begin{abstract}
Rare-event methods resume a saddle search from a stored geometry and
match atoms across frames by an identifier on each row.
CON is the geometry file those methods exchange, and it had no
specification.
Here, we introduce readcon-core, the reference reader and writer of
CON 3.1, a versioned grammar for that text.
Two conformance corpora, 165 files in all, define which files a
conforming reader accepts.
The writer prints the shortest decimal that reads back as the same
binary64 value, and the frames of one file are parsed in parallel.
One Rust core serves C, C++, Fortran, Julia and Python and exports
coordinate arrays through DLPack.
eOn, an ASE plugin and chemfiles read and write CON through that core.
readcon-db stores the corpora, and readcon-ops compares frames, aligns
them and builds a Wulff construction.
On the Claisen rearrangement of allyl vinyl ether the stored atom ids
converge to a 0.607~eV barrier, and a geometric renumbering of the same
product does not.
On 4096 molecules of mW water, d-SEAMS follows each molecule by that id,
and neighbour pairs persist at 0.955 on CON against about 0.001 when the
same frames are written in a new atom order.
A Rust read of \num{100000} CON frames takes 0.179~s, against 10.8~s for
ASE's eon reader and 10.3~s for eOn's Python reader \texttt{loadcons}, a
development build of eOn 3.6.0.
readcon-core is available under the MIT licence at
\url{https://github.com/lode-org/readcon-core}.
\end{abstract}

\textit{Nature of problem:} Rare-event methods resume a saddle search
from a stored geometry and match atoms across frames by an identifier
on each row.
The checkpoint also stores which Cartesian components are held and the
time unit of the velocities, because a lost hold changes the prefactor
and a misread unit scales the kinetic energy.
A restart that repeats the interrupted run reads the binary64
coordinates back as written.
CON is the geometry file those methods exchange, and it had no
specification.

\textit{Solution method:} CON 3.1 is a versioned grammar for that text,
and readcon-core is the reference reader and writer that formalizes and
improves it.
The second line of a frame is a JSON object that declares the major and
minor version, the units, the periodic flags and the per-atom sections
after the coordinates.
The fourth column of a coordinate row is a three-bit mask of fixed
components and the fifth an atom identifier.
From minor 1 a velocity section declares its time unit.
A reader of a known major accepts any later minor, keeps unknown keys
and skips a later section by its declared width.
The writer prints the shortest decimal that reads back as the same
binary64 value, and the reader rounds each decimal to the nearest
binary64 value.
Two corpora of legal and illegal files define which files a conforming
reader accepts.
readcon-core implements the grammar once in Rust, behind a C interface
for C++, Julia and Fortran and a PyO3 binding for Python.
On more than one thread it walks the frame boundaries serially by the
counts in each header, parses the frames in parallel and returns them in
file order.
A path writer opens the destination and truncates it, then writes the
frames into that file.

\section{Introduction}\label{sec:introduction} Rare-event methods turn a
potential energy surface into rates.
Transition state theory
\cite{eyringActivatedComplexChemical1935,vineyardFrequencyFactorsIsotope1957,hanggiReactionrateTheoryFifty1990}
reduces the kinetics of an activated process to its saddle points and
the vibrations there.
The saddles are located by the nudged elastic band
\cite{jonssonNudgedElasticBand1998,henkelmanClimbingImageNudged2000,henkelmanImprovedTangentEstimate2000,asgeirssonNudgedElasticBand2021},
by minimum-mode followers, and by Gaussian-process acceleration of those searches
\cite{henkelmanDimerMethodFinding1999,kastnerSuperlinearlyConvergingDimer2008,olsenComparisonMethodsFinding2004,goswamiGaussianProcessSaddle2025,goswamiAdaptivePruning2026,goswamiTutorialReviewBayesian2026}
and by string methods
\cite{eStringMethodStudy2002,petersGrowingStringMethod2004}.
Adaptive kinetic Monte Carlo (AKMC) and accelerated dynamics chain them
into trajectories of seconds and longer
\cite{henkelmanLongTimeScale2001,xuAdaptiveKineticMonte2008,voterExtendingTimeScale2002,perezLongtimeDynamicsThrough2016}.
A long-timescale run in eOn
\cite{chillEonSoftwareLong2014,rohitgoswamiTheochemuieonV3602026} spawns
thousands of saddle searches, often on volunteer or distributed
resources
\cite{andersonBoincSystemPublicresource2004,pedersenDistributedImplementationAdaptive2010}.
It passes their geometries between Python drivers
\cite{larsenAtomicSimulationEnvironmenta2017,hermesSellaOpensourceAutomationfriendly2022},
C++ engines and Fortran electronic structure codes
\cite{kresseEfficiencyAbinitioTotal1996}.
A search that stops on one machine resumes on another from a geometry
file, the checkpoint of the search.

The checkpoint has to return four fields that a trajectory reader can
ignore.
A surface search fixes the slab and can hold an adatom at a set height
while it crosses the surface, so mobility belongs to each Cartesian
component, and a lost hold changes the saddle that the search converges
to (Section~\ref{sec:prefactor}).
Mode following and AKMC bookkeeping match atoms across frames and events
by an identifier on each row.
A reader has to return that identifier as written rather than as the row
order.
Dynamical steps read velocities, and the natural time unit of eOn is
\((\mathrm{amu}\,\text{\AA}^2/\mathrm{eV})^{1/2}=\wkTimeFs\,\mathrm{fs}\),
so a reader that takes the same numbers as \(\text{\AA}/\mathrm{fs}\)
scales the kinetic energy by \(\velFactorSq\).
A restart that repeats the interrupted run to roundoff reads back
binary64 coordinates
\cite{ieeecomputersocietyIeeeStandardFloatingpoint2019}.
For that, the writer prints the shortest decimal that reads back as the
same double
\cite{steeleHowPrintFloatingpoint1990,adamsRyFastFloattostring2018}, and
the reader rounds each decimal to the nearest double
\cite{clingerHowReadFloating1990}.
Two readers given the same bytes must then return the same fields, and
that takes a versioned grammar rather than the convention of one reader.
On the Claisen rearrangement the stored ids select a converged 0.607~eV
chair, and a geometric renumbering of the same product does not converge
(Section~\ref{sec:claisen}).
The same reader carries a 4096-molecule water trajectory into d-SEAMS
(Section~\ref{sec:connectivity}) and resumes a saddle search from the
stored mask and coordinates (Section~\ref{sec:cases}).

Existing formats keep some of these fields.
Extended XYZ adds key-value metadata to the comment line of the plain
Cartesian coordinate format (XYZ) and publishes a grammar
\cite{kermodeLibatomsExtxyzV0462026}.
It keeps masks and identifiers in column names that the Atomic
Simulation Environment (ASE) chose
\cite{larsenAtomicSimulationEnvironmenta2017}, and a file declares no
version and no velocity unit.
H5MD
\cite{buylH5mdStructuredEfficient2014,folkOverviewHdf5Technology2011}
stores identity, velocities with units and the box in HDF5, and it
defines no element for a per-component constraint.
XTC, TRR, DCD and TNG store molecular-dynamics output with neither a mask nor a velocity unit, and the GROMACS trajectory that replaces TNG is still an H5MD file with no per-component constraint (Section~\ref{sec:supp-formats}).
The ASE trajectory keeps every field in a layout that the Python code of
ASE defines.
POSCAR, the structure file of the Vienna Ab initio Simulation Package
\cite{vaspwikiPoscar2026,kresseEfficiencyAbinitioTotal1996}, stores a
per-component hold as selective-dynamics flags but no atom identifier.
Many of these formats are read and written by chemfiles
\cite{frauxChemfileschemfilesVersion01042023,frauxChemfiles2023},
MDAnalysis
\cite{gowersMdanalysisPythonPackage2016,michaudAgrawalMDAnalysisToolkit2011},
the Open Visualization Tool (OVITO)
\cite{stukowskiVisualizationAnalysisAtomistic2010} and Open Babel
\cite{oboyleOpenBabelOpen2011}.
IMD version 3 streams positions, velocities, forces and the box from a running GROMACS, NAMD or LAMMPS simulation into MDAnalysis \cite{thirumalaiswamyStreamingMolecularDynamics2026}.
ReaxKit prepares, parses and analyses ReaxFF trajectories \cite{dinaniReaxkitModularPython2026}.
None of chemfiles, MDAnalysis, OVITO or Open Babel opens a CON file
(versions in Section~\ref{sec:performance}).
The eon module of ASE opens both but stops at the velocity section of the
frame of Section~\ref{sec:worked}.

Most atomistic formats have no specification apart from the code that
reads them, so that code is the de facto definition of the format.
Particle physics fixed the files that pass between independent event
generators in published texts: the Les Houches event file
\cite{Alwall2007LHEF}, the second Les Houches Accord for supersymmetric
spectra \cite{Allanach2009SLHA2} and the HepMC3 library for generator
events \cite{Buckley2021HepMC3}.
Electronic structure has done the same for densities and wavefunctions
with the European Theoretical Spectroscopy Facility (ETSF) file format
\cite{Gonze2008ETSF} and TREXIO \cite{posenitskiyTrexioFileFormat2023},
and for pseudopotentials with the pseudopotential markup language (PSML)
\cite{Garcia2018PSML}.
A computed barrier is reproducible from a file only when every reader
returns the same fields from it.
A versioned specification and a corpus of files with known verdicts turn
that condition into a test of any reader.

Here, we introduce readcon-core, the reference reader and writer of
CON 3.1, a versioned grammar for that checkpoint.
Section~\ref{sec:identity} is the atom correspondence a rare-event method
assumes.
Section~\ref{sec:fields} states the stored fields, Section~\ref{sec:worked}
reads one frame and Section~\ref{sec:format} is the grammar.
Section~\ref{sec:implementation} describes the program, its bindings and
the companion tools.
Section~\ref{sec:conformance} is the corpora.
Section~\ref{sec:claisen} is the Claisen rearrangement,
Section~\ref{sec:connectivity} follows molecules through a nucleation
trajectory, and Section~\ref{sec:cases} resumes saddle searches.
Section~\ref{sec:performance} is the performance.
The grammar places a version, the units and the periodic flags on a JSON
header line, a three-bit mask and an atom identifier on each coordinate
row, and a time unit on any velocity section.
CON 3.1 is the first written specification of CON, and readcon-core is the only reader tested that returns the mask, the id, the masses and the time unit together.

\section{Atom correspondence in rare-event methods}\label{sec:identity}
A rare-event method compares two geometries atom by atom.
The path, the tangent, the displacement, the Hessian and the rate are defined only when atom \(i\) in image A is atom \(i\) in image B.
Write the \(3N\) Cartesian coordinates of an image, in one fixed order, as the vector \(R\).
The improved NEB tangent at image \(i\) is built from the forward and backward differences
\begin{equation}
\label{eq:tangent}
\tau_i^{+}=R_{i+1}-R_i,\qquad \tau_i^{-}=R_i-R_{i-1},
\end{equation}
and the spring force lies along that tangent
\cite{jonssonNudgedElasticBand1998,henkelmanImprovedTangentEstimate2000},
\begin{equation}
\label{eq:spring}
F_i^{\parallel}=k\big(|R_{i+1}-R_i|-|R_i-R_{i-1}|\big)\,\hat\tau_i.
\end{equation}
A permutation matrix \(\Pi\) applied to one image replaces \(R\) by \(\Pi R\).
The differences in Eq.~\eqref{eq:tangent} then connect different atoms, and the spring in Eq.~\eqref{eq:spring} pulls along that wrong chord.
The dimer axis, the Cartesian RMSD and the Vineyard prefactor pair the same slots (Section~\ref{sec:supp-pairing}, Eqs.~\eqref{eq:dimer}, \eqref{eq:rmsd} and~\eqref{eq:vineyard}).
A permutation reorders the Hessian, and a mask that frees one more component changes which eigenvalues enter the prefactor.

A file that stores coordinates and element symbols, and no atom index, leaves the map to the next program.
An XYZ written and read through a SMILES canonicalisation, an Open Babel conversion or an RDKit molecule rebuild can return the atoms in a new order.
A POSCAR groups atoms by the element block.
A LAMMPS dump written with atoms sorted by type does the same.
In each case Eq.~\eqref{eq:tangent} is evaluated on a vector whose slots no longer name the atoms of the previous image.
The band still returns a number.
That number is the barrier of a different path.

\section{The CON 3.1 format}
\subsection{Stored fields}\label{sec:fields}
CON 3.1 stores, on each frame, the coordinates, the full \(3\times 3\) cell including the axes the periodic flags leave open, a mass on each atom, a three-bit mask, an atom id, and a velocity section with its own time unit.
The id is what a band, a dimer and an AKMC comparison need after a file reorders the rows, and readcon keeps it through the read and the write.
The mask is an integer from 0 to 7, Eq.~\eqref{eq:mask}.
Dropping the hold on the Pt(100) adatom selects another saddle, \(0.68\,\mathrm{eV}\) with a prefactor 37 times larger (Section~\ref{sec:prefactor}).
The mass enters the Lagrangian, Eq.~\eqref{eq:lagrangian}, and the velocity section names its time unit.
The same digits read as \(\text{\AA}/\mathrm{fs}\) scale the kinetic energy by \(\velFactorSq\), Eq.~\eqref{eq:tau}.
What each other format keeps of these fields, and the bridges into eOn and chemfiles, is Section~\ref{sec:supp-fields}.
Section~\ref{sec:cases} measures these fields on one restarted band.
A CON 3.1 round trip returns the uninterrupted barrier.
A file that moves a coordinate or drops the mask returns a different one.

\subsection{One frame}\label{sec:worked}
Listing~\ref{lst:frame}, Table~\ref{tab:frame} and Figure~\ref{fig:layout} are one CON 3.1 frame, a Pt(100) slab of two layers of four atoms with one adatom, and the rule that reads each line (Section~\ref{sec:supp-frame}).
The reader rebuilds the cell from the lengths and angles, Eqs.~\eqref{eq:cell} and~\eqref{eq:gram}.
The mask is Eq.~\eqref{eq:mask}.
The velocity section uses the unit the header names, Eq.~\eqref{eq:tau}, and a reader that takes those numbers as \(\text{\AA}/\mathrm{fs}\) scales the kinetic energy by \(\velFactorSq\).
The coordinates are printed in the shortest decimal that reads back as the same binary64 value.
A version-1 header, anything other than one JSON object, is the text that earlier eOn releases write.

\subsection{Grammar}\label{sec:format}
Section~\ref{sec:spec-normative} is the normative specification, \clauseTotal{} numbered clauses.
The production of one frame, the clauses this argument uses, and the rule for a later minor are Section~\ref{sec:supp-grammar}.
Each number is a finite decimal that the reader rounds to the nearest binary64 value, ties to even.
The default writer prints the shortest decimal that rounds back to the same value, so writing a frame and reading it back returns every coordinate unchanged, and a setting prints six fixed decimals instead.
A gzip or zstd envelope wraps the same text, and a reader recognises it by content.
A reader accepts a later minor of a known major, keeps an unknown key on rewrite, and rejects any other major.
A later minor never makes a reader reject a file that an earlier minor requires it to accept.

\section{Program description}\label{sec:implementation}
readcon-core implements the grammar once, in Rust
(Figure~\ref{fig:architecture}).
C++, Julia \cite{bezansonJuliaFreshApproach2017} and Fortran 2008 call
its C interface, and Python calls the Rust core through PyO3 and
receives NumPy arrays \cite{harrisArrayProgrammingNumpy2020}.
eOn links readcon-core through the C++ wrapper, and its public release
\eOneEonVersion{} embeds readcon-core \eOneEonReadcon, which writes
CON~3.0 \cite{rohitgoswamiTheochemuieonV3602026}.
That layering follows chemfiles
\cite{frauxChemfileschemfilesVersion01042023}, one core with a binding
for each language, and we take it over unchanged.

\begin{figure*}[tbp] \centering
\includegraphics[width=\textwidth]{figures/generated/architecture.pdf}
\caption{\textbf{One Rust core serves every language.} C, C++ (including
eOn), Julia and Fortran call the core through the C interface, and
Python calls it through PyO3. An arrow runs from the caller to the code
it calls.}
\label{fig:architecture} \end{figure*}

The released API in readcon-core 0.21.0 pairs atoms by the column-5 id.
\texttt{atom\_id\_permutation} returns the permutation \(\Pi\) of Section~\ref{sec:identity}: for each atom of the reference frame, the index of the same id in the other frame.
\texttt{reorder\_like} rewrites that frame into the reference order, and positions, velocities, forces and bond endpoints move with the atom.
\texttt{check\_atom\_id\_consistency} names the first frame of a band or a trajectory that disagrees with the first frame, by frame index and atom id.
\texttt{minimum\_image\_displacements} returns the wrapped displacement of each matched pair.
Python, C and C++ expose the four calls (Table~\ref{tab:correspondence}, Section~\ref{sec:supp-api}).
\texttt{check\_atom\_id\_consistency} in strict mode, the default, also requires the mass and the fixed mask to agree.

In the core, Algorithm~\ref{alg:parser} of Section~\ref{sec:supp-parser} is the path reader of the
release.
A plain file of fewer than \(B_{\mathrm{map}}=\wkMmapBytes\) bytes is
read whole into memory, a larger one is memory-mapped, and a gzip or
zstd file is decompressed into memory whatever its size.
One thread parses frame after frame.
Two or more threads parse in a pool, with no length cutoff.
The parallel path walks the frame boundaries in one thread, because the
start of each frame depends on the counts before it, then parses the
frames independently and returns them in file order.
Table~\ref*{tab:anchors} of the supplementary material gives the source
lines of each step.
Figure~\ref{fig:parser} is that read.
A coordinate row is three decimals, a mask and an optional identifier.
The short decimal and the Eisel--Lemire path are in Section~\ref{sec:supp-cell}.


One frame of \(N\) atoms costs \(\Theta(N)\) time and memory.
For a text of \(B\) bytes, after inflation for a gzip or zstd file, the
read costs one serial \(\Theta(B)\) boundary walk and a \(\Theta(B)\)
parse that \(P\) threads share, and the frames it returns occupy
\(\Theta(B)\) memory.
A compressed file of \(C\) bytes is first inflated by one serial decoder
in \(\Theta(C+B)\) time.
The peak resident set of each reader on the Xeon is in
Section~\ref{sec:host}.

A path writer opens the destination and truncates it, then writes the
frames into that file.
A failure during the write leaves a partial file.
A writer to a string, or to a stream the caller opened, writes into that
stream.
Listing~\ref{lst:py} of Section~\ref{sec:supp-parser} reads a band from Python and writes it back to the same path, which the writer truncates when the write opens.

\subsection{Companion programs}\label{sec:ecosystem}
readcon-core parses CON and convel and returns the coordinates as the column \(R\) of Eq.~\eqref{eq:tangent} or as one frame object per image.
C, C++, Fortran, Julia and Python call that parser.
The Fortran binding is there because scientific codes still call Fortran
\cite{kedwardStateFortran2022}.
A quantum-chemistry input parser is held to the same standard, that the text it reads is the calculation it runs
\cite{goswamiWailordParsers2022}.
Algorithm~\ref{alg:parser} is the path reader.
The C entry \(\texttt{rkr\_read\_positions}\) and the Rust entry \(\texttt{read\_positions}\) both return that column, and the coordinates match.
The same read and write keep \texttt{atom\_id}.

readcon-db, under the MIT licence, from \url{https://github.com/lode-org/readcon-db}, stores the corpus in LMDB.
A frame key is 12 bytes, the trajectory id and the frame index, and the record is the CON text (Section~\ref{sec:supp-tools}).
The commands are \texttt{ingest}, \texttt{select}, \texttt{dedup-export}, \texttt{annotate-topology}, \texttt{find-by-topology}, \texttt{shard}, \texttt{compact} and \texttt{h5md-velocities}.
seams-core selects from the corpus by element or by formula (Section~\ref{sec:connectivity}).
In the AKMC catalog amsel, each process stores its barrier, its prefactor and its mode, and points at three frames: the reactant, the saddle and the product.
The saddle carries a displacements section with the same fixed-flag column and the same \texttt{atom\_id} column as the coordinates.

readcon-ops, under the BSD 3-clause licence, from \url{https://github.com/lode-org/readcon-ops}, is a Python API.
It has no command line and no file input or output.
The argument is a \texttt{ConFrame} or a pyeonclient object, and the distances come from lode-org/minimage.
\(\texttt{identical}(a, b, \epsilon_r)\) matches atoms of one element under the minimum image, and each index is claimed once.
The tolerance argument is \(\epsilon_r\).
\texttt{internal\_motion} removes a rotation by the Kabsch fit, with the masses as optional weights.
On a periodic frame it removes only the mean minimum-image translation, and the correspondence is the index.
\texttt{rotational\_match} calls the iterative rotations and assignments alignment through pyeonclient
\cite{gundeIRAShapeMatching2021}.
\texttt{spacegroup} calls spglib.
The API also provides \texttt{wulff\_vertices}.
The three programs split the work as parse, store and compare (Table~\ref{tab:commands}, Section~\ref{sec:supp-commands}).

\section{Applications}
\subsection{Claisen}\label{sec:claisen}
Allyl vinyl ether rearranges to pent-4-enal by a [3,3] sigmatropic shift
\cite{bakerLocationTransitionStates1996}.
The reactant and the product are the same fourteen atoms.
The path breaks one C--O bond and forms one C--C bond through a six-membered chair.
The endpoints are the benchmark CON frames, used as written.
Energies and forces are PET-MAD-S, version 1.1.0, through metatomic
\cite{mazitovPETMADLightweight2025,bigiMetatensorMetatomicFoundational2026}.
The band is an OCI-NEB with a climbing image
\cite{henkelmanClimbingImageNudged2000}, run in eOn 3.6.0 on one CPU
\cite{rohitgoswamiTheochemuieonV3602026}.
A climbing image aligned to a Hessian eigenmode has the same pairing of the atoms
\cite{goswamiEnhancedClimbingImage2026}.

Label the atoms once, in the reactant.
The product coordinates \(R^{\mathrm{P}}\) in that same label enter the linear image
\begin{equation}
\label{eq:lerp}
R(s)=(1-s)\,R^{\mathrm{R}}+s\,R^{\mathrm{P}},\qquad s\in[0,1].
\end{equation}
The path length of Eq.~\eqref{eq:lerp} is \(|R^{\mathrm{P}}-R^{\mathrm{R}}|\).
A second labelling \(\Pi\) of the product replaces the length by \(|\Pi R^{\mathrm{P}}-R^{\mathrm{R}}|\).
The NEB tangent and the spring, Eqs.~\eqref{eq:tangent} and~\eqref{eq:spring}, then follow whatever nuclei the new slots happen to pair.

The chemical correspondence is the identity permutation carried by the atom ids of the two frames.
That band converges.
It has ten images, eight of them between the endpoints, and takes 453 force calls, and the climbing-image force is \(0.042\,\mathrm{eV/\text{\AA}}\).
The barrier is 0.607~eV (14.0~kcal/mol).
The highest image is a connected six-membered chair (Figure~\ref{fig:claisen-struct}).
The forming distance C5--C0 is \(2.046\,\text{\AA}\) and the breaking distance C2--O is \(1.488\,\text{\AA}\).
One internal mode is imaginary, at \(-542.5\,\mathrm{cm}^{-1}\).

IRA reassigns the same product by the minimum-Hausdorff permutation (Section~\ref{sec:supp-claisen-protocol}).
The shorter distance pairs the wrong nuclei, and that band does not meet the \(0.05\,\mathrm{eV/\text{\AA}}\) criterion.
Its highest image lies at 3.988~eV (92.0~kcal/mol), separated into C0--C1--C2\({=}\)O and a detached C4--C5, with O--C4 at \(2.874\,\text{\AA}\) (Figure~\ref{fig:claisen-struct}).
Three internal modes are imaginary, at \(-251\), \(-135\) and \(-123\,\mathrm{cm}^{-1}\).
Figure~\ref{fig:claisen-land} is the plane of reaction progress and orthogonal deviation.

The minimum-Hausdorff assignment minimises a distance.
The chemical map is the atom id, and that id has to travel with the coordinates.
A CON row stores the id beside the position, and readcon returns the id with the position.
The released API in readcon-core 0.21.0 checks the correspondence on a constructed test frame, the Claisen endpoints rewritten oxygen-first, with C5 shifted one cell of \(18\,\text{\AA}\) along \(+x\).
It is not a third Claisen result.
Pairing rows by file position puts the reactant oxygen against the shifted C5, a raw, unwrapped step of 15.761~\text{\AA}.
The minimum image of that pairing is 2.272~\text{\AA}.
Pairing by id follows the vinyl-ether O--C4 bond, 1.360~\text{\AA}, to the C4\({=}\)O carbonyl of pent-4-enal, 1.210~\text{\AA}, a shortening of 0.150~\text{\AA}, and brings C5 back across the cell.
A three-image band whose middle image exchanges the atoms of ids 0 and 5 stays consistent by id.
The first file slot of that image then differs by 3.615~\text{\AA}, and the id-matched atom of id 0 moves 0.018~\text{\AA}.
Duplicating atom id 2 in the third image is reported as frame 2 and that atom id.
Frame indices count from zero, so frame 2 is the third image.

The chair, the separated renumbered image and the two final bands are Figures~\ref{fig:claisen-struct} and~\ref{fig:claisen-band} (Section~\ref{sec:supp-claisen-draw}).
The plane of reaction progress and orthogonal deviation is Figure~\ref{fig:claisen-land}.

\subsection{Connectivity tracking in d-SEAMS}\label{sec:connectivity}
One trajectory suffices because the comparison is between two encodings of the same frames.
The system is mW water, 4096 molecules, and an 81-frame window around a CHILL+ ice core.
The same frames were written as CON and as XYZ with the atom order permuted independently in every frame.
The quench, the cutoff and the command that rebuilds Figure~\ref{fig:water} are in Sections~\ref{sec:supp-water-protocol} and~\ref{sec:supp-water}.

Persistence is the mean, over frames \(t\), of the fraction of a per-atom relation that is still true one lag later,
\begin{equation}
\label{eq:persist}
P(\tau)=\left\langle\frac{|A(t)\cap A(t+\tau)|}{|A(t)|}\right\rangle_{t},
\end{equation}
with \(A(t)\) the set of neighbour pairs, or of molecule labels, at frame \(t\) (Figure~\ref{fig:water}).
A neighbour drawn uniformly among the other molecules has chance \(z/(N-1)\), about 0.001, with \(z\) the number of neighbours of a molecule and \(N=4096\).
Two independent draws of the CHILL+ label agree with chance \(\sum_k p_k^{2}\), about 0.63, where \(p_k\) is the fraction of molecules of class \(k\).
Neighbour pairs on the CON frames persist at 0.955, 0.939, 0.927 and 0.897 for lags of 1, 5, 10 and 25 frames, and at about 0.001 on the permuted XYZ at every lag.
The CHILL+ type of a molecule persists at 0.800, 0.790, 0.785 and 0.771 on CON, and at 0.630--0.631 on the permuted XYZ.
Six-ring membership is 0.996--0.997 on CON and 0.995 on the permuted XYZ, because almost every molecule already sits in a six-ring, so it does not separate them.
Ring counts and ice counts match on every frame of the two files.
A whole-frame total survives the new order.
Following one molecule as it joins the ice nucleus uses the atom id.

The 81 frames, 4096 atoms each, were ingested into a readcon-db corpus and selected back by the formula \texttt{O:4096}.
All 81 frames returned, bitwise identical in the positions and in the cell.
The median wall time of that ingest and select is 0.578~s on the machine of Section~\ref{sec:compute}, and the eight repeats span 0.571--0.596~s.

\subsubsection{A climbing-image band through every route}
The protocol, the fixed parameters and the route-by-route results are Sections~\ref{sec:supp-protocol} and~\ref{sec:supp-restart}, Table~\ref{tab:params} and Table~\ref{tab:restartfmt} (Section~\ref{sec:supp-restart-tables}).
Uninterrupted, the band converges in \(\rfStepsUnint\) steps and
\(\rfCallsUnint\) force calls, with barrier
\(\rfBarrierUnint\,\mathrm{eV}\) and \(\rfModesUnint\) free modes on the
middle image.
We interrupt it after \(K\) steps, write it, read it back and resume it
to \(f_{\mathrm{band}}\), once per route.
A file that drops the hold resumes another relaxation, because the held height is not a stationary point of the free adsorbate.

The shortest CON round trip changes no coordinate, and the resumed band
is the uninterrupted band bit for bit: the same \(\rfStepsCon\) steps,
\(\rfModesCon\) free modes on the middle image, and the same coordinates
and energy on every image (Figure~\ref{fig:restartfmt}).
Every force evaluation builds its EMT calculators afresh, so a step
depends on the positions alone.
The ASE trajectory with identifiers in tags and H5MD written and read
with h5py return the same row.
Two columns of Table~\ref{tab:restartfmt} are different quantities.
File is the largest coordinate change on the written round trip.
Max displacement is how far the resumed band sits from the uninterrupted
band, and that displacement is what Figure~\ref{fig:restartfmt} plots.
POSCAR with the height held as FixScaled moves one written coordinate by
\(\num{\rfFileScaledNum}\,\text{\AA}\).
The resumed band moves by \(\num{\rfDispScaledLoNum}\) to
\(\num{\rfDispScaledHiNum}\,\text{\AA}\) and the barrier by
\(\num{\rfDeScaledLoNum}\) to \(\num{\rfDeScaledHiNum}\,\mathrm{eV}\),
the range over the four host builds.

\subsubsection{The mask and the prefactor}\label{sec:prefactor} A barrier
is one number, and the harmonic prefactor needs the free modes at the
saddle.
The rate is \(k=\nu\exp(-\Delta E^\ddagger/k_{\mathrm{B}}T)\) with the Vineyard prefactor of Eq.~\eqref{eq:vineyard}.
A mask that frees one more component can move the saddle itself, besides
adding a mode to each product.
We wrote the endpoints of the same slab through each route and read them
back before relaxing them, converged a climbing-image band with the fast
inertial relaxation engine (FIRE)
\cite{bitzekStructuralRelaxationMade2006}, and took the Hessian of the
highest image.
With the height held, the barrier is \(\eFiveBarrierHeld\,\mathrm{eV}\)
on a path of \(\eFivePathHeld\,\text{\AA}\).
The highest image has \(\eFiveModesHeld\) free modes, one imaginary mode
of \(\eFiveImagHeld\,\mathrm{meV}\) with \(\eFiveWeightHeld\) of its
weight on the lateral motion of the adatom, and a prefactor of
\(\num{\eFivePrefactorHeldNum}\,\mathrm{Hz}\).
CON 3.1, the ASE trajectory, FixScaled POSCAR and h5py H5MD all return
that prefactor (Table~\ref{tab:prefactor-routes}).
If the reader drops the height constraint, the band crosses a different
saddle at \(0.68\,\mathrm{eV}\), with a prefactor 37 times larger.
A misread of the natural unit as \(\text{\AA}/\mathrm{fs}\) scales the kinetic energy by \(\velFactorSq\) (Section~\ref{sec:supp-velunit}).

The route-by-route prefactors are Table~\ref{tab:prefactor-routes} (Section~\ref{sec:supp-restart-tables}).

\FloatBarrier \section{Conclusions}\label{sec:conclusions}
readcon-core is the reference reader and writer of CON 3.1, a versioned grammar checked by two conformance corpora.
It prints the shortest decimal that reads back as the same double, parses the frames of one file in parallel, and serves C, C++, Fortran, Julia and Python from one Rust core, including a DLPack view of the arrays.
eOn, an ASE plugin and chemfiles use that core.
readcon-db stores the corpora, and readcon-ops compares frames, aligns them and builds a Wulff construction.
On allyl vinyl ether the stored atom ids converge to a 0.607~eV chair, and the minimum-Hausdorff renumbering of the same product reaches 3.988~eV at two separated fragments and does not converge.
On 4096 molecules of mW water, d-SEAMS follows each molecule by the stored id, and neighbour pairs persist at 0.955 on CON against about 0.001 on a permuted XYZ.
A Rust read of \num{100000} CON frames takes 0.179~s, against 10.8~s for ASE's eon reader and 10.3~s for eOn \texttt{loadcons}.
CON stores the id with the per-axis mask, the masses and the time unit, and readcon keeps the id through read and write.
Dropping the height constraint on the Pt(100) adatom changes the prefactor by a factor of 37.
