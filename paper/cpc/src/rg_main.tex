\begin{abstract}
Saddle-point and rare-event searches are often stopped and resumed, sometimes in a different code from the one that started them.
The geometry file used for the restart then has to keep the per-component atomic constraints, the atom identifiers, the time unit of the velocities and the binary64 coordinates.
CON is the text geometry format of the eOn code, and it has had no specification.
Here, we present the CON 3.1 specification and readcon-core, its reference reader and writer.
A JSON header on the second line of each frame declares the grammar version and the physical units, each coordinate row stores a three-bit constraint mask and an atom identifier, and a reader of a given major version accepts later minor revisions.
Two conformance corpora of \corpusFiles{} legal and illegal files fix what a conforming reader returns, and every Python and C read path in readcon-core returns the verdict of every corpus file.
On a platinum slab, a climbing-image band resumed from CON 3.1 reproduces the uninterrupted band exactly, whereas dropping the height constraint of the adatom changes the prefactor by a factor of \sigfig{2}{\eFivePrefactorRatioFree}.
A borrowed DLPack view of \dlpackAtoms{} atomic positions costs \dlpackRatio{} times an explicit copy, the median of six runs.
\end{abstract}

\textit{Nature of problem:} Rare-event campaigns stop saddle searches and resume them from a stored geometry, often on another machine.
A resumed surface search has to know which Cartesian components of each atom are fixed, since a held component removes a mode from the harmonic prefactor and can move the saddle.
It also needs the identifier on each row, since events and band images are matched by atom identity, and the time unit of the velocities, since a misread unit scales the kinetic energy by the square of the conversion factor.
A restart that repeats the interrupted run to roundoff must further read back the binary64 coordinates as they were written.
Of the formats in common use, H5MD defines no mask element, the POSCAR structure file defines no atom identifier, and extended XYZ keeps both in column names chosen by one library and names no time unit.
CON, the geometry format of eOn, had no specification, so each reader decided for itself which files are legal and what each column means.

\textit{Solution method:} CON 3.1 is a versioned grammar for the CON text, and readcon-core is its reference reader and writer.
The second line of a frame is a JSON object that declares the major and minor version, the units, the periodic flags and the per-atom sections that follow the coordinates.
The fourth column of a coordinate row is a three-bit mask of the fixed components, and the fifth is an atom identifier.
From minor 1 onwards, a velocity section declares its time unit.
A reader of a known major accepts any later minor, keeps unknown keys and skips a section of a later minor by its declared width.
The writer prints the shortest decimal that reads back as the same binary64 value, and the reader rounds each decimal to the nearest binary64 value.
Two corpora of legal and illegal files fix the verdict of a conforming reader on the clauses of the specification.
readcon-core implements the grammar once in Rust, with a C interface for C++, Julia and Fortran and a PyO3 binding for Python.
With more than one thread, it walks the frame boundaries serially using the counts in each header, parses the frames in parallel and returns them in file order.
A writer given a path replaces the destination only after the last frame has been accepted.

\textit{Additional comments including restrictions and unusual features:} The release described here is readcon-core~\readconversion{} (Data availability).
Every build reads gzip input, while zstd input and parallel parsing are build features, both enabled in the Python wheel.
A frame stores Cartesian coordinates, the cell, the periodic flags, the mask, one identifier per atom, and optional per-atom velocities, forces, energies, charges, spins, magnetic moments, displacements and spreads.
It stores no optimizer history, so an optimizer with memory takes a different path after a restart.
Files written by earlier eOn releases are grammar version 1 and are read as such.
Velocities in a file of an earlier version are read in the natural time unit of eOn, whatever time unit the file names.
In Python, \texttt{readcon.read\_con(path)} returns the frames of a file (Listing~\ref{lst:py}).

\textit{References:} eOn \cite{chillEonSoftwareLong2014,rohitgoswamiTheochemuieonV3602026}; readcon-core releases \cite{goswamiReadconcoreConConvel2026}.

\section{Introduction}\label{sec:introduction} Rare-event methods turn a potential energy surface into rates.
Transition state theory \cite{eyringActivatedComplexChemical1935,vineyardFrequencyFactorsIsotope1957,hanggiReactionrateTheoryFifty1990} reduces the kinetics of an activated process to its saddle points and the vibrations about them.
The saddle points are located with the nudged elastic band \cite{jonssonNudgedElasticBand1998,henkelmanClimbingImageNudged2000,henkelmanImprovedTangentEstimate2000,asgeirssonNudgedElasticBand2021}, with minimum-mode following methods \cite{henkelmanDimerMethodFinding1999,kastnerSuperlinearlyConvergingDimer2008,olsenComparisonMethodsFinding2004} and with string methods \cite{eStringMethodStudy2002,petersGrowingStringMethod2004}.
Adaptive kinetic Monte Carlo (AKMC) chains such searches into state-to-state trajectories, and together with accelerated molecular dynamics it reaches milliseconds and longer \cite{henkelmanLongTimeScale2001,xuAdaptiveKineticMonte2008,voterExtendingTimeScale2002,perezLongtimeDynamicsThrough2016,chillEonSoftwareLong2014}.
A long-timescale run in eOn \cite{chillEonSoftwareLong2014,rohitgoswamiTheochemuieonV3602026} spawns thousands of saddle searches, often on volunteer or distributed resources \cite{andersonBoincSystemPublicresource2004,pedersenDistributedImplementationAdaptive2010}.
Their geometries pass between Python drivers \cite{larsenAtomicSimulationEnvironmenta2017,hermesSellaOpensourceAutomationfriendly2022}, C++ engines and Fortran electronic structure codes \cite{kresseEfficiencyAbinitioTotal1996}.
A search that stops on one machine is resumed on another from a geometry file, which is then the checkpoint of the search.

Such a checkpoint has to return four fields that a trajectory reader can ignore.
First, mobility belongs to each Cartesian component.
A surface search fixes the slab and may hold an adatom at a set height while it crosses the surface, and losing that hold changes the saddle the search converges to (Section~\ref{sec:prefactor}).
Second, mode following and the bookkeeping of AKMC match atoms across frames and events by an identifier on each row, so a reader has to return that identifier as written rather than the row order.
Third, dynamical steps read velocities.
The natural time unit of eOn is \((\mathrm{amu}\,\text{\AA}^2/\mathrm{eV})^{1/2}=\wkTimeFs\,\mathrm{fs}\), and a reader that takes the same numbers as \(\text{\AA}/\mathrm{fs}\) scales the kinetic energy by \(\velFactorSq\).
Finally, a restart that repeats the interrupted run to roundoff has to read back the binary64 coordinates \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019}.
This requires a writer that prints the shortest decimal that reads back as the same double \cite{steeleHowPrintFloatingpoint1990,adamsRyFastFloattostring2018} and a reader that rounds each decimal to the nearest double \cite{clingerHowReadFloating1990}.
Two readers given the same bytes must then return the same fields, which needs a versioned grammar rather than the conventions of one reader.

Existing formats keep some of these fields.
Extended XYZ adds key-value metadata to the comment line of the plain Cartesian coordinate format (XYZ) and publishes a grammar \cite{kermodeLibatomsExtxyzV0462026}.
It keeps masks and identifiers in column names chosen by the Atomic Simulation Environment (ASE) \cite{larsenAtomicSimulationEnvironmenta2017}, and a file declares neither a version nor a velocity unit.
H5MD \cite{buylH5mdStructuredEfficient2014,folkOverviewHdf5Technology2011} stores particle identifiers, velocities and the box in HDF5, with units through an optional module, but it defines no element for a per-component constraint.
The GROMACS compressed (XTC) and full-precision (TRR) trajectory formats \cite{abrahamGromacsHighPerformance2015}, the binary trajectory (DCD) format of CHARMM \cite{brooksCharmmBiomolecularSimulation2009} and the trajectory next generation (TNG) format \cite{spangbergTrajectoryNgPortable2011,lundborgEfficientExtensibleFormat2014} have no per-component mask.
XTC stores no velocities, and TRR, DCD and TNG store them in the units of the program that wrote them, without a field that declares the unit.
The Amber NetCDF convention declares a unit for every variable, the velocities included, but it defines neither an atom identifier nor a constraint \cite{amberNetcdfConvention2026}.
The ASE trajectory keeps every field, in a layout defined by the Python code of ASE.
POSCAR, the structure file of the Vienna Ab initio Simulation Package \cite{vaspwikiPoscar2026,kresseEfficiencyAbinitioTotal1996}, stores selective-dynamics flags along each lattice vector but no atom identifier.
Many of these formats are read and written by chemfiles \cite{frauxChemfileschemfilesVersion01042023}, MDAnalysis \cite{michaudAgrawalMDAnalysisToolkit2011,gowersMdanalysisPythonPackage2016}, the Open Visualization Tool (OVITO) \cite{stukowskiVisualizationAnalysisAtomistic2010} and Open Babel \cite{oboyleOpenBabelOpen2011}.
None of these four opens a version-1 CON file or a CON 3.1 file, while the eon module of ASE opens both but stops at the velocity section of the frame of Section~\ref{sec:worked}.
OVITO 3.16.1, the version of Section~\ref*{sec:supp-versions}, writes an extended XYZ file without the periodicity of the simulation cell, and that file has no place for a per-component constraint or a velocity time unit.
OVITO 3.17.0, released 2026-10-21, always writes the periodicity as \texttt{pbc}, and its XYZ reader accepts whitespace around \texttt{=}, escape sequences in quoted strings, array values and string columns \cite{ovitoNewFeatures31702026}, but its extended XYZ file still names no velocity time unit.
MDAnalysis reads one model of an mmCIF/PDBx file, with positions and a cell, and has no element for the mask either.
The Rust parser extxyz-ng also reads extended XYZ \cite{yuExtxyzNgV0022026}.
Under the specification, a comment line of key-value pairs without a \texttt{Properties} key makes the file plain XYZ, which carries neither the cell nor the mask.

Most atomistic formats have no specification apart from the code that reads them, so that code is the de facto definition of the format.
Other fields have fixed their interchange files in published texts.
In particle physics, the Les Houches event file passes parton-level events from matrix-element generators to shower generators \cite{Alwall2007LHEF}, the second SUSY Les Houches Accord passes spectra and decay tables between spectrum calculators, decay codes and event generators \cite{Allanach2009SLHA2}, and the HepMC3 library defines the event record that generators hand to analysis \cite{Buckley2021HepMC3}.
Electronic structure has done the same for densities and wavefunctions with the European Theoretical Spectroscopy Facility (ETSF) file format \cite{Gonze2008ETSF} and TREXIO \cite{posenitskiyTrexioFileFormat2023}, and for pseudopotentials with the pseudopotential markup language (PSML) \cite{Garcia2018PSML}.
A computed barrier can be reproduced from a file only when every reader returns the same fields from it.
A versioned specification together with a corpus of files of known verdicts makes that condition a test that any reader can run.

In this paper, we present the CON 3.1 specification and readcon-core, its reference implementation.
CON 3.1 adds a JSON header line that declares the format version, the physical units and the periodic flags, stores a three-bit constraint mask and an atom identifier on each coordinate row, allows declared per-atom sections, and reads each coordinate back as the binary64 value that was written.
The parser is one Rust core with C, C++, Python, Julia and Fortran interfaces, similar in layout to chemfiles \cite{frauxChemfileschemfilesVersion01042023}, and it provides borrowed DLPack views of the positions at \dlpackRatio{} times the cost of an explicit copy (Section~\ref{sec:dlpack}).
Section~\ref{sec:worked} steps through a reference frame and gives the effect of each field on a restart, and Section~\ref{sec:format} states the normative grammar and the version rules.
Sections~\ref{sec:implementation} and~\ref{sec:conformance} describe the implementation and test it against both conformance corpora.
Section~\ref{sec:cases} resumes saddle searches from checkpoints written and read back with readcon-core and with other libraries, and Section~\ref{sec:performance} compares read times with ASE, eOn, chemfiles, MDAnalysis, OVITO, pymatgen, h5py and NumPy.
Of the formats in this comparison, only CON 3.1 specifies all four checkpoint fields, and readcon-core is the only reader here that returns the constraint mask, the atom identifier and the velocity time unit from fields its own specification defines, while accepting later minor revisions.

The header line is one JSON object \cite{brayJavascriptObjectNotation2017}, recognized by its first non-blank character, \texttt{\{}.
A frame whose header is anything else is grammar version~1, the text written by earlier eOn releases.
In Listing~\ref{lst:frame} the object names the major and minor version of the grammar, declares the slab periodic in \(x\) and \(y\) and open in \(z\), lists \texttt{velocities} as the only section after the coordinates, and gives the units of length, energy, mass and time.

The two cell lines carry the lengths \(a=b\approx\wkLengthA\,\text{\AA}\) and \(c=\wkLengthC\,\text{\AA}\) and the angles \(\alpha\), \(\beta\) and \(\gamma\) in degrees.
From these the reader rebuilds the cell with \(\mathbf{a}\) along \(x\) and \(\mathbf{b}\) in the \(xy\) plane, the restricted triclinic form of LAMMPS \cite{thompsonLammpsFlexibleSimulation2022},
\begin{equation}
\label{eq:cell}
\begin{aligned}
\mathbf{a}&=a\,\hat{\mathbf{x}},\qquad
\mathbf{b}=b\cos\gamma\,\hat{\mathbf{x}}+b\sin\gamma\,\hat{\mathbf{y}},\\
\mathbf{c}&=c\cos\beta\,\hat{\mathbf{x}}+c\,\kappa\,\hat{\mathbf{y}}+c\sqrt{\rho}\,\hat{\mathbf{z}},\\
\kappa&=\frac{\cos\alpha-\cos\beta\cos\gamma}{\sin\gamma},\qquad \rho=1-\cos^2\beta-\kappa^2.
\end{aligned}
\end{equation}
In binary64 the cosine of the double nearest \(\pi/2\) is \(\num{\wkCosRight}\), so for this cell Eq.~\eqref{eq:cell} gives \(b_x=\num{\wkBx}\,\text{\AA}\) and \(c_x=c_y=\num{\wkCxy}\,\text{\AA}\).
ASE~\wkAseVersion{} instead returns \(b_x=\wkAseRightBx\), since it sets to zero the cosine of any angle within two units in the last place of a right angle \cite{larsenAtomicSimulationEnvironmenta2017}.

Whether three angles describe a cell at all depends on the radicand \(\rho\).
The volume of the cell of Eq.~\eqref{eq:cell} is \(V=a\cdot b\sin\gamma\cdot c\sqrt{\rho}\), and \(V^2\) is the determinant of the Gram matrix \(G\) of the three vectors, so that
\begin{equation}
\label{eq:gram}
\begin{aligned}
\rho\,\sin^2\gamma = D &= 1-\cos^2\alpha-\cos^2\beta-\cos^2\gamma+2\cos\alpha\cos\beta\cos\gamma,\\
\det G &= a^2b^2c^2D .
\end{aligned}
\end{equation}
No three vectors in space have angles with \(D<0\), and \(D=0\) is a flat cell.
Two variants of the angle line show both cases.
For angles of \(\wkFlatAlpha\), \(\wkFlatBeta\) and \(\wkFlatGamma\) degrees the exact \(\rho\) is zero, since \(\mathbf{c}\) then lies in the plane of \(\mathbf{a}\) and \(\mathbf{b}\), while binary64 gives \(\hat\rho=\num{\wkFlatRadicand}\).
readcon-core accepts that frame with \(c_z=0\), because \(\hat\rho\) lies inside the window of \(\num{\wkWindow}\) that Section~\ref{sec:format} allows for the roundoff of a zero radicand, whereas ASE stops on its own assertion that \(\hat\rho\ge0\).
With \(\wkNoneAlpha\), \(\wkNoneAlpha\) and \(\wkNoneGamma\) degrees, \(D=\wkNoneGram\) and \(\rho=\wkNoneRadicand\).
readcon-core rejects that frame with an error that names line~\trCellLine, and ASE fails the same assertion without naming a line.
ASE also refuses Listing~\ref{lst:frame} itself, because its eon reader takes the blank line~\wkLineBlank{} for the first line of a second frame and stops when line~\wkLineVelocities{} does not parse as three cell lengths.

Two free lines follow, then the counts: one atom type, nine atoms of that type and the mass of the type.
Each type then has a block with its symbol, a label, and one row per atom of \(x\), \(y\), \(z\), the mask and the identifier.

For a frame of major \(M\), with \(M=1\) when the header is not JSON, the mask is the integer
\begin{equation}
\label{eq:mask}
m =
\begin{cases}
b_x + 2 b_y + 4 b_z, & M\ge 2,\\
b_x = b_y = b_z, & M = 1,
\end{cases}
\qquad b_\alpha\in\{0,1\},
\end{equation}
with \(b_\alpha=1\) when component \(\alpha\) is fixed.
In Listing~\ref{lst:frame} the bottom rows are fixed in every component, the top layer is free, and the adatom is held in \(z\) alone.
A reader that applies the version-1 rule of Table~\ref{tab:clauses} to this frame rejects the mask of the adatom as an illegal flag.
Conversely, a reader that applies the CON 3.1 rule to a version-1 file frees \(y\) and \(z\) of every atom held there.
Section~\ref{sec:prefactor} shows what is lost with the hold of the adatom: the band crosses a different saddle, with a larger prefactor.

The identifier is the index of the atom in the numbering of the writer, from \wkIdFirst{} on the first row to \wkIdLast{} on the last, and between \wkIdLow{} and \wkIdHigh{} overall.
Grouping the atoms by type has permuted that numbering, and sorting by identifier restores it.
A reader returns the identifiers exactly and in file order, up to \(2^{64}-1\), and a row without an identifier takes its zero-based position in the frame.
One of the cross-library round trips of Section~\ref{sec:cases} returns no identifiers at all.

The blank line~\wkLineBlank{} opens the velocity section declared in the header.
The section repeats the shape of the coordinate block, with one row of \(v_x\), \(v_y\), \(v_z\), mask and identifier per atom.
The held atoms have zero velocity and the adatom has \(v_z=0\), so \wkMovingAtoms{} atoms move.
The velocities are in the unit named in the header, the natural unit of eOn,
\begin{equation}
\label{eq:tau}
\tau=\left(\frac{m_{\mathrm{u}}\,\text{\AA}^{2}}{\mathrm{eV}}\right)^{1/2}
=\left(\frac{1.6605\times10^{-27}\,\mathrm{kg}\cdot 10^{-20}\,\mathrm{m}^{2}}{1.6022\times10^{-19}\,\mathrm{J}}\right)^{1/2}
=\wkTimeFs\,\mathrm{fs},
\end{equation}
with the CODATA 2018 values of the atomic mass constant \(m_{\mathrm{u}}\) and the electronvolt \cite{tiesingaCodataRecommendedValues2021}.
In that unit the frame has a kinetic energy \(\tfrac{1}{2}\sum_i m_i\lvert\mathbf{v}_i\rvert^2\) of \(\wkKinetic\,\mathrm{eV}\).
A reader that takes the same numbers as \(\text{\AA}/\mathrm{fs}\) returns \(\wkKineticMisread\,\mathrm{eV}\), which is larger by \((\tau/\mathrm{fs})^2=\velFactorSq\).

The coordinates are printed in the shortest form that reads back as the same binary64 value \cite{steeleHowPrintFloatingpoint1990,adamsRyFastFloattostring2018}, here with \wkDigitsMin{} to \wkDigitsMax{} significant digits, and the reader rounds each decimal to the nearest binary64 value \cite{clingerHowReadFloating1990,lemireNumberParsingGigabytes2021}.
A writer that prints six decimals instead puts \(x=\wkFirstXRounded\) in line~\wkLineFirstRow, a shift of \(\num{\wkShiftFirst}\,\text{\AA}\), and moves the \wkCoordinates{} coordinates by up to \(\num{\wkShiftMax}\,\text{\AA}\).
When the climbing-image band of Section~\ref{sec:cases} is resumed from six decimals, it converges in the same number of steps, but its barrier moves by \(\num{\rfDeSixNum}\,\mathrm{eV}\).
The frame ends after line~\wkLineLastVelocity, and the next line, if there is one, opens the next frame.

\section{The grammar of CON 3.1}\label{sec:format} The normative specification, with \clauseTotal{} numbered clauses, is Section~\ref*{sec:spec-normative} of the supplementary material.
Here we state the rules used in Section~\ref{sec:worked}, and Table~\ref{tab:clauses} lists the clauses behind them.
A CON file is one or more frames with no marker between them, followed only by lines of white space.
With \(T\) atom types of \(N_k\) atoms each, a frame \(\mathcal{F}\) is
\begin{equation}
\label{eq:frame}
\begin{aligned}
\mathcal{F}&\to \lambda_1\ \ \lambda_2\ \ (a\ b\ c)\ \ (\alpha\ \beta\ \gamma)\ \ \lambda_5\ \ \lambda_6\ \ T\ \ (N_1\cdots N_T)\\
&\qquad (M_1\cdots M_T)\ \ \mathcal{B}_1\cdots\mathcal{B}_T\ \ \mathcal{S}^{*},\\
\mathcal{B}_k&\to s_k\ \ (\text{\texttt{Coordinates of Component}}\ k)\ \ \bigl(x\ y\ z\ m\ [\iota]\bigr)^{N_k},\\
\mathcal{S}&\to \varnothing\ \ \mathcal{V}_1\cdots\mathcal{V}_T,\\
\mathcal{V}_k&\to s_k\ \ (S\ \text{\texttt{of Component}}\ k)\ \ \bigl(v_1\cdots v_w\ m\ \iota\bigr)^{N_k},
\end{aligned}
\end{equation}
where each symbol or parenthesized group is one line, a superscript repeats a line, \(\lambda_1\), \(\lambda_5\) and \(\lambda_6\) are free lines, \(\lambda_2\) is the header, \(M_k\) and \(s_k\) are the mass and symbol of type \(k\), \(\iota\) is the identifier, \(\varnothing\) is a blank line and \(S\) is the name of a section of width \(w\).
A type count of zero gives a frame without atoms.
The release also ships this shape as an informative parsing expression grammar (PEG) \cite{fordParsingExpressionGrammars2004}, and where the PEG admits a token that a clause rejects, the clause decides.

The cell rule rests on Eq.~\eqref{eq:gram}.
readcon-core evaluates Eq.~\eqref{eq:cell} in binary64 and accepts the angles when the computed radicand satisfies \(\hat\rho>-\num{\wkWindow}\), setting \(c_z=0\) when such a \(\hat\rho\) is negative.
Otherwise it rejects the frame with a validation error, an error class that the specification leaves open.
Since the window is fixed, a cell whose exact radicand lies between \(-\num{\wkWindow}\) and zero is accepted as flat, and every set of angles that misses a real cell by more is rejected.

Table~\ref{tab:clauses} also gives the masks that each version admits and the range of the identifier.
The readcon-core writer refuses a frame that repeats an identifier, and no clause ties the identifiers of one frame to those of another.

Each number is a finite decimal that the reader rounds to the nearest binary64 value, with ties to even \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019,clingerHowReadFloating1990,lemireNumberParsingGigabytes2021}.
By default the writer prints the shortest decimal that rounds back to the same value \cite{steeleHowPrintFloatingpoint1990,loitschPrintingFloatingpointNumbers2010,andryscoPrintingFloatingpointNumbers2016,adamsRyFastFloattostring2018}, so a frame that is written and read back has every coordinate unchanged; an option prints six fixed decimals instead.
A gzip or zstd envelope may wrap the same text \cite{deutschGzipFileFormat1996,colletZstandardCompressionApplicationzstd2021}, and the reader recognizes it by its content.
readcon-core decodes zstd when built with that feature and otherwise refuses the file with an error that names zstd.

The major version is \texttt{con\_spec\_version}, and the minor version is \texttt{con\_spec\_minor}, which is zero when absent.
For a frame whose header is a JSON object, let \(\mu\) be its minor, \(U\) the set of keys of its \texttt{units} object, and \(V\) true when the frame has a velocity section.
The reader accepts that header only when
\begin{equation}
\label{eq:version}
\begin{aligned}
&M\in\{2,3\}\ \wedge\ \mu\in\mathbb{N}\\
&\wedge\ \bigl(M=3\Rightarrow\{\mathrm{length},\mathrm{energy}\}\subseteq U\bigr)\\
&\wedge\ \bigl(M=3\wedge\mu\ge1\wedge V\Rightarrow \mathrm{time}\in U\bigr).
\end{aligned}
\end{equation}
For \(M=3\) it also rejects a unit whose dimension does not match its quantity.
A reader accepts a later minor of a known major, keeps an unknown key on rewrite with its digits as read, and rejects any other major as an unsupported version.
H5MD stores its version as the same pair of major and minor numbers, with the same meaning for a change of the minor \cite{buylH5mdStructuredEfficient2014}.

\section{Reference implementation}\label{sec:implementation} readcon-core implements the grammar once, in Rust (Figure~\ref{fig:architecture}).
C++, Julia \cite{bezansonJuliaFreshApproach2017} and Fortran 2008 call its C interface, and Python calls the Rust core through PyO3 and receives NumPy arrays \cite{harrisArrayProgrammingNumpy2020}.
eOn links readcon-core through the C++ wrapper, and its public release \eOneEonVersion{} embeds readcon-core \eOneEonReadcon, which writes CON 3.0 \cite{rohitgoswamiTheochemuieonV3602026}.
chemfiles is built the same way, with one C++ core behind a C interface that its other languages call \cite{frauxChemfileschemfilesVersion01042023}.

\begin{figure*}[tbp] \centering \includegraphics[width=\textwidth]{figures/generated/architecture.pdf} \caption{\textbf{One Rust core serves every language.}
C, C++ (including eOn), Julia and Fortran call the core through the C interface, and Python calls it through PyO3.
An arrow runs from the caller to the code it calls.}
\label{fig:architecture} \end{figure*}

Algorithm~\ref{alg:parser} is the path reader of the release.
A plain file of fewer than \(B_{\mathrm{map}}=\wkMmapBytes\) bytes is read whole into memory, a larger one is memory-mapped, and a gzip or zstd file is decompressed into memory whatever its size.
One thread parses frame after frame.
At the default thread count, the global thread pool parses a text of at least \(B_{\mathrm{par}}=\wkParallelBytes\) bytes, and an explicit count above one parses in a pool of that size.
The parallel path finds the frame boundaries in one thread, since the start of each frame depends on the counts before it, and then parses the frames independently and returns them in file order.
When the columnar reader fills frames of equal length in parallel, it checks every frame against the header and the component layout of frame~0.
A worker that panics leaves no partly filled frame in the result.
Table~\ref*{tab:anchors} of the supplementary material gives the source lines of each step.

One frame of \(N\) atoms costs \(\Theta(N)\) time and memory.
For a text of \(B\) bytes, after inflation for a gzip or zstd file, the read costs one serial \(\Theta(B)\) boundary walk and a \(\Theta(B)\) parse that \(P\) threads share, and the frames it returns occupy \(\Theta(B)\) memory.
A compressed file of \(C\) bytes is first inflated by one serial decoder in \(\Theta(C+B)\) time.
Section~\ref{sec:host} gives the peak resident set of each reader.

Every writer that takes a path writes its frames to a temporary file in the directory of the destination.
Once the last frame is accepted, it flushes and syncs that file and renames it over the destination.
A frame that fails deletes the temporary file, and the destination keeps its earlier bytes.
The uncompressed writers of the C interface write a device or a named pipe in place, and a writer to a string or to a stream that the caller opened writes no temporary file.
Each language binding has a test that fails a write midway and compares the destination with its earlier bytes.
Listing~\ref{lst:py} reads a band from Python and writes it back to the same path, after which the file contains either its earlier frames or the frames written.

\begin{lstlisting}[language=Python,caption={\textbf{A checkpoint round trip in Python.} The default printer keeps every binary64 value; six decimals are a separate argument.},label={lst:py}]
import readcon
frames = readcon.read_con("band.con")
readcon.write_con("band.con", frames)
\end{lstlisting}

\subsection{Python bindings and thread safety}\label{sec:python-threads}
The PyO3 module declares that it does not need the global interpreter lock (\texttt{gil\_used = false}).
Continuous integration runs the tests on free-threaded Python \texttt{3.13t} and \texttt{3.14t} as well as on the standard builds.
Parsing, formatting, file writes and correspondence checks detach the Python thread state with \texttt{py.detach}, so other Python threads run while they do.
Each write path first copies or converts whatever input Python can reach, while still attached, and only then formats, compresses and writes while detached.
On a frame that Python has not indexed, \texttt{coords\_array()} copies the coordinates from the parsed buffer into a new NumPy array without building a Python object for each atom.
Once the atom list of a frame exists, \texttt{coords\_array()} reads that list, so edits made in place remain visible.

\texttt{ConFrameList} keeps its parsed frames behind a read-write lock of its own.
When every frame is still in the list, the writers and \texttt{touch\_checksum()} hold one read lock across the detached call instead of moving frames out, so other threads see the full list and a panic leaves the frames intact.
When indexing has moved a frame out into a Python object, the writers go through the list frame by frame.
A thread that waits for the lock detaches before it blocks, so a detached holder can attach again without deadlock.
\texttt{columns()} takes the write lock, so detached readers finish before Python receives the shared coordinate array.

When Python can reach the coordinates of a frame, through the shared array of \texttt{columns()} or the \texttt{xyz} array of the frame, the attached thread copies them into a private buffer before the detached work starts, and the other fields are borrowed from the frames.
Each aligned double is copied with one relaxed \texttt{AtomicU64} load \cite{bosRustAtomicsLocks2023}, so no single value is torn.
The loads are not atomic across elements, and a thread that writes during the copy can leave the buffer holding elements from different instants.
Frames whose coordinates Python cannot reach are written without the copy.
When a shared list is written again and no frame has changed, the writer reuses the buffer of the previous write.

\texttt{write\_columns}, \texttt{write\_extxyz} and \texttt{write\_conbin\_columns} treat NumPy arrays the same way, copying them in runs of about \(4\) MiB while attached and formatting or writing each run while detached.
No Rust slice is ever formed over numeric memory that Python owns and can change.


\section{Zero-copy tensor exchange}\label{sec:dlpack} A caller that already holds a frame should be able to read its coordinates as a tensor without a copy.
readcon-core exposes such tensors through DLPack \cite{dlpackDLPack2026}.
On the Rust builder, the methods for positions, velocities, forces, per-atom energies and masses return a borrowed float64 tensor, and the method for atom identifiers returns a borrowed uint64 tensor.
Each borrowed tensor lives as long as the builder, and the default build places it on the CPU.
A C caller that needs the tensor after the builder is gone takes the versioned managed tensor, and that export copies the storage.
Python materializes a contiguous NumPy array, which implements the DLPack protocol, so PyTorch and JAX take the array without a second copy.
CuPy accepts only device memory and needs one copy from the host.
The measured exchange is a NumPy DLPack view against an explicit copy of the same positions, for \dlpackAtoms{} copper atoms.
The record holds six repeats of each arm.
The view takes a median of \dlpackViewUs{} microseconds and the copy a median of \dlpackCopyUs{} microseconds, so the view costs \dlpackRatio{} times the copy.
A 95 percent bootstrap interval for that ratio, drawn from those six samples, is \dlpackRatioLo{} to \dlpackRatioHi{}, and the interval excludes 1.
The type 7 interquartile ranges are \dlpackViewIqr{} microseconds and \dlpackCopyIqr{} microseconds.
Figure~\ref{fig:dlpack} shows the six repeats, and the timing record of both arms is part of the records of this paper (Data availability).

\section{Conformance}\label{sec:conformance} A specification settles a dispute between readers only when each reader can be tested against it.
The conformance corpus shipped with readcon-core~\readconversion{} contains \(\corpusConfValid\) legal and \(\corpusConfInvalid\) illegal files (Table~\ref{tab:corpus} of the supplementary material), and its manifest names the error class of each illegal file.
Read through the Python module of the release, all \(\corpusConfAgree\) files return the verdict and error class of their manifest entries, and the release checks the same files from Rust, Python, C, Fortran and Julia.

That corpus has few files for the header, the sections and the units, so we wrote a second corpus of \(\cthreeoneFiles\) CON 3.1 files, \(\cthreeoneAccepted\) legal and \(\cthreeoneRejected\) illegal.
For each file, its manifest names the clauses that decide it and the outcome: the frame count and periodic flags of a legal file, or the error class and line of an illegal one.
For \(\cthreeoneExplicit\) entries the outcome follows from the text of a clause, and the others record a reading where the text leaves the case open (Section~\ref*{sec:supp-corpus31}).
All \(\cthreeoneMatch\) files return the outcome of their entry at one, two and eight threads and at the default.
Both corpora also go through every read path of the Python module and the C library, in the default and the parallel build at each of those thread counts, and all \(\cpathsReads\) reads return the outcome that the manifests name (Table~\ref*{tab:corpus-paths}).

We also wrote an independent reader in \(\corpusIndepLines\) lines of Python that import nothing from readcon.
It follows the clauses of the specification, and where a clause requires a rejection without naming its class, or no clause decides a case, it follows the reading of the corpus manifest.
On all \(\corpusIndepAgree\) of the \(\corpusFiles\) files of both corpora, the frame list and the frame iterator of readcon and the independent reader each return the manifest outcome.
On the \(\corpusBoth\) files that both readers accept, all \(\corpusFieldIdentical\) carry the same bits in every coordinate, velocity and cell entry and equal masks, identifiers, units and periodic flags (Table~\ref*{tab:corpus-crosscheck}).
The two readers also read \(\mutantCases\) mutants of the \(\mutantFiles\) corpus files under \(\mutantMaxBytes\) bytes, \(\mutantPerSeed\) from each of \(\mutantSeeds\) seeds.
Each mutant inserts, deletes or replaces characters and tokens at one to three random places.
The readers agree on \(\mutantSame\) of them, with the same frame count or error class.
The other \(\mutantDiffer\) fall in \(\mutantGroups\) cases that no clause decides: a count line that breaks two clauses at once, a number in the header beyond the binary64 range, and a carriage return as the last byte of the input.
A variant of the independent reader that follows readcon-core on those three cases returns the readcon-core verdict on all of them.

Of the \(\clauseTotal\) clauses of the specification, \(\clauseCovered\) are named by a corpus file, a probe or a test of the library, and the other \(\clauseUncovered\) state no duty of a reader, such as the rules for revising the specification.

A format name should mean the same language to every reader that claims it, and versions of one reader are the first test.
The published wheels of readcon-core 0.17.0, 0.17.1, 0.17.2 and \rcDriftFourth{} do not return the same outcome on every probe file.
On files of two frames whose first line is empty, the oldest refuses the file and the later three read two frames, and on a blank symbol line the newest two refuse a file that the earlier two read (Section~\ref*{sec:supp-versions}).
Each of those changes decided a case that the text of its release left open, and Table~\ref{tab:versions} lists the clauses involved.

Extended XYZ is the text format to compare with CON on this test, because it has a published grammar, the specification of the libAtoms extxyz package \cite{kermodeLibatomsExtxyzV0462026}, and parsers in C, C++ and Python.
We gave seven three-atom files (Table~\ref{tab:drift} of the supplementary material) to \(\driftAllPaths\) reader paths from \(\driftAllLibraries\) libraries.
On the reference frame the \(\driftXyzPaths\) extended XYZ paths, from \(\driftXyzLibraries\) libraries, return \(\driftXyzOutcomes\) different outcomes.
That grammar admits a \texttt{d} or \texttt{D} exponent and reads \texttt{T}, \texttt{true}, \texttt{True} and \texttt{TRUE} as true, and the paths split on both files.
It leaves open whether a comment line that is not key-value pairs makes a file plain XYZ or an error, and on such a file the C parser of libAtoms departs from the default periodicity while its Python parser fails.

\section{Resumed saddle searches}\label{sec:cases} A resumed search needs every field that its file carries, so we first asked which routes return them all.
We wrote the survey frame of Listing~\ref{lst:frame} with one library and read it back with the same library or another, \(\surveyRoutes\) routes in all, \(\surveySameRows\) within one library and \(\surveyCrossRows\) across two (Table~\ref{tab:survey} of the supplementary material).
The libraries are ASE \cite{larsenAtomicSimulationEnvironmenta2017}, chemfiles \cite{frauxChemfileschemfilesVersion01042023}, MDAnalysis \cite{gowersMdanalysisPythonPackage2016,gowersMdanalysismdanalysisRelease21002025}, h5py \cite{collettePythonHdf52013}, OVITO \cite{stukowskiVisualizationAnalysisAtomistic2010} and Open Babel \cite{oboyleOpenBabelOpen2011}, at the versions of Section~\ref*{sec:supp-versions}, and each stores each field in the way its documentation gives.
We grade a returned field as fixed by the format when the specification of the format defines its place in the file, and as a convention when only the documented layout of one library defines that place.

Only the CON 3.1 route returns every field from places that its own specification defines.
The ASE trajectory, with the identifiers stored as ASE tags, and H5MD written and read with h5py also return every field bit for bit.
The trajectory keeps the mask, the identifiers, the unit and the periodicity in the layout of ASE, and H5MD keeps the mask in a dataset outside the H5MD specification, which only our own reader knows to read.
Extended XYZ returns the mask and the identifiers through the column names of ASE, which chemfiles and OVITO also read.
ASE writes that file with eight decimals, a shift of \(\num{\surveyAseXyzShiftNum}\,\text{\AA}\); chemfiles moves the coordinates by \(\num{\surveyChemXyzShiftNum}\,\text{\AA}\), rounds the cell lengths to six significant digits and drops the velocities.
MDAnalysis 2.10.0 returns single precision, which changes a coordinate by up to \(\num{\surveyMdaShiftNum}\,\text{\AA}\), and Open Babel keeps the identifiers only inside the site labels of a Crystallographic Information File (CIF).
MDAnalysis 2.11.0 still writes the H5MD positions, velocities and forces in single precision, as \texttt{float32} \cite{gowersMdanalysismdanalysisRelease21102026,gowersMdanalysisH5mdPy21102026}.
Identifiers come back on \(\surveyCrossIds\) of the \(\surveyCrossRoutes\) cross-library round trips, all through the \texttt{id} column of ASE.

\subsection{A climbing-image band through every route} The restart study uses a larger slab: Pt(100) under the effective-medium theory (EMT) potential of ASE \cite{jacobsenSemiempiricalEffectiveMedium1996}, three layers of \(3\times3\) atoms with the bottom layer held in every component, and one adatom held in \(z\) at the height of Table~\ref{tab:params} (Figure~\ref{fig:structures}, right).
The adatom hops between neighboring fourfold hollows along \(x\).
With the slab fixed, the EMT force on the adatom at that height exceeds the band tolerance.
That height is not a stationary point of the free adsorbate, so a file that drops the hold resumes a different relaxation.
A climbing-image band of five movable images with the improved tangent \cite{henkelmanClimbingImageNudged2000,henkelmanImprovedTangentEstimate2000} converges under fixed-step steepest descent on the projected force.
That optimizer keeps no step history, so any difference after the restart comes from the file.
The spring and the tangent are the defaults of ASE, the band tolerance is the default force tolerance of the ASE optimizer divided by the five movable images, and each endpoint is minimized to that tolerance divided by five again \cite{larsenAtomicSimulationEnvironmenta2017}.
A force equal to the band tolerance moves an atom by \(2\times 10^{-4}\,\text{\AA}\) under that step.
Uninterrupted, the band converges in \(\rfStepsUnint\) steps and \(\rfCallsUnint\) force calls, with barrier \(\rfBarrierUnint\,\mathrm{eV}\) and \(\rfModesUnint\) free modes on the middle image.
We interrupt it after \(K\) steps, write it, read it back and resume it to \(f_{\mathrm{band}}\), once per route of Table~\ref{tab:restartfmt}.

\subsection{The mask and the prefactor}\label{sec:prefactor} A barrier is one number, but the harmonic prefactor needs the free modes at the saddle.
In harmonic transition state theory the rate is \(k=\nu\exp(-\Delta E^\ddagger/k_{\mathrm{B}}T)\) with the Vineyard prefactor \cite{vineyardFrequencyFactorsIsotope1957}
\begin{equation}
\label{eq:vineyard}
\nu=\frac{\prod_{i=1}^{n}\nu_i^{\mathrm{min}}}{\prod_{i=1}^{n-1}\nu_i^{\ddagger}},
\end{equation}
where the products run over the \(n\) free modes of the minimum and the \(n-1\) real modes of the saddle.
A mask that frees one more component adds a mode to each product, and it can also move the saddle itself.
We wrote the endpoints of the same slab through each route and read them back before relaxing them.
We then converged a climbing-image band with the fast inertial relaxation engine (FIRE) \cite{bitzekStructuralRelaxationMade2006} and took the Hessian of the highest image.
With the height held, the barrier is \(\eFiveBarrierHeld\,\mathrm{eV}\) on a path of \(\eFivePathHeld\,\text{\AA}\).
The highest image has \(\eFiveModesHeld\) free modes, one imaginary mode of \(\eFiveImagHeld\,\mathrm{meV}\) with \(\eFiveWeightHeld\) of its weight on the lateral motion of the adatom, and a prefactor of \(\num{\eFivePrefactorHeldNum}\,\mathrm{Hz}\).
CON 3.1, the ASE trajectory, FixScaled POSCAR and h5py H5MD all return that prefactor (Table~\ref{tab:prefactor-routes}).
With the height free, which is the problem a reader solves when the file has lost the hold, the band crosses a saddle at \(\eFiveBarrierFree\,\mathrm{eV}\) with \(\eFiveModesFree\) free modes and a prefactor of \(\num{\eFivePrefactorFreeNum}\,\mathrm{Hz}\), \sigfig{2}{\eFivePrefactorRatioFree} times the held value.

\subsection{readcon-db campaign store}\label{sec:readcon-db}

The fair store comparison ingests the same 40 frames of 8 copper atoms into readcon-db and into the ASE database on one thread, twelve samples each, each insert one transaction and one commit, and each sample the mean of a 2~s span.
readcon-db takes a median of \num{\rdbIngestMedian}~s and the ASE database takes \num{\rdbAseIngestMedian}~s.
Type, positions, the cell lengths, angles and matrix on a triclinic cell, periodic boundary conditions, masses, fixed flags, velocities, the frame index and the unset energy (zero, with \texttt{energy\_set} false) are bit-exact in both stores, while atom ids, units and the \texttt{velocities\_set} and \texttt{pbc\_set} flags are kept only by readcon-db.

CON stores one mass per type.
On a 500-frame corpus readcon-db reads every frame in a mean of \num{\rdbCorpusReadMs}~ms.

readcon-db also keeps a derived cache of the same CON text with each coordinate column byte-shuffled and compressed with zstd.
On one thread the warm full read of the shuffled cache on the lattice trajectory divided by the raw read is \num{\rdbShuffleFirst} in the first campaign and \num{\rdbShuffleSecond} in the second, and the paired interval of the second runs from \num{\rdbShuffleSecondLo} to \num{\rdbShuffleSecondHi}, so the shuffled read is the faster of the two.
A third campaign compares the raw warm full read of the measured code with an earlier commit on one thread, in \rdbRawPairs{} pairs (\rdbRawPairedCIMethod; \rdbRawPairOrder).
Each pair divides the time of the measured code by that of the earlier commit; the paired median is \num{\rdbRawPairedMedian}, and its interval runs from \num{\rdbRawPairedLo} to \num{\rdbRawPairedHi}, so it includes 1.
A commit bisect of the raw read returns a paired interval at each stored step, and every stored bisect interval includes 1.
In a fourth campaign the lattice best case reads the shuffled cache in \num{\rdbLatticeBest} of the raw time, and the paired median of that read in a fifth is \num{\rdbLatticePaired}.
The shuffled cache uses the shuffle-zstd codec, which readcon-db applies only when asked: it stores the raw codec by default and for warm point access, and shuffle-zstd for cold bulk access.
The fourth campaign asks for shuffle-zstd on every read, so it measures what the codec trades.
On the membrane-protein trajectory the shuffled cache stores its frames in \num{\rdbMembraneFrameShare} of the raw bytes and the whole corpus in \num{\rdbMembraneCorpusShare} of them.
On one thread the median warm full read of the shuffled cache takes \num{\rdbMembraneRatio} of the median raw time, and the paired interval of the shuffled over the raw time runs from \num{\rdbMembraneColdLo} to \num{\rdbMembraneColdHi} for a cold full read and from \num{\rdbMembraneWarmLo} to \num{\rdbMembraneWarmHi} for a warm full read, each from \rdbMembranePairs{} pairs (\rdbMembraneCIMethod).

\FloatBarrier \section{Conclusions}\label{sec:conclusions}
A resumed saddle search repeats an interrupted run only when the checkpoint keeps the per-component constraints, the atom identifiers, the time unit of the velocities and the binary64 coordinates as written.
We have written the CON format down as the versioned CON 3.1 grammar and implemented it in readcon-core, one Rust core behind C, C++, Python, Julia and Fortran interfaces, with borrowed DLPack views of the coordinates.
Every Python and C read path of readcon-core returns the verdict of the corpus manifests on all \corpusFiles{} legal and illegal files of the two conformance corpora.
On the held Pt(100) slab, a band resumed from CON 3.1 repeats the uninterrupted band bit for bit, and a reader that drops the hold sends the band to a saddle whose prefactor is \sigfig{2}{\eFivePrefactorRatioFree} times larger.
Section~\ref{sec:host} gives the measured reads.
The specification and the conformance corpus of CON 3.1 belong to no single simulation engine, so any program can test its reader against the corpus, add a section under a later minor without breaking older readers, and resume a search from the files of another code.
