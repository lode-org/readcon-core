\begin{abstract}
Rare-event methods resume a saddle search from a stored geometry and
match atoms across frames by an identifier on each row.
CON is the geometry file those methods exchange, and it had no
specification.
Here, we introduce readcon-core, the reference reader and writer of
CON 3.1, a versioned grammar for that text.
Two conformance corpora, 165 files in all, define which files a
conforming reader accepts.
The writer prints the shortest decimal that reads back as the same
binary64 value, and the frames of one file are parsed in parallel.
One Rust core serves C, C++, Fortran, Julia and Python and exports
coordinate arrays through DLPack.
eOn and an ASE plugin read and write CON through that core.
The package readcon-chemfiles imports XYZ, PDB, GRO and LAMMPS dump text into a CON frame.
readcon-db stores the corpora, and readcon-ops compares frames, aligns
them and builds a Wulff construction.
On allyl vinyl ether the stored ids converge to 0.607~eV, and the renumbered product does not.
A Rust read of \num{100000} CON frames takes 0.179~s, against 10.8~s for
ASE's eon reader and 10.3~s for eOn's Python reader \texttt{loadcons}.
readcon-core is available under the MIT licence at
\url{https://github.com/lode-org/readcon-core}.
\end{abstract}

\textit{Nature of problem:} Rare-event methods resume a saddle search
from a stored geometry and match atoms across frames by an identifier
on each row.
The checkpoint also stores which Cartesian components are held and the
time unit of the velocities, because a lost hold changes the prefactor
and a misread unit scales the kinetic energy.
A restart that repeats the interrupted run reads the binary64
coordinates back as written.
CON is the geometry file those methods exchange, and it had no
specification.

\textit{Solution method:} CON 3.1 is a versioned grammar for that text,
and readcon-core is the reference reader and writer that formalizes and
improves it.
The second line of a frame is a JSON object that declares the major and
minor version, the units, the periodic flags and the per-atom sections
after the coordinates.
The fourth column of a coordinate row is a three-bit mask of fixed
components and the fifth an atom identifier.
From minor 1 a velocity section declares its time unit.
A reader of a known major accepts any later minor, keeps unknown keys
and skips a later section by its declared width.
The writer prints the shortest decimal that reads back as the same
binary64 value, and the reader rounds each decimal to the nearest
binary64 value.
Two corpora of legal and illegal files define which files a conforming
reader accepts.
readcon-core implements the grammar once in Rust, behind a C interface
for C++, Julia and Fortran and a PyO3 binding for Python.
On more than one thread it walks the frame boundaries serially by the
counts in each header, parses the frames in parallel and returns them in
file order.
A path writer opens the destination and truncates it, then writes the
frames into that file.

\section{Introduction}\label{sec:introduction} Rare-event methods turn a
potential energy surface into rates.
Transition state theory \cite{eyringActivatedComplexChemical1935,vineyardFrequencyFactorsIsotope1957,hanggiReactionrateTheoryFifty1990}
reduces the kinetics of an activated process to its saddle points and
the vibrations there.
The saddles are located by the nudged elastic band
\cite{jonssonNudgedElasticBand1998,henkelmanClimbingImageNudged2000,henkelmanImprovedTangentEstimate2000,asgeirssonNudgedElasticBand2021},
by minimum-mode followers, and by Gaussian-process acceleration of those searches \cite{henkelmanDimerMethodFinding1999,kastnerSuperlinearlyConvergingDimer2008,olsenComparisonMethodsFinding2004,goswamiGaussianProcessSaddle2025,goswamiAdaptivePruning2026,goswamiTutorialReviewBayesian2026}
and by string methods \cite{eStringMethodStudy2002,petersGrowingStringMethod2004}.
Adaptive kinetic Monte Carlo (AKMC) and accelerated dynamics chain them
into trajectories of seconds and longer \cite{henkelmanLongTimeScale2001,xuAdaptiveKineticMonte2008,voterExtendingTimeScale2002,perezLongtimeDynamicsThrough2016}.
A long-timescale run in eOn
\cite{chillEonSoftwareLong2014,rohitgoswamiTheochemuieonV3602026} spawns
thousands of saddle searches, often on volunteer or distributed
resources \cite{andersonBoincSystemPublicresource2004,pedersenDistributedImplementationAdaptive2010}.
It passes their geometries between Python drivers
\cite{larsenAtomicSimulationEnvironmenta2017,hermesSellaOpensourceAutomationfriendly2022},
C++ engines and Fortran electronic structure codes \cite{kresseEfficiencyAbinitioTotal1996}.
A search that stops on one machine resumes on another from a geometry
file, the checkpoint of the search.

The checkpoint has to return four fields that a trajectory reader can
ignore.
A surface search fixes the slab and can hold an adatom at a set height
while it crosses the surface, so mobility belongs to each Cartesian
component, and a lost hold changes the saddle that the search converges
to (Section~\ref{sec:prefactor}).
Mode following and AKMC bookkeeping match atoms across frames and events
by an identifier on each row.
A reader has to return that identifier as written rather than as the row
order.
Dynamical steps read velocities, and the natural time unit of eOn is
\((\mathrm{amu}\,\text{\AA}^2/\mathrm{eV})^{1/2}=\wkTimeFs\,\mathrm{fs}\),
so a reader that takes the same numbers as \(\text{\AA}/\mathrm{fs}\)
scales the kinetic energy by \(\velFactorSq\).
A restart that repeats the interrupted run to roundoff reads the
coordinates back as the same doubles \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019}.
For that, the writer prints the shortest decimal that reads back as the
same double
\cite{steeleHowPrintFloatingpoint1990,adamsRyFastFloattostring2018}, and
the reader rounds each decimal to the nearest double \cite{clingerHowReadFloating1990}.
Two readers given the same bytes must then return the same fields, and
that takes a versioned grammar rather than the convention of one reader.
On the Claisen rearrangement the stored ids select a converged 0.607~eV
chair, and a geometric renumbering of the same product does not converge
(Section~\ref{sec:claisen}).
The same reader carries a 4096-molecule water trajectory into d-SEAMS \cite{goswamiDseamsDeferredStructural2020}
(Section~\ref{sec:connectivity}) and resumes a saddle search from the
stored mask and coordinates (Section~\ref{sec:cases}).

Existing formats keep some of these fields and drop the ones a restart reads.
Extended XYZ publishes a grammar for key-value metadata on the comment line
\cite{kermodeLibatomsExtxyzV0462026},
and a mask or an identifier survives there only under a column name chosen by the Atomic Simulation Environment (ASE)
\cite{larsenAtomicSimulationEnvironmenta2017},
with neither a version nor a velocity unit.
H5MD stores an identifier, velocities with a unit and the box \cite{buylH5mdStructuredEfficient2014,folkOverviewHdf5Technology2011}
but defines no element for a per-component constraint, and MDAnalysis, pyh5md, ZnH5MD and zarrtraj write that kind of trajectory \cite{mdanalysisH5mdWriter211,debuylPyh5md,znh5md2025,woodsZarrtrajPythonPackage2026}.
XTC, TRR, DCD and TNG store molecular-dynamics output with neither a mask nor a velocity unit, and the GROMACS trajectory that replaces TNG is still an H5MD file with no per-component constraint (Section~\ref{sec:supp-formats}).
The ASE trajectory keeps the fields in the layout of its own Python code, while POSCAR stores a per-component hold as selective-dynamics flags and stores no atom identifier \cite{vaspwikiPoscar2026,kresseEfficiencyAbinitioTotal1996}.
chemfiles, MDAnalysis, the Open Visualization Tool (OVITO) and Open Babel read these formats \cite{frauxChemfileschemfilesVersion01042023,frauxChemfiles2023,gowersMdanalysisPythonPackage2016,michaudAgrawalMDAnalysisToolkit2011,stukowskiVisualizationAnalysisAtomistic2010,oboyleOpenBabelOpen2011}
and leave a CON file unread, at the versions of Section~\ref{sec:performance}, and ASE's eon reader opens CON only up to the velocity section of the frame in Section~\ref{sec:worked}.
A live stream of positions, velocities, forces and the box
\cite{thirumalaiswamyStreamingMolecularDynamics2026},
a ReaxFF analysis path
\cite{dinaniReaxkitModularPython2026},
and the tools that convert, check or index a trajectory after it has been written \cite{woodsSire2024,evansOptimade2024,petixLammpsio2025,tiemannMdverse2024}
likewise carry no per-component mask for the saddle search.

Most atomistic formats have no specification apart from the code that
reads them, so that code is the de facto definition of the format.
Particle physics fixed the files that pass between independent event
generators in published texts: the Les Houches event file
\cite{Alwall2007LHEF}, the second Les Houches Accord for supersymmetric
spectra \cite{Allanach2009SLHA2} and the HepMC3 library for generator
events \cite{Buckley2021HepMC3}.
Electronic structure has done the same for densities and wavefunctions
with the European Theoretical Spectroscopy Facility (ETSF) file format
\cite{Gonze2008ETSF} and TREXIO \cite{posenitskiyTrexioFileFormat2023},
and for pseudopotentials with the pseudopotential markup language (PSML) \cite{Garcia2018PSML}.
A computed barrier is reproducible from a file only when every reader
returns the same fields from it.
A versioned specification and a corpus of files with known verdicts turn
that condition into a test of any reader.

Here, we introduce readcon-core, the reference reader and writer of
CON 3.1, a versioned grammar for that checkpoint.
The grammar places a version, the units and the periodic flags on a JSON
header line, a three-bit mask and an atom identifier on each coordinate
row, and a time unit on any velocity section.
In Section~\ref{sec:fields} we state the fields a restart must keep, in Section~\ref{sec:implementation} we describe the library and the programs that store and compare frames, in Section~\ref{sec:validation} we test that grammar on the Claisen rearrangement, on a water trajectory and on a resumed saddle search, and in Section~\ref{sec:performance} we compare the read time with the readers those codes already use.
Of the readers in Section~\ref{sec:fidelity}, readcon is the one that returns the identifier in file order together with the per-axis mask, the masses, the cell on every frame and the velocities.

\section{The CON 3.1 format}
\subsection{Stored fields}\label{sec:fields}
CON 3.1 stores, on each frame, the coordinates, the full \(3\times 3\) cell including the axes the periodic flags leave open, a mass on each atom, a three-bit mask, an atom id and a velocity section with its own time unit, and that identifier is what a band, a dimer and an AKMC comparison need after a file reorders the rows.
The mask is an integer from 0 to 7, Eq.~\eqref{eq:mask}, and dropping the hold on the Pt(100) adatom selects another saddle, \(0.68\,\mathrm{eV}\) with a prefactor 37 times larger (Section~\ref{sec:prefactor}).
The mass enters the Lagrangian, Eq.~\eqref{eq:lagrangian}, and because the velocity section names its time unit, the same digits read as \(\text{\AA}/\mathrm{fs}\) scale the kinetic energy by \(\velFactorSq\), Eq.~\eqref{eq:tau}.
On one restarted band a round trip through this grammar returns the uninterrupted barrier, while a file that moves a coordinate or drops the mask returns a different barrier (Section~\ref{sec:cases}), and Section~\ref{sec:supp-fields} compares what each other format keeps of these fields.

\subsection{One frame}\label{sec:worked}
Listing~\ref{lst:frame}, Table~\ref{tab:frame} and Figure~\ref{fig:layout} are one frame of a platinum slab, two layers of four atoms with one adatom, and the rule that reads each line (Section~\ref{sec:supp-frame}).
The reader rebuilds the cell from the lengths and angles, Eqs.~\eqref{eq:cell} and~\eqref{eq:gram}, the mask is Eq.~\eqref{eq:mask}, and the velocity section uses the unit the header names, Eq.~\eqref{eq:tau}, so a reader that takes those numbers as \(\text{\AA}/\mathrm{fs}\) scales the kinetic energy by \(\velFactorSq\).
The coordinates are printed in the shortest decimal that reads back as the same double, and a version-1 header, anything other than one JSON object, is the text that earlier eOn releases write.

\subsection{Grammar}\label{sec:format}
Section~\ref{sec:spec-normative} states the normative specification in \clauseTotal{} numbered clauses, and Section~\ref{sec:supp-grammar} gives the production of one frame, the clauses this argument uses and the rule for a later minor.
Each number is a finite decimal that the reader rounds to the nearest double, ties to even.
The default writer prints the shortest decimal that rounds back to the same value, so writing a frame and reading it back returns every coordinate unchanged, and a setting prints six fixed decimals instead.
A gzip or zstd envelope wraps the same text, and a reader recognises it by content.
A reader accepts a later minor of a known major, keeps an unknown key on rewrite, and rejects any other major.
A later minor never makes a reader reject a file that an earlier minor requires it to accept.

\section{Program description}\label{sec:implementation}
We implement the grammar once, in Rust
(Figure~\ref{fig:architecture}).
C++, Julia \cite{bezansonJuliaFreshApproach2017} and Fortran 2008 call
its C interface, and Python calls the Rust core through PyO3 and
receives NumPy arrays \cite{harrisArrayProgrammingNumpy2020}.
eOn links readcon-core through the C++ wrapper, and its public release
\eOneEonVersion{} embeds readcon-core \eOneEonReadcon, which writes
CON~3.0 \cite{rohitgoswamiTheochemuieonV3602026}.
That layering follows chemfiles
\cite{frauxChemfileschemfilesVersion01042023}, one core with a binding
for each language, and we take it over unchanged.

\begin{figure*}[tbp] \centering
\includegraphics[width=\textwidth]{figures/generated/architecture.pdf}
\caption{\textbf{One Rust core serves every language.} C, C++ (including
eOn), Julia and Fortran call the core through the C interface, and
Python calls it through PyO3. An arrow runs from the caller to the code
it calls.}
\label{fig:architecture} \end{figure*}

We pair atoms by the identifier in the fifth column.
For each atom of the reference frame, the permutation is the index of that same identifier in the other frame.
Reordering into the reference order carries the positions, the velocities, the forces and the bond endpoints with the atom.
The consistency check names the first frame of a band or a trajectory that disagrees with the first frame.
The wrapped displacement of each matched pair uses the reference cell.
Python, C and C++ expose the four calls (Table~\ref{tab:correspondence}, Section~\ref{sec:supp-api}).
In strict mode, which is the default, the mass and the fixed mask must agree as well.

In the core, Algorithm~\ref{alg:parser} of Section~\ref{sec:supp-parser} is the path reader of the
release.
A plain file of fewer than \(B_{\mathrm{map}}=\wkMmapBytes\) bytes is
read whole into memory, a larger one stays mapped, and a gzip or
zstd file is decompressed into memory whatever its size.
The read stays on the calling thread until the caller asks for two or more workers, with no minimum file length for the pool: equal-length frames, including a whitespace tail, split into equal spans, and on any other file one thread walks the frame boundaries from the counts in each header before the pool parses the frames and returns them in file order.
Table~\ref*{tab:anchors} of the supplementary material gives the source lines of each step, Figure~\ref{fig:parser} is that read, and a coordinate row is three decimals, a mask and an optional identifier, with the short decimal and the Eisel--Lemire path in Section~\ref{sec:supp-cell}.


One frame of \(N\) atoms costs \(\Theta(N)\) time and memory.
For a text of \(B\) bytes, after inflation for a gzip or zstd file, the
read costs one serial \(\Theta(B)\) boundary walk and a \(\Theta(B)\)
parse that \(P\) threads share, and the frames it returns occupy
\(\Theta(B)\) memory.
A compressed file of \(C\) bytes is first inflated by one serial decoder
in \(\Theta(C+B)\) time.
The peak resident set of each reader on the Xeon is in
Section~\ref{sec:host}.

A path writer opens the destination and truncates it before writing the frames, so a failure during the write leaves a partial file, while a writer to a string or to a stream the caller opened writes into that stream.
Listing~\ref{lst:py} of Section~\ref{sec:supp-parser} reads a band from Python and writes it back to the same path, which the writer truncates when the write opens.

\subsection{Companion programs}\label{sec:ecosystem}
readcon-core parses CON and convel and returns the coordinates as the column \(R\) of Eq.~\eqref{eq:tangent} or as one frame object per image.
C, C++, Fortran, Julia and Python call that parser.
The Fortran binding is there because scientific codes still call Fortran \cite{kedwardStateFortran2022}.
A quantum-chemistry input parser is held to the same standard, that the text it reads is the calculation it runs \cite{goswamiWailordParsers2022}.
Algorithm~\ref{alg:parser} is the path reader.
The C entry \(\texttt{rkr\_read\_positions}\) and the Rust entry \(\texttt{read\_positions}\) both return that column, and the coordinates match.
The same read and write keep \texttt{atom\_id}.

readcon-db, under the MIT licence, from \url{https://github.com/lode-org/readcon-db}, stores the corpus in LMDB.
A frame key is 12 bytes, the trajectory id and the frame index, and the record is the CON text (Section~\ref{sec:supp-tools}).
The commands include \texttt{ingest}, \texttt{select}, \texttt{dedup-export}, \texttt{annotate-topology}, \texttt{find-by-topology}, \texttt{index-canonical}, \texttt{find-by-atom-order}, \texttt{shard}, \texttt{compact} and \texttt{h5md-velocities}.
\texttt{dedup-export} keeps one copy of a frame whose serialized text hashes to a frame already stored.
That hash is the xxHash3-128 of the CON text, an identity of bytes rather than of chemical graphs \cite{muraokaGraphIdentifiers2026}.
\texttt{index-canonical} reorders each frame into increasing \texttt{atom\_id}, under the strict check of symbol, mass and fixed mask, and stores the xxHash3-128 of that round-trip text.
\texttt{find-by-atom-order} returns each stored frame with that hash and the permutation back to the query.
A NEB image or an AKMC product whose rows were grouped by element is then the same geometry.
seams-core selects from the corpus by element or by formula (Section~\ref{sec:connectivity}).
In the AKMC catalog amsel, each process stores its barrier, its prefactor and its mode, and points at three frames: the reactant, the saddle and the product.
The saddle carries a displacements section with the same fixed-flag column and the same \texttt{atom\_id} column as the coordinates.

readcon-ops, under the BSD 3-clause licence, from \url{https://github.com/lode-org/readcon-ops}, is the compare layer of the stack.
readcon-ops takes a \texttt{ConFrame}: \texttt{identical} matches atoms of one element under the minimum image, \texttt{internal\_motion} removes a rigid motion, \texttt{rotational\_match} aligns by iterative rotations and assignments, and \texttt{wulff\_vertices} returns a Wulff construction.
On the Claisen endpoints the id-matched vinyl-ether bond is 1.360~\text{\AA} and the carbonyl is 1.210~\text{\AA} (Section~\ref{sec:fidelity}).
The three programs split the work as parse, store and compare (Table~\ref{tab:commands}, Section~\ref{sec:supp-commands}).

\subsection{Installation and usage}
Rust installs with \texttt{cargo add readcon-core@0.22.0}, Python with \texttt{pip install readcon==0.22.0}, and the chemfiles bridge with \texttt{pip install readcon-chemfiles==0.22.0}.
Julia, from a checkout of the repository, is \texttt{julia -{}-project=julia/ReadCon -e 'using Pkg; Pkg.instantiate()'}, and C and C++ use the shipped headers, with \texttt{find\_package(readcon-core)} or \texttt{cargo cinstall -{}-release -{}-prefix /usr/local}.
readcon-db is \texttt{cargo add readcon-db} or \texttt{pip install readcon-db}, and readcon-ops, which is not on PyPI, installs with \texttt{pip install .} from a checkout of \url{https://github.com/lode-org/readcon-ops}.


\section{Conformance}\label{sec:conformance} A specification settles a
dispute between readers only when each reader can be tested against it.
The conformance corpus of readcon-core~\readconversion{} contains
\(\corpusConfValid\) legal and \(\corpusConfInvalid\) illegal files
(Table~\ref{tab:corpus}), and its manifest names the error class of each
illegal file.
Read through the Python module of the release, all \(\corpusConfAgree\)
files return the verdict and error class of their manifest entries, and
we check the same files from Rust, Python, C, Fortran and
Julia.

\section{Validation}\label{sec:validation}
A lost field changes the calculation that reads the file, and Section~\ref{sec:supp-applications} gives the three studies in full.

\subsection{Claisen}\label{sec:claisen}
Allyl vinyl ether rearranges to pent-4-enal through a six-membered chair, and the improved NEB tangent at image \(i\) is built from the forward and backward differences
\begin{equation}
\label{eq:tangent}
\tau_i^{+}=R_{i+1}-R_i,\qquad \tau_i^{-}=R_i-R_{i-1},
\end{equation}
and the spring force lies along that tangent
\cite{jonssonNudgedElasticBand1998,henkelmanImprovedTangentEstimate2000},
\begin{equation}
\label{eq:spring}
F_i^{\parallel}=k\big(|R_{i+1}-R_i|-|R_i-R_{i-1}|\big)\,\hat\tau_i.
\end{equation}
A permutation of one image makes those differences connect different atoms, so the band needs the stored ids.
That pairing is the chemical map.
The band that follows the atom ids stored on the CON rows converges to 0.607~eV, while the minimum-Hausdorff renumbering of the same product does not meet the convergence criterion and reaches 3.988~eV at two separated fragments (Figure~\ref{fig:claisen-land}).
The same endpoints, stored oxygen-first with C5 shifted one cell along \(+x\), give an index-wise oxygen step of 15.8~\text{\AA} when the rows are paired by position (Section~\ref{sec:fidelity}), and the enhanced climbing-image band keeps the identifier order with readcon-core \cite{goswamiEnhancedClimbingImage2026}.

\subsection{What a second reader keeps}\label{sec:fidelity}
A band, an AKMC catalog and a dynamical step pair atoms rather than file slots: column 5 is the atom id, column 4 is the per-axis mask, the mass enters Eq.~\eqref{eq:lagrangian}, the cell is the minimum image, and a velocity is the momentum divided by that mass.
We read the same five files with readcon, with ASE's eon reader, with eOn's Python loader and with chemfiles, on one core of the Xeon in Section~\ref{sec:compute}, and we report the median of six reads after one warmup (Table~\ref{tab:fidelity-time}).
Readcon keeps the identifier sequence, the per-axis mask, the masses and the cell on every frame, and it keeps the velocities when the file stores them.
Each of those fields matches the input.
The eon reader in ASE builds the atom from the coordinates and from the mask column as one Boolean on every axis.
On the platinum slab, where the adatom is held in height only, one atom therefore leaves the written file with every axis held, and the same reader stops when the next block is a force or a velocity section.
The written cell stays inside the tolerance of six printed decimals.
Chemfiles stops because it has no reader for this format.
The eOn loader keeps the identifiers and sorts them on the Claisen file and on the slab, while a three-image band stays in file order.
Velocities come back as the numbers in the file, under the natural time unit even when an older header names femtoseconds.
On the Claisen product stored oxygen-first, with C5 shifted one cell along \(+x\), the index-wise displacement is 15.8~\text{\AA} at the oxygen slot, and because readcon keeps the identifier sequence the minimum-image step follows the nuclei.
After the loader sorts the identifiers, that norm is 18~\text{\AA} and it falls on C5.
The sorted file is a different path.
The eon writer numbers the atoms from zero, and the identifier check then fails because the product atom numbered zero is oxygen where the reactant atom is carbon.
The identifier-matched vinyl-ether bond on these endpoints is 1.360~\text{\AA} and the carbonyl is 1.210~\text{\AA}, a shortening of 0.150~\text{\AA}.

\subsection{Connectivity in d-SEAMS}\label{sec:connectivity}
A LAMMPS dump sorted by id already carries an atom id and a box, and H5MD carries an id and a velocity unit.
Neither is the checkpoint eOn writes: this grammar carries the per-component mask, the id and the time unit in one file that eOn, ASE and d-SEAMS read \cite{goswamiDseamsDeferredStructural2020}.
On 4096 molecules of mW water, neighbour pairs persist at 0.955 when the id is kept and at 0.001 when the file order is not that id (Figure~\ref{fig:water}).

\FloatBarrier \section{Conclusions}\label{sec:conclusions}
We find that the stored atom identifiers select a converged chair at 0.607~eV on the allyl vinyl ether rearrangement, while a geometric renumbering of the same product reaches 3.988~eV at two separated fragments and does not meet the force criterion.
An oxygen-first copy of those endpoints gives an index-wise step of 15.8~\text{\AA} at the oxygen, and once the identifiers are sorted that step is 18~\text{\AA} and falls on C5.
A Rust read of \num{100000} CON frames takes 0.179~s on one core, against 10.8~s for ASE's eon reader and 10.3~s for eOn's Python loader, and on 4096 molecules of mW water the neighbour pairs persist at 0.955 when the stored identifier is kept and at 0.001 when the file order replaces it.
The geometry file stores no optimiser history, so a search that keeps a Hessian or a set of previous steps takes a different path after a restart even when every coordinate matches.
ASE's own eon reader still stores the per-axis mask as one Boolean and drops the column-5 identifier, and the next step is to carry both through that reader so a band resumed in ASE keeps the hold and the atom order that the CON file already stores.
