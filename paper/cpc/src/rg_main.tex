\begin{abstract}
A saddle search resumes from a geometry file, so that file is the restart state.
The resume needs a per-axis mask, a persistent atom id, a declared velocity time unit, binary64 coordinates with the cell and the periodic flags, and a versioned grammar.
One masked Pt(100) frame loses at least one of those fields in every common format tested here.
An ASE POSCAR round trip drops the adatom's height constraint, and the resumed climbing-image band finishes \(70.2\,\mathrm{meV}\) below the uninterrupted barrier of \(0.644561366\,\mathrm{eV}\).
Five extended XYZ readers return four answers for one file.
CON 3.1 versions the text eOn writes, pairs it with a conformance corpus, and implements it once: a Rust core behind a C interface for C, C++, Python, Julia and Fortran.
Twenty-five language pairs resume the band at that barrier.
A warm read of \(10{,}000\) frames of 218 atoms takes \(12.6\,\mu\mathrm{s}\) per frame.
The reader scales across threads and across eight MPI ranks, and the companion store readcon-db keeps the CON text, indexes it, and ingests it from several ranks.
\end{abstract}

\textit{Nature of problem:}
Rare-event campaigns stop and resume from a stored geometry.
The formats in common use each drop part of the resume state: a per-axis mask, a persistent atom id, the velocity time unit, binary64 coordinates, or the periodic flags.
Readers of one format also disagree with each other, so the resumed search runs on a different surface.

\textit{Solution method:}
CON 3.1 is a versioned grammar.
A reader of a known major accepts a later minor, keeps unknown keys, and rejects an unknown major.
Every velocity block declares its time unit.
The default writer emits the shortest decimal that parses back to the same binary64 value.
A corpus of legal and illegal frames decides what a conforming reader accepts.
One Rust core sits behind one C interface, and eOn 3.6.0 reads and writes CON through it.
The companion store readcon-db keeps that text, indexes composition, energy and forces, recognises gzip and zstd wrappers of the same text, and ingests frames from several MPI ranks.

\textit{Additional comments including restrictions and unusual features:}
A frame stores geometry and its labels.
The short history of a quasi-Newton or FIRE step lies outside the frame.
The default memory map of readcon-db is 2 GiB.
\end{small}

\section{Introduction}
\label{sec:introduction}
Harmonic transition-state theory builds a rate from a barrier and from the curvatures at a minimum and at a first-order saddle \cite{eyringActivatedComplexChemical1935}.
The prefactor is a ratio of frequencies of the free modes \cite{vineyardFrequencyFactorsIsotope1957}.
The rate theories that followed keep that dependence on the barrier region \cite{hanggiReactionrateTheoryFifty1990}.
A mask read wrongly removes a mode, so the stored geometry has to carry the mask.
A coordinate that moves on restart is a different stationary point, so the stored geometry has to come back as the same binary64 values.

The searches that find those points all stop on a file.
The nudged elastic band stores a chain of images tied by springs \cite{jonssonNudgedElasticBand1998}.
Its climbing image pushes the highest image to the saddle, which is the number the campaign reports \cite{henkelmanClimbingImageNudged2000}.
The tangent that image uses is estimated from its neighbours, so a displaced neighbour changes the next step \cite{henkelmanImprovedTangentEstimate2000}.
Energy-weighted springs change the spacing and still resume from the same images \cite{asgeirssonNudgedElasticBand2021}.
An improved initial path is itself a file of geometries \cite{smidstrupImprovedInitialGuess2014}.
The string method stores the path as a curve of configurations \cite{eStringMethodStudy2002}, and the simplified string does the same \cite{eSimplifiedImprovedString2007}.
A growing string adds images from the endpoints, so an interrupted growth resumes from the images already placed \cite{petersGrowingStringMethod2004}.
The dimer stores two nearby geometries and rotates them onto the lowest mode \cite{henkelmanDimerMethodFinding1999}.
Later dimer variants change the rotation and still restart from those two geometries \cite{heydenEfficientMethodsFinding2005,kastnerSuperlinearlyConvergingDimer2008}.
Single-ended searches differ in how they climb, and they share the stored point as the object being compared \cite{olsenComparisonMethodsFinding2004}.
A catalogue of stationary points is a catalogue of geometries \cite{walesExploringEnergyLandscapes2018}.
Partial Hessian diagonalization accelerates the refinement of a saddle the file already holds \cite{hermesAcceleratedSaddlePoint2019}.
A geodesic step in internal coordinates speeds the optimiser and still writes the Cartesian frame \cite{hermesGeometryOptimizationSpeedup2021}.
An automation layer such as Sella stops and resumes that frame \cite{hermesSellaOpensourceAutomationfriendly2022}.
Aligning the climbing image with a Hessian eigenmode is a later step on the same stored band \cite{goswamiEnhancedClimbingImage2026}.
The chapter that collects these searches is a list of algorithms with one shared record, the geometry \cite{henkelmanMethodsFindingSaddle2005}.

When the event is too rare for a direct trajectory, the campaign still hands a configuration from one stage to the next.
Hyperdynamics adds a bias defined on the stored configuration \cite{voterHyperdynamicsAcceleratedMolecular1997}.
The bond-boost form of that bias is defined on the same point \cite{mironAcceleratedMolecularDynamics2003}.
The review of accelerated molecular dynamics is a review of methods that exchange a configuration \cite{voterExtendingTimeScale2002}.
Off-lattice kinetic Monte Carlo accepts an event and writes the new state for the next search \cite{henkelmanLongTimeScale2001}.
The event table is keyed by that configuration \cite{voterIntroductionKineticMonte2007}.
Adaptive kinetic Monte Carlo builds the table as it goes, and the campaign is the sequence of stored states \cite{xuAdaptiveKineticMonte2008}.
Absorbing Markov chains for slow dynamics resume from the last configuration \cite{novotnyMonteCarloAlgorithms1995}.
A parallel replica copies one state onto many ranks, so every replica has to start from the same geometry \cite{voterParallelReplicaMethod1998}.
Dephasing starts from that same stored state \cite{perezParallelReplicaDynamics2015}.
Parallel trajectory splicing passes states between segments \cite{perezLongtimeDynamicsThrough2016}.
Basin hopping records the minimum it just accepted \cite{walesGlobalOptimizationBasinhopping1997}.
Minima hopping escapes by a short trajectory and then relaxes, so it writes both velocities and a geometry \cite{goedeckerMinimaHoppingEfficient2004}.

eOn is the program that runs these searches and stops them on a file \cite{chillEonSoftwareLong2014}.
The concept record of that program is separate from any one release \cite{goswamiEon2026}.
Release 3.6.0 reads and writes the file through the reader in this paper \cite{rohitgoswamiTheochemuieonV3602026}.
A long exploration writes thousands of such files \cite{goswamiEfficientExplorationChemical2025}.
A distributed adaptive kinetic Monte Carlo run ships the files between ranks \cite{pedersenDistributedImplementationAdaptive2010}.
A public-resource client returns the same files across machines \cite{andersonBoincSystemPublicresource2005}.

A surrogate inside the search loop does not replace the file.
A Gaussian-process force model is trained on geometries \cite{goswamiEfficientImplementationGaussian2025}.
Pruning that model removes training points and still evaluates the geometry the search is standing on \cite{goswamiAdaptivePruningIncreased2026}.
A Gaussian-process band and a Gaussian-process minimum-mode search both write the geometry they refined \cite{koistinenNudgedElasticBand2019,koistinenMinimumModeSaddle2020}.
Accelerating the saddle search leaves the checkpoint in place \cite{petersonAccelerationSaddlepointSearches2016}.
A Bayesian search places its posterior on stationary points that are geometries \cite{goswamiTutorialReviewBayesian2026}.
A model container such as metatensor evaluates a geometry; it does not store the search \cite{bigiMetatensorMetatomicFoundational2026}.
A universal potential such as PET-MAD consumes a geometry and returns energy and forces \cite{mazitovPetmadLightweightUniversal2025}.
A descriptor library consumes the same geometry and cannot rebuild a mask from the descriptor \cite{himanenDscribeLibraryDescriptors2020}.
Symmetry search can renumber atoms, so an atom id is not recoverable from coordinates alone \cite{togoSpglibSoftwareLibrary2024}.
A materials-analysis library starts from a stored structure \cite{ongPythonMaterialsGenomics2013}.
A materials API returns that structure and does not return the optimiser state that produced it \cite{ongMaterialsApplicationProgramming2015}.

The file therefore has a job an exchange format does not.
A surface calculation holds the slab and lets an adatom move in the plane, so the mask is per atom and per axis \cite{jonssonSimulationSurfaceProcesses2011}.
A band and an event table refer to atoms by identity after a file has grouped them by element \cite{gundeIraShapeMatching2021,terrellDatabaseAtomisticReaction2012}.
Velocities enter a step only with a unit.
The natural unit of eOn is \((\mathrm{amu}\cdot\text{\AA}^{2}/\mathrm{eV})^{1/2}\).
On a \(10{,}001\)-atom slab the committed conversion is \(10.1805056712\,\mathrm{fs}\), and the kinetic energy scales by \(103.642696\) when the same numbers are read as \(\text{\AA}/\mathrm{fs}\) \cite{tiesingaCodataRecommendedValues2021}.
A unit library is how a program names that quantity; the file has to carry the name \cite{mckeeverUnitMeasurementLibraries2021}.
Velocity Verlet advances positions with those velocities \cite{swopeComputerSimulationMethod1982}.
A thermostat rescales the kinetic energy it is given \cite{bussiCanonicalSamplingThrough2007}.
The developers of MDAnalysis stated the documentation problem directly: simulation file formats ``are often only poorly documented and just adhere to certain community expectations that can be difficult to understand for outsiders'' \cite{gowersMdanalysisPythonPackage2016}.

Two readers given the same bytes have to return the same state, because the computation is the data \cite{pengReproducibleResearchComputational2011}.
A second group can rerun that computation only from the file and the program \cite{inceCaseOpenComputer2012}.
The file outlives the code that wrote it \cite{hinsenCaringYourData2012}.
A format defined only by one library version collapses when that library changes \cite{hinsenDealingSoftwareCollapse2019}.
The FAIR principles ask for a record another group can reuse \cite{wilkinsonFairGuidingPrinciples2016}.
The matching principles for research software ask for a versioned, citable program \cite{barkerIntroducingFairPrinciples2022,lamprechtTowardsFairPrinciples2020,smithSoftwareCitationPrinciples2016}.
Chemical Markup Language and MOSAIC wrote the data model down before the code \cite{murrayrustChemicalMarkupXml1999,hinsenMosaicDataModel2014}.
checkCIF turned the CIF rules into alerts a later reader can reproduce \cite{hallCrystallographicInformationFile1991,spekCheckcifValidationAlerts2020}.
CON 3.1 is that treatment of the text eOn already writes.

The contributions are the five requirements, the grammar and corpus that meet them, and one reader that every binding calls.
Section \ref{sec:requirements} measures the requirements on one frame.
Section \ref{sec:format} states the grammar.
Section \ref{sec:conformance} is the corpus and the extended XYZ disagreement.
Section \ref{sec:implementation} is the reader and the store.
Section \ref{sec:cases} resumes the same band through every route.
Section \ref{sec:performance} reports threads, peers, MPI and the store.

R1 is a mask for each Cartesian axis of each atom.
R2 is an integer stored on the row, so a later frame finds the same atom after the file groups rows by element.
R3 is a time unit written in the file.
R4 is coordinates, cell and periodic flags that read back as the values written.
R5 is a grammar with a major and a minor, a rule for what a later minor may add, and a corpus that decides disputes.

The short history of an optimiser is outside the five.
Limited-memory quasi-Newton updates a Hessian from a few previous steps \cite{nocedalUpdatingQuasinewtonMatrices1980}.
The optimisers used on minimum-energy paths keep an analogous history \cite{sheppardOptimizationMethodsFinding2008}.
FIRE carries velocities of the images between steps \cite{bitzekStructuralRelaxationMade2006}.
A resume can match the coordinates and still take a different next step.
Section \ref{sec:cases} measures that on one band, and Section \ref{sec:limitations} states the scope.

\subsection{One frame through each format}
The frame is a Pt(100) slab with one adatom: the bottom atoms held on every axis, the adatom held in \(z\), ids that are not the row order, and velocities in the natural unit.
Section \ref{sec:supp-failure} gives the coordinates, the ids and the grading rules.
Each row of Table \ref{tab:survey} writes that frame with one library and reads it with another.
The libraries are ASE 3.29.0 \cite{larsenAtomicSimulationEnvironmenta2017,bahnObjectorientedScriptingInterface2002}, chemfiles 0.10.4 \cite{frauxChemfileschemfilesVersion01042023}, MDAnalysis 2.10.0 \cite{gowersMdanalysismdanalysisRelease21002025,michaudagrawalMdanalysisToolkitAnalysis2011}, and h5py 3.7.0 where the route needs it \cite{colletteH5pyh5py3702022}.
The chemfiles concept record covers the project across versions \cite{frauxChemfiles2023}.
The 2016 MDAnalysis paper is the toolkit description; the 2.10.0 record is the version in the table.

The CON 3.1 row keeps every field.
Extended XYZ written and read by ASE returns the mask, the ids and the time unit because both sides share ASE's column names and ASE's internal unit.
The extended XYZ grammar does not define those names, so chemfiles drops the mask and MDAnalysis drops the mask and the ids.
The ASE writer prints a fixed number of decimals and the coordinates move by up to \(4.7\times10^{-9}\,\text{\AA}\).
chemfiles writing the same frame moves them by \(4.9\times10^{-6}\,\text{\AA}\) and returns every axis periodic.
MDAnalysis returns single-precision coordinates, a shift of \(2.2\times10^{-7}\,\text{\AA}\).
The ASE trajectory keeps the mask and the coordinates exactly and drops the id; its time unit is the library's unit, which the file does not name.
POSCAR selective dynamics is a per-axis mask in the VASP definition of the ionic restart \cite{kresseEfficientIterativeSchemes1996,kresseEfficiencyAbinitioTotal1996}.
The ASE writer turns the held slab into a different mask and writes the adatom free, so this route changes R1.
POSCAR has no atom id and no open axis.
H5MD written by MDAnalysis declares the velocity unit, writes no mask and no id, stores single-precision coordinates, and marks the open \(z\) axis periodic \cite{buylH5mdStructuredEfficient2014}.
H5MD sits on HDF5, whose container can hold extra arrays \cite{folkOverviewHdf5Technology2011}.
An extra array carries a mask only when every reader agrees on its name and type, which is the extended XYZ situation again.
Section \ref{sec:cases} attaches that array and shows which readers return it.
The ASE eon reader rejects a CON frame that contains a velocity block.
Given coordinates alone it freezes every masked atom on every axis, drops the ids, and returns no periodic axis.
The ASE eon writer cannot express a per-axis constraint, so that route produces no file.

Line 1 is free text.
Line 2 is one JSON object \cite{brayJavascriptObjectNotation2017}.
A bulk JSON parser reaches gigabytes per second on arrays of objects, so this single header line is not the cost measured in Section \ref{sec:perf-read} \cite{langdaleParsingGigabytesJson2019}.
Lines 3 and 4 are the cell lengths and the angles in degrees.
The type count, the per-type counts and the masses follow.
Each coordinate row is \(x\), \(y\), \(z\), the mask and the id.
Lengths and angles rebuild the box with \(a\) along \(x\) and \(b\) in the \(xy\) plane,
\begin{equation}
\mathbf{a}=a\,\hat{\mathbf{x}},\qquad
\mathbf{b}=b\cos\gamma\,\hat{\mathbf{x}}+b\sin\gamma\,\hat{\mathbf{y}},
\end{equation}
after which \(\mathbf{c}\) is fixed by \(\alpha\) and \(\beta\) so the cell is right-handed \cite{bekkerUnificationBoxShapes1997}.
When line 2 carries lattice vectors, those rows are the cell.
A missing periodicity flag means periodic on every axis.

\paragraph{R1, the mask.}
Column 4 is the integer of Table \ref{tab:mask}.
Mask 0 is free, mask 4 fixes \(z\) only, and mask 7 fixes every axis.
A float spelling, a sign, or a value outside 0 to 7 is an illegal flag.
Under version 1 the column is 0 or 1, so masks 4 and 7 cannot be stored as written.

\paragraph{R2, the identity.}
Column 5 is an integer from 0 through \(2^{64}-1\).
Writers emit ids unique within a frame.
A missing id column takes the zero-based row index.

\paragraph{R3, the time unit.}
From minor 1, a velocity block declares \texttt{units.time}.
The natural unit is spelled \texttt{(amu*angstrom\textasciicircum{}2/eV)\textasciicircum{}0.5}.
Versions 1, 2 and 3.0 are read in the natural unit.
An fs label on those older files is not trusted: producers of that era wrote natural-unit numbers under an fs label \cite{rohitgoswamiTheochemuieonV3602026}.

\paragraph{R4, the numbers.}
Readers convert each finite decimal to binary64 with correct rounding \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019,goldbergWhatEveryComputer1991,clingerHowReadFloating1990,clingerHowReadFloating2004}.
The default writer prints the shortest decimal that parses back to the same value.
That printer is the end of the line that runs from the early correct algorithms through Grisu, Errol and Ryū \cite{steeleHowPrintFloatingpoint1990,steeleHowPrintFloatingpoint2004,burgerPrintingFloatingpointNumbers1996,loitschPrintingFloatingpointNumbers2010,andryscoPrintingFloatingpointNumbers2016,adamsRyFastFloattostring2018}.
Six fixed decimals are an optional writer mode.
gzip and zstd wrap the same bytes, and a reader recognises the wrapper by content \cite{deutschGzipFileFormat1996,colletZstandardCompressionApplicationzstd2021}.
The wrapper is part of the grammar: a conforming reader accepts the compressed file and returns the same frames.

\paragraph{R5, the version.}
Table \ref{tab:keys} lists the reserved keys of the JSON line.
A reader accepts a later minor of a known major, keeps an unknown key on rewrite, may skip an unknown section whose width is declared, and rejects an unknown major.
H5MD uses the same split for its version pair \cite{buylH5mdStructuredEfficient2014}.
Table \ref{tab:versions} is the history of the grammar.
Table \ref{tab:sections} is the sections reserved at minor 1.
Table \ref{tab:rules} is the reader rules.
The grammar of one frame is the 50-rule listing in Section \ref{sec:appendix-abnf}.
The prose specification wins where the listing and the prose disagree.

\subsection{What the text costs}
\label{sec:rationale}
eOn has written CON since its first releases, so the campaigns already on disk are in this grammar \cite{chillEonSoftwareLong2014}.
The server and its clients exchange those files across machines, and the bytes do not depend on endianness \cite{pedersenDistributedImplementationAdaptive2010}.
A diff of a text checkpoint shows a changed mask or id.
The JSON line takes a new key without a new grammar, and a reader keeps a key it does not know \cite{brayJavascriptObjectNotation2017}.

Table \ref{tab:sizes} is the byte cost on the committed size table: one 218-atom frame, and the same frame repeated \(10{,}000\) times, raw and after gzip at level 6.
The repeated file is the same text, so its gzip column is smaller than the gzip column of a trajectory whose frames differ.
That is the measurement in the table.
One CON frame is \(41.99\) bytes per atom, against \(83.64\) for extended XYZ written by ASE with the mask column, \(314.39\) for one H5MD frame written by MDAnalysis, and \(95.40\) for one H5MD frame written by h5py with binary64 positions, a mask dataset and an id dataset.
At \(10{,}000\) copies the raw CON cost stays \(41.99\) bytes per atom.
H5MD amortises its container and falls to \(12.61\) and \(24.04\) bytes per atom.
gzip of the repeated CON file reaches \(0.39\) bytes per atom.
H5MD is the record for a long trajectory, where binary storage and chunked reads pay for the container \cite{buylH5mdStructuredEfficient2014}.
CON is the record for the checkpoint, where one frame has to keep the mask, the id and the unit.

\section{Reference implementation}
\label{sec:implementation}
readcon-core 0.17.0 is the reference reader and writer \cite{goswamiReadconcoreConconvelReaderwriter2026}.
The concept record covers every version \cite{goswamiReadconcoreConConvel2026}.
The store measurements in Section \ref{sec:perf-db} use 0.16.2 \cite{goswamiReadconcoreV0162Conconvel2026}.
Figure \ref{fig:architecture} is the layering.
One Rust core parses and writes.
One C interface is the waist every other caller uses.
C++ wraps it for eOn.
Python exposes array views \cite{harrisArrayProgrammingNumpy2020}.
Julia calls the C symbols through its foreign-function interface \cite{bezansonJuliaFreshApproach2017}.
Fortran 2008 reaches the same symbols through C interoperability.
chemfiles took the same route for trajectories, one core and several language bindings \cite{frauxChemfileschemfilesVersion01042023}.
Rust gives the core memory safety without a garbage collector on the far side of a C interface \cite{jungRustbeltSecuringFoundations2018,perkelWhyScientistsTurning2020}.
Decimal fields go through a correctly rounded conversion on that shared path \cite{lemireNumberParsingGigabyte2021,mushtakFastNumberParsing2023}.
A second parser would be a second implementation.
The public Fortran wrapper shows that a binding can still disagree with the core; Section \ref{sec:cases} records the status it returns.

\centering
\includegraphics[width=0.92\textwidth]{figures/generated/architecture.pdf}
\caption{The Rust core parses and writes CON.
The C interface is the waist.
eOn 3.6.0 calls the C++ wrapper.}
\label{fig:architecture}

The caller owns a frame handle and frees it.
Structure-of-arrays accessors return a pointer into that frame.
Absent numeric metadata is a NaN sentinel and is not written back.
The reader records the byte offset of each frame.
The scan that finds those offsets is serial, because each start depends on the counts before it.
Each frame is then parsed on its own, and the frames return in file order.
The Python binding releases the interpreter lock during the parse and takes it back to build objects.

\begin{lstlisting}[language=Python,caption={A round trip in Python. The default printer preserves binary64. Six decimals are a separate argument.},label={lst:py}]
frames = readcon.read_con("slab.con")
readcon.write_con("rt.con", frames)
\end{lstlisting}

readcon-db is the campaign store for that text \cite{goswamiReadcondbMmapCon2026}.
It writes each CON frame into LMDB, posts an xxHash3-128 of the text, and keeps secondary indexes on atom count, composition, energy, maximum force and section presence.
A select touches the index and then the frames the index names.
Identical texts share one hash entry, and each frame keeps its own stored text, so the stored blob bytes equal the raw file.
gzip and zstd remain properties of the CON bytes, recognised by content before ingest.
The MPI paths are a single writer, which inserts in global frame order, and a sharded ingest.
Section \ref{sec:perf-mpi} measures both.
Two behaviours of the bindings are part of the same test, and both are visible in the evaluation record.
Python \texttt{ConCorpus.select} always applies an atom-count range, including the default range from 0 to \(2^{32}-1\), so a Python query walks the atom-count index.
The timed queries use the Rust select and do not add that predicate.
\texttt{readcon.iter\_con} skips a leading newline, so an empty user line shifts the header and the parse fails.
\texttt{read\_con} on one frame keeps that empty line.
The specification says an empty first header line is the user line and is kept.
The evaluation writes the user line \texttt{cpc-eval} so the iterator can read the corpus.
\texttt{from\_ase} leaves the user line empty, which is legal CON.

Table \ref{tab:peers} is readcon-core through its Python binding at one worker, divided by the peer, so a ratio below 1 means readcon-core finished sooner.
Campaign A, rustc 1.88, thirty interleaved pairs, compares the ASE eon reader, chemfiles XYZ, h5py and MDAnalysis H5MD.
On \(10{,}000\) frames the ratios are \(0.337\) against ASE eon (readcon-core \(1.269\,\mathrm{s}\), ASE \(3.745\,\mathrm{s}\)), \(2.15\) against chemfiles XYZ, \(67.1\) against h5py (peer \(0.01899\,\mathrm{s}\)), and \(0.207\) against MDAnalysis H5MD (peer \(6.179\,\mathrm{s}\)).

The ASE eon ratio on the same \(10{,}000\)-frame file is \(0.348\), against \(0.337\) in campaign A.

XYZ and H5MD peers receive coordinates of the same frames, written before the timed loop.
Section \ref{sec:appendix-peers} extends the table to the 1-frame and 100-frame files.
On one frame the open dominates, and h5py and chemfiles lose the lead they have on the long file.

\texttt{RAYON\_NUM\_THREADS} and \texttt{OMP\_NUM\_THREADS} were 1, so a rank does not spawn a second pool.

readcon-core was 0.17.0 at \texttt{af8aabb}.
readcon-db was 0.1.8 at \texttt{55214d1}.

Cold repeats drop the page cache.
Warm repeats follow an untimed warmup.
The median is the third of the five sorted times.
Every one of the 480 repeats matched the serial bytes.

\subsection{The store}
\label{sec:perf-db}
The store measurements are the readcon-db evaluation at commit \path{6146c3b}, copied into \path{paper/cpc/data/db}.
The host is an Intel Xeon, 8 CPUs, \(47.07\,\mathrm{GiB}\).
The software is Python 3.12.3, rustc 1.88.0, readcon-db 0.1.8, readcon-core 0.16.2, ASE 3.29.0 and numpy 2.5.4.
Threads are pinned to 1 so the three stores run under one cap.
Five repeats are interleaved.
Cold is a \texttt{posix\_fadvise} \texttt{DONTNEED} hint and then a fresh process; the run did not drop the page cache.
Warm is the next query in that process.
The timed corpora have \(1{,}000\) and \(10{,}000\) frames, and every frame has its own xxHash3-128, so the ingest timing is not a deduplication win.
The frames come from ASE EMT searches: an HCN/HNC band of 157 frames, a Cu adatom band of 159, a Pt--H band of 83, and a Pt adatom dimer of 71, plus an adaptive kinetic Monte Carlo trace of \(4{,}000\) steps on three systems.
EMT on H, C and N is not a quantitative barrier.
The HCN saddle in that trace is \(197.6\,\mathrm{eV}\) with no hops, the Cu saddle is \(5.23\,\mathrm{eV}\) with barrier about \(1.09\,\mathrm{eV}\) and no hops, and the Pt--H trace has \(1{,}664\) hops and a barrier about \(0.03\,\mathrm{eV}\).
eOn was not used for those searches.
A \(100{,}000\)-frame ingest was not timed: ASE's database writes about \(200\) frames/s and does not finish in two minutes.
One million frames does not fit the default \(2\,\mathrm{GiB}\) map.

At \(10{,}000\) frames the ingest medians are \(0.311306\,\mathrm{s}\) for readcon-db (\(32{,}123\) frames/s, \(35.09\,\mathrm{MB/s}\)), \(48.411\,\mathrm{s}\) for ASE's database committing every write (\(206.6\) frames/s), and \(5.985\,\mathrm{s}\) for one ASE connection that still commits every \(5{,}000\) rows (\(1{,}671\) frames/s).
The paired ratios are \(0.006800\) against the per-write commits and \(0.05283\) against the single connection.
At \(1{,}000\) frames the readcon-db median is \(0.03289\,\mathrm{s}\) (\(30{,}403\) frames/s).
The ingest table has 30 rows and the query table has 180, and every row passed the hit-count and index-sum check.
The composition query is Cu with 9 atoms: 292 hits at \(1{,}000\) frames and \(2{,}542\) hits at \(10{,}000\) frames.

At \(10{,}000\) frames the readcon-db query medians are \(8.14\,\mathrm{ms}\), \(10.1\,\mathrm{ms}\) and \(9.57\,\mathrm{ms}\) cold for composition, energy and maximum force, and \(0.176\,\mathrm{ms}\), \(0.211\,\mathrm{ms}\) and \(0.208\,\mathrm{ms}\) warm.
ASE's database takes \(0.286\,\mathrm{s}\), \(0.223\,\mathrm{s}\) and \(0.225\,\mathrm{s}\) cold, and \(0.258\,\mathrm{s}\), \(0.203\,\mathrm{s}\) and \(0.206\,\mathrm{s}\) warm.
A directory of the same text in 64-frame chunks takes \(0.193\,\mathrm{s}\), \(0.193\,\mathrm{s}\) and \(0.197\,\mathrm{s}\) cold, and \(0.140\,\mathrm{s}\), \(0.138\,\mathrm{s}\) and \(0.138\,\mathrm{s}\) warm.
The index is what the warm readcon-db number measures.

Allocated bytes at \(10{,}000\) frames are \(10{,}923{,}745\) for the raw CON text, \(3{,}241{,}302\) after gzip level 6, \(3{,}312{,}800\) after zstd level 3, \(11{,}501{,}568\) for the directory, \(27{,}340{,}800\) for readcon-db and \(8{,}929{,}280\) for ASE's database.
readcon-db is \(2.503\) times the raw text: the text plus the indexes.
The \(2\,\mathrm{GiB}\) figure is the map ceiling, not this file.
At \(1{,}000\) frames zstd level 3 (\(270{,}863\) bytes) is smaller than gzip level 6 (\(277{,}258\) bytes).
At \(10{,}000\) frames zstd is the larger of the two.
The adaptive kinetic Monte Carlo trace has \(24{,}000\) frames and \(27{,}864{,}917\) stored blob bytes, equal to the raw file, and 7 unique hashes whose text is \(8{,}319\) bytes.
A corpus of those seven texts allocates \(98{,}304\) bytes; the full trace allocates \(74{,}911{,}744\).
The seven texts are the unhopped HCN state and its saddle, the unhopped Cu state and its saddle, and both Pt--H states with that saddle.
Nine correctness checks pass: a round trip, identical bytes sharing one hash entry, a one-digit coordinate change, a missing force or velocity section, periodicity taken only from the declared flags, a rebuild of the indexes from the stored text, a second rebuild, an ignored numeric cache, and a hash entry that remains after a duplicate is rewritten.
Section \ref{sec:appendix-db} records the repeats and the figures.

\section{Limitations}
\label{sec:limitations}
A frame stores geometry and its labels.
It does not store the short history of a quasi-Newton update or of a FIRE step.
The control in Section \ref{sec:cases} is the measurement: both printers agree with each other at \(0.670723\,\mathrm{eV}\) and differ by \(0.037113\,\mathrm{eV}\) from the uninterrupted barrier.
The corpus decides the listed files.
Agreement among the language bindings is agreement of one core, and the public Fortran wrapper shows that a binding can still fail while that core is unchanged.
The resumed bands are one EMT Pt hop and one Morse band.
They show what a lost field does to those searches.
The EMT energies quoted for H, C and N are recorded as the trace produced them: the HCN saddle is \(197.6\,\mathrm{eV}\), and that potential is not a quantitative barrier for those atoms.
Peer ratios hold for the library versions named in Sections \ref{sec:requirements} and \ref{sec:perf-peers}.
The MPI claim covers ranks 1 to 8 on the 8-core virtio host in Section \ref{sec:perf-mpi}.
The default LMDB map is \(2\,\mathrm{GiB}\), and one million frames returns \texttt{MDB\_MAP\_FULL}.
CON is the checkpoint record.
H5MD is the trajectory record.
The byte counts in Table \ref{tab:sizes} are the measured cost of the checkpoint text.

\section{Conclusions}
\label{sec:conclusions}
The geometry file in a rare-event campaign is the restart state of the search.
The resume reads a per-axis mask, a persistent id, a declared time unit, binary64 coordinates with their periodic flags, and a version two readers agree on.
On one masked slab, every common format tested here drops at least one of those fields.
The ASE POSCAR resume drops the height constraint and finishes \(70.2\,\mathrm{meV}\) lower.
Five extended XYZ readers return four answers for one file.
CON 3.1 states the grammar, the corpus decides the listed files, and one parser serves the five languages.
Twenty-five language pairs resume the climbing-image band at the uninterrupted barrier.
The public Fortran wrapper, tested the same way, returns status \(-4\) and writes no usable frame.
A warm read costs \(12.6\,\mu\mathrm{s}\) per 218-atom frame.
Shared MPI reads and MPI-IO writes speed up across eight ranks on this host.
The sharded ingest does not stay flat under weak scaling.
readcon-db stores the CON text, indexes it, and ingests it in parallel; those are the operations Section \ref{sec:perf-db} and Section \ref{sec:perf-mpi} time.
