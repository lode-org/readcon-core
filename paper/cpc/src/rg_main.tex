readcon-core formalizes that text as CON 3.1 and improves the fields a restart reads back.
A JSON line states the version and the units.

\textit{Nature of problem:} Rare-event campaigns stop and resume saddle searches from a stored geometry.
A resumed surface search reads which Cartesian components of each atom are fixed, because a held component removes a mode from the harmonic prefactor and can move the saddle.
It reads an identifier on each row, because events and band images are matched by atom identity, and the time unit of the velocities, because a misread unit scales the kinetic energy by the square of the conversion factor.
A restart that repeats the interrupted run to roundoff also reads back the binary64 coordinates as written.
Of the formats in common use, H5MD defines no mask element, the POSCAR structure file defines no atom identifier, and extended XYZ keeps both in column names that one library chose and names no time unit.
CON is a geometry format used in many codes, and it had no specification, so each reader decided for itself which files are legal and what each column means.

\textit{Solution method:} CON 3.1 is a versioned grammar for that text, and readcon-core is the reference reader and writer that formalizes and improves it.
The second line of a frame is a JSON object that declares the major and minor version, the units, the periodic flags and the per-atom sections after the coordinates.
The fourth column of a coordinate row is a three-bit mask of fixed components and the fifth an atom identifier.
From minor 1 a velocity section declares its time unit.
A reader of a known major accepts any later minor, keeps unknown keys and skips a later section by its declared width.
The writer prints the shortest decimal that reads back as the same binary64 value, and the reader rounds each decimal to the nearest binary64 value.
Two corpora of legal and illegal files fix the verdict of a conforming reader on the clauses of the specification.
readcon-core implements the grammar once in Rust, behind a C interface for C++, Julia and Fortran and a PyO3 binding for Python.
On more than one thread it walks the frame boundaries serially by the counts in each header, parses the frames in parallel and returns them in file order.
A path writer replaces the destination only after the last frame is accepted.

\textit{Additional comments including restrictions and unusual features:} The release described is readcon-core~\readconversion{} (Data availability).
Every build reads gzip input; zstd input and parallel parsing are build features, and the Python wheel enables both.
A frame stores Cartesian coordinates, the cell, the periodic flags, the mask, one identifier per atom, and optional per-atom velocities, forces, energies, charges, spins, magnetic moments, displacements and spreads.
It stores no optimiser history, so an optimiser with memory takes a different path after a restart.
Files that earlier eOn releases wrote are grammar version 1 and read as such.
The velocities of a file of an earlier version are read in the natural unit of eOn whatever time unit the file names.
In Python, \texttt{readcon.read\_con(path)} returns the frames of a file (Listing~\ref{lst:py}).

\section{Introduction}\label{sec:introduction} Rare-event methods turn a potential energy surface into rates.
Transition state theory \cite{eyringActivatedComplexChemical1935,vineyardFrequencyFactorsIsotope1957,hanggiReactionrateTheoryFifty1990} reduces the kinetics of an activated process to its saddle points and the vibrations there.
The saddles are located by the nudged elastic band \cite{jonssonNudgedElasticBand1998,henkelmanClimbingImageNudged2000,henkelmanImprovedTangentEstimate2000,asgeirssonNudgedElasticBand2021}, by minimum-mode followers \cite{henkelmanDimerMethodFinding1999,kastnerSuperlinearlyConvergingDimer2008,olsenComparisonMethodsFinding2004} and by string methods \cite{eStringMethodStudy2002,petersGrowingStringMethod2004}.
Adaptive kinetic Monte Carlo (AKMC) and accelerated dynamics chain them into trajectories of seconds and longer \cite{henkelmanLongTimeScale2001,xuAdaptiveKineticMonte2008,voterExtendingTimeScale2002,perezLongtimeDynamicsThrough2016}.
A long-timescale run in eOn \cite{chillEonSoftwareLong2014,rohitgoswamiTheochemuieonV3602026} spawns thousands of saddle searches, often on volunteer or distributed resources \cite{andersonBoincSystemPublicresource2004,pedersenDistributedImplementationAdaptive2010}.
It passes their geometries between Python drivers \cite{larsenAtomicSimulationEnvironmenta2017,hermesSellaOpensourceAutomationfriendly2022}, C++ engines and Fortran electronic structure codes \cite{kresseEfficiencyAbinitioTotal1996}.
A search that stops on one machine resumes on another from a geometry file, the checkpoint of the search.

The checkpoint has to return four fields that a trajectory reader can ignore.
A surface search fixes the slab and can hold an adatom at a set height while it crosses the surface, so mobility belongs to each Cartesian component, and a lost hold changes the saddle that the search converges to (Section~\ref{sec:prefactor}).
Mode following and AKMC bookkeeping match atoms across frames and events by an identifier on each row.
A reader has to return that identifier as written rather than as the row order.
Dynamical steps read velocities, and the natural time unit of eOn is \((\mathrm{amu}\,\text{\AA}^2/\mathrm{eV})^{1/2}=\wkTimeFs\,\mathrm{fs}\), so a reader that takes the same numbers as \(\text{\AA}/\mathrm{fs}\) scales the kinetic energy by \(\velFactorSq\).
A restart that repeats the interrupted run to roundoff reads back binary64 coordinates \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019}.
For that, the writer prints the shortest decimal that reads back as the same double \cite{steeleHowPrintFloatingpoint1990,adamsRyFastFloattostring2018}, and the reader rounds each decimal to the nearest double \cite{clingerHowReadFloating1990}.
Two readers given the same bytes must then return the same fields, and that takes a versioned grammar rather than the convention of one reader.

Existing formats keep some of these fields.
Extended XYZ adds key-value metadata to the comment line of the plain Cartesian coordinate format (XYZ) and publishes a grammar \cite{kermodeLibatomsExtxyzV0462026}.
It keeps masks and identifiers in column names that the Atomic Simulation Environment (ASE) chose \cite{larsenAtomicSimulationEnvironmenta2017}, and a file declares no version and no velocity unit.
H5MD \cite{buylH5mdStructuredEfficient2014,folkOverviewHdf5Technology2011} stores identity, velocities with units and the box in HDF5, and it defines no element for a per-component constraint.
The GROMACS compressed trajectory (XTC) and full-precision trajectory (TRR) formats \cite{abrahamGromacsHighPerformance2015}, the binary trajectory (DCD) format of CHARMM \cite{brooksCharmmBiomolecularSimulation2009} and the trajectory next generation (TNG) format \cite{spangbergTrajectoryNgPortable2011,lundborgEfficientExtensibleFormat2014} store molecular dynamics output with neither a mask nor a velocity unit.
The ASE trajectory keeps every field in a layout that the Python code of ASE defines.
POSCAR, the structure file of the Vienna Ab initio Simulation Package \cite{vaspwikiPoscar2026,kresseEfficiencyAbinitioTotal1996}, stores a per-component hold as selective-dynamics flags but no atom identifier.
Many of these formats are read and written by chemfiles \cite{frauxChemfileschemfilesVersion01042023}, MDAnalysis \cite{gowersMdanalysisPythonPackage2016}, the Open Visualization Tool (OVITO) \cite{stukowskiVisualizationAnalysisAtomistic2010} and Open Babel \cite{oboyleOpenBabelOpen2011}.
Of the four, none opens a version-1 CON file or a CON 3.1 file, and the eon module of ASE opens both but stops at the velocity section of the frame of Section~\ref{sec:worked}.

Most atomistic formats have no specification apart from the code that reads them, so that code is the de facto definition of the format.
Particle physics fixed the files that pass between independent event generators in published texts: the Les Houches event file \cite{Alwall2007LHEF}, the second Les Houches Accord for supersymmetric spectra \cite{Allanach2009SLHA2} and the HepMC3 library for generator events \cite{Buckley2021HepMC3}.
Electronic structure has done the same for densities and wavefunctions with the European Theoretical Spectroscopy Facility (ETSF) file format \cite{Gonze2008ETSF} and TREXIO \cite{posenitskiyTrexioFileFormat2023}, and for pseudopotentials with the pseudopotential markup language (PSML) \cite{Garcia2018PSML}.
A computed barrier is reproducible from a file only when every reader returns the same fields from it.
A versioned specification and a corpus of files with known verdicts turn that condition into a test of any reader.

Here, we describe CON 3.1 and readcon-core.
CON is a file format used in many places.
CON 3.1 formalizes that text, and readcon-core improves it with a JSON header line that declares a version, the units and the periodic flags, a three-bit mask of fixed components and an atom identifier on each coordinate row, declared per-atom sections, and coordinates that read back as the binary64 values written.
A borrowed DLPack view of the positions costs \dlpackRatio{} times an explicit copy (Section~\ref{sec:dlpack}).
readcon-core is its reference reader and writer, one Rust core behind C, C++, Python, Julia and Fortran interfaces, a layout that it takes from chemfiles \cite{frauxChemfileschemfilesVersion01042023}.
Section~\ref{sec:worked} reads one frame line by line and measures what each field changes when a reader gets it wrong, and Section~\ref{sec:format} states the grammar and its version rule.
Sections~\ref{sec:implementation} and~\ref{sec:conformance} give the reader and test it against the corpora, Section~\ref{sec:cases} resumes saddle searches from checkpoints that we wrote and read back with readcon-core and with other libraries, and Section~\ref{sec:performance} times readcon-core against ASE, MDAnalysis, OVITO, pymatgen and a pure Python parse of the same CON file.
Unlike H5MD, TNG and extended XYZ, the CON 3.1 specification defines all four fields that a restart reads, and its corpus of legal and illegal files decides the verdict of any reader on each clause.
readcon-core is the only reader in this comparison that returns the fixed-component mask, the atom identifier and the velocity time unit from places that specification defines.
No other reader both accepts a later minor of a known major and decides each file of the conformance corpus.

The header line is one JSON object \cite{brayJavascriptObjectNotation2017}, recognised by its first non-blank character, \texttt{\{}, and a frame whose header is anything else is grammar version~1, the text that earlier eOn releases write.
The object of Listing~\ref{lst:frame} names the major and the minor of the grammar, declares the slab periodic in \(x\) and \(y\) and open in \(z\), lists \texttt{velocities} as the one section after the coordinates, and states the units of length, energy, mass and time.

The two cell lines carry the lengths \(a=b\approx\wkLengthA\,\text{\AA}\) and \(c=\wkLengthC\,\text{\AA}\) and the angles \(\alpha\), \(\beta\) and \(\gamma\) in degrees, from which the reader rebuilds the cell with \(\mathbf{a}\) along \(x\) and \(\mathbf{b}\) in the \(xy\) plane \cite{bekkerUnificationBoxShapes1997},
\begin{equation}
\label{eq:cell}
\begin{aligned}
\mathbf{a}&=a\,\hat{\mathbf{x}},\qquad
\mathbf{b}=b\cos\gamma\,\hat{\mathbf{x}}+b\sin\gamma\,\hat{\mathbf{y}},\\
\mathbf{c}&=c\cos\beta\,\hat{\mathbf{x}}+c\,\kappa\,\hat{\mathbf{y}}+c\sqrt{\rho}\,\hat{\mathbf{z}},\\
\kappa&=\frac{\cos\alpha-\cos\beta\cos\gamma}{\sin\gamma},\qquad \rho=1-\cos^2\beta-\kappa^2.
\end{aligned}
\end{equation}
In binary64 the cosine of the double nearest \(\pi/2\) is \(\num{\wkCosRight}\), so Eq.~\eqref{eq:cell} gives this cell \(b_x=\num{\wkBx}\,\text{\AA}\) and \(c_x=c_y=\num{\wkCxy}\,\text{\AA}\).
ASE~\wkAseVersion{} returns \(b_x=\wkAseRightBx\), because it sets the cosine of an angle within two units in the last place of a right angle to zero \cite{larsenAtomicSimulationEnvironmenta2017}.

The radicand \(\rho\) decides whether three angles describe a cell at all.
The volume of the cell of Eq.~\eqref{eq:cell} is \(V=a\cdot b\sin\gamma\cdot c\sqrt{\rho}\), and \(V^2\) is the determinant of the Gram matrix \(G\) of the three vectors, so
\begin{equation}
\label{eq:gram}
\begin{aligned}
\rho\,\sin^2\gamma = D &= 1-\cos^2\alpha-\cos^2\beta-\cos^2\gamma+2\cos\alpha\cos\beta\cos\gamma,\\
\det G &= a^2b^2c^2D .
\end{aligned}
\end{equation}
No three vectors in space have angles with \(D<0\), and \(D=0\) is a flat cell.
Two variants of the angle line show both cases.
The exact \(\rho\) is zero for angles of \(\wkFlatAlpha\), \(\wkFlatBeta\) and \(\wkFlatGamma\) degrees, since \(\mathbf{c}\) then lies in the plane of \(\mathbf{a}\) and \(\mathbf{b}\), and binary64 gives \(\hat\rho=\num{\wkFlatRadicand}\).
readcon-core accepts that frame with \(c_z=0\), because \(\hat\rho\) lies inside the window of \(\num{\wkWindow}\) that Section~\ref{sec:format} gives for the roundoff of a zero radicand, and ASE stops on its own assertion that \(\hat\rho\ge0\).
With \(\wkNoneAlpha\), \(\wkNoneAlpha\) and \(\wkNoneGamma\) degrees, \(D=\wkNoneGram\) and \(\rho=\wkNoneRadicand\).
readcon-core rejects that frame with an error that names line~\trCellLine, and ASE fails the same assertion without naming a line.
ASE also refuses Listing~\ref{lst:frame} itself: its eon reader takes the blank line~\wkLineBlank{} for the first line of a second frame and stops when line~\wkLineVelocities{} fails to parse as three cell lengths.

After two free lines come the counts, one atom type, nine atoms of that type and the mass of the type, and then a block for each type: its symbol, a label, and one row of \(x\), \(y\), \(z\), the mask and the identifier per atom.

For a frame of major \(M\), with \(M=1\) when the header is not JSON, the mask is the integer
\begin{equation}
\label{eq:mask}
m =
\begin{cases}
b_x + 2 b_y + 4 b_z, & M\ge 2,\\
b_x = b_y = b_z, & M = 1,
\end{cases}
\qquad b_\alpha\in\{0,1\},
\end{equation}
with \(b_\alpha=1\) when component \(\alpha\) is fixed.
The bottom rows of Listing~\ref{lst:frame} are fixed in every component, the top layer is free, and the adatom is held in \(z\) alone.
A reader that applies the version-1 rule of Table~\ref{tab:clauses} to this frame rejects the mask of the adatom as an illegal flag, and one that applies the CON 3.1 rule to a version-1 file frees \(y\) and \(z\) of every atom held there.
Section~\ref{sec:prefactor} measures what a lost hold of the adatom changes: the band crosses another saddle, with a larger prefactor.

The identifier is the index of the atom in the numbering of the writer, from \wkIdFirst{} on the first row to \wkIdLast{} on the last, and between \wkIdLow{} and \wkIdHigh{} in all.
Grouping by type has permuted that numbering, and ascending identifier restores it.
A reader returns the identifiers in file order and exactly, up to \(2^{64}-1\), and a row without an identifier takes its zero-based position in the frame.
Of the cross-library round trips of Section~\ref{sec:cases}, one returns no identifiers at all.

The blank line~\wkLineBlank{} opens the velocity section that the header declared, and the section repeats the block shape with one row of \(v_x\), \(v_y\), \(v_z\), mask and identifier per atom.
The held atoms have zero velocity and the adatom has \(v_z=0\), so \wkMovingAtoms{} atoms move.
Their unit is the one the header names, eOn's natural unit,
\begin{equation}
\label{eq:tau}
\tau=\left(\frac{m_{\mathrm{u}}\,\text{\AA}^{2}}{\mathrm{eV}}\right)^{1/2}
=\left(\frac{1.6605\times10^{-27}\,\mathrm{kg}\cdot 10^{-20}\,\mathrm{m}^{2}}{1.6022\times10^{-19}\,\mathrm{J}}\right)^{1/2}
=\wkTimeFs\,\mathrm{fs},
\end{equation}
with the CODATA 2018 values of the atomic mass constant \(m_{\mathrm{u}}\) and the electronvolt \cite{tiesingaCodataRecommendedValues2021}.
In that unit the frame has a kinetic energy \(\tfrac{1}{2}\sum_i m_i\lvert\mathbf{v}_i\rvert^2\) of \(\wkKinetic\,\mathrm{eV}\).
A reader that takes the same numbers as \(\text{\AA}/\mathrm{fs}\) returns \(\wkKineticMisread\,\mathrm{eV}\), larger by \((\tau/\mathrm{fs})^2=\velFactorSq\).

The coordinates are printed in the shortest form that reads back as the same binary64 value \cite{steeleHowPrintFloatingpoint1990,adamsRyFastFloattostring2018}, here \wkDigitsMin{} to \wkDigitsMax{} significant digits, and the reader rounds each decimal to the nearest binary64 value \cite{clingerHowReadFloating1990,lemireNumberParsingGigabytes2021}.
A writer that prints six decimals instead puts \(x=\wkFirstXRounded\) in line~\wkLineFirstRow, a shift of \(\num{\wkShiftFirst}\,\text{\AA}\), and moves the \wkCoordinates{} coordinates by up to \(\num{\wkShiftMax}\,\text{\AA}\).
Resumed from six decimals, the climbing-image band of Section~\ref{sec:cases} converges in the same step count with its barrier moved by \(\num{\rfDeSixNum}\,\mathrm{eV}\).
The frame ends after line~\wkLineLastVelocity, and the next line, if any, opens the next frame.
Listing~\ref*{lst:testrun} of the supplementary material runs the example program of the release on this file and on the two variants of the angle line.

\section{The grammar of CON 3.1}\label{sec:format} Section~\ref*{sec:spec-normative} of the supplementary material is the normative specification, \clauseTotal{} numbered clauses, and this section states the rules that Section~\ref{sec:worked} used, with the clauses behind them in Table~\ref{tab:clauses}.
A CON file is one or more frames with no marker between them, followed only by lines of white space.
With \(T\) atom types of \(N_k\) atoms each, a frame \(\mathcal{F}\) is
\begin{equation}
\label{eq:frame}
\begin{aligned}
\mathcal{F}&\to \lambda_1\ \ \lambda_2\ \ (a\ b\ c)\ \ (\alpha\ \beta\ \gamma)\ \ \lambda_5\ \ \lambda_6\ \ T\ \ (N_1\cdots N_T)\\
&\qquad (M_1\cdots M_T)\ \ \mathcal{B}_1\cdots\mathcal{B}_T\ \ \mathcal{S}^{*},\\
\mathcal{B}_k&\to s_k\ \ (\text{\texttt{Coordinates of Component}}\ k)\ \ \bigl(x\ y\ z\ m\ [\iota]\bigr)^{N_k},\\
\mathcal{S}&\to \varnothing\ \ \mathcal{V}_1\cdots\mathcal{V}_T,\\
\mathcal{V}_k&\to s_k\ \ (S\ \text{\texttt{of Component}}\ k)\ \ \bigl(v_1\cdots v_w\ m\ \iota\bigr)^{N_k},
\end{aligned}
\end{equation}
where each symbol or parenthesised group is one line, a superscript repeats a line, \(\lambda_1\), \(\lambda_5\) and \(\lambda_6\) are free lines, \(\lambda_2\) is the header, \(M_k\) and \(s_k\) are the mass and symbol of type \(k\), \(\iota\) is the identifier, \(\varnothing\) is a blank line and \(S\) is the name of a section of width \(w\).
A type count of zero is a frame without atoms.
The release includes this shape as an informative parsing expression grammar (PEG) \cite{fordParsingExpressionGrammars2004}, and where the PEG admits a token that a clause rejects, the clause decides.

The cell rule rests on Eq.~\eqref{eq:gram}.
readcon-core evaluates Eq.~\eqref{eq:cell} in binary64, accepts the angles when the computed radicand satisfies \(\hat\rho>-\num{\wkWindow}\), sets \(c_z=0\) when such a \(\hat\rho\) is negative, and otherwise rejects the frame as a validation error, a class that the specification leaves open.
The window is fixed, so it accepts as flat a cell whose exact radicand lies between \(-\num{\wkWindow}\) and zero, and it rejects every set of angles that misses a real cell by more.

Table~\ref{tab:clauses} gives the masks that each version admits and the range of the identifier.
The readcon-core writer refuses a frame that repeats an identifier, and no clause binds the identifiers of one frame to those of another.

Each number is a finite decimal that the reader rounds to the nearest binary64 value, ties to even \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019,clingerHowReadFloating1990,lemireNumberParsingGigabytes2021}.
The default writer prints the shortest decimal that rounds back to the same value \cite{steeleHowPrintFloatingpoint1990,loitschPrintingFloatingpointNumbers2010,andryscoPrintingFloatingpointNumbers2016,adamsRyFastFloattostring2018}, so writing a frame and reading it back returns every coordinate unchanged, and a setting prints six fixed decimals instead.
A gzip or zstd envelope wraps the same text \cite{deutschGzipFileFormat1996,colletZstandardCompressionApplicationzstd2021}, and a reader recognises it by content.
readcon-core decodes zstd when built with that feature and otherwise refuses the file by name.

\label{eq:version}
\begin{aligned}
&M\in\{2,3\}\ \wedge\ \mu\in\mathbb{N}\\

\end{aligned}
\end{equation}

\section{Reference implementation}\label{sec:implementation} readcon-core implements the grammar once, in Rust (Figure~\ref{fig:architecture}).
C++, Julia \cite{bezansonJuliaFreshApproach2017} and Fortran 2008 call its C interface, and Python calls the Rust core through PyO3 and receives NumPy arrays \cite{harrisArrayProgrammingNumpy2020}.
eOn links readcon-core through the C++ wrapper, and its public release \eOneEonVersion{} embeds readcon-core \eOneEonReadcon, which writes CON 3.0 \cite{rohitgoswamiTheochemuieonV3602026}.
That layering follows chemfiles \cite{frauxChemfileschemfilesVersion01042023}, one core with a binding for each language, and we take it over unchanged.

An arrow runs from the caller to the code it calls.}

In the core, Algorithm~\ref{alg:parser} is the path reader of the release.
A plain file of fewer than \(B_{\mathrm{map}}=\wkMmapBytes\) bytes is read whole into memory, a larger one is memory-mapped, and a gzip or zstd file is decompressed into memory whatever its size.
One thread parses frame after frame.
At the default thread count, the global thread pool parses a text of at least \(B_{\mathrm{par}}=\wkParallelBytes\) bytes, and an explicit count above one parses in a pool of that size.
The parallel path walks the frame boundaries in one thread, because the start of each frame depends on the counts before it, then parses the frames independently and returns them in file order.
Table~\ref*{tab:anchors} of the supplementary material gives the source lines of each step.

% snapper:off.
\begin{algorithm}[tbp] \footnotesize \caption{Read a CON file from a path, as readcon-core~\readconversion{} does.}
\label{alg:parser} \begin{algorithmic}[1] \Require path; thread count \(P\), where absent or 0 selects the default \Ensure frames in file order, or an error that names its line \State Read the first four bytes; on gzip magic, decompress every member into memory \State On zstd magic, decompress when built with zstd, else \textbf{error}: unsupported zstd input \State Otherwise read a file shorter than \(B_{\mathrm{map}}\) whole, else memory-map it \If{\(P=1\), or no parallel feature, or \(P\) is the default and the text is shorter than \(B_{\mathrm{par}}\)} \State Parse frame after frame with \Call{ParseFrame}{} \Else \State Walk the frame boundaries in one thread, skipping each frame by its counts \State Parse the frames with \Call{ParseFrame}{} in a pool of \(P\) threads, or the global pool \EndIf \Function{ParseFrame}{} \State \textbf{error} on a byte-order mark at the start of the file; line 2 is JSON when it starts with \texttt{\{}, else version 1 \State Check the header against Eq.~\eqref{eq:version}; keep unknown keys \State Read the cell; \textbf{error} when \(\hat\rho\le-\num{\wkWindow}\) in Eq.~\eqref{eq:cell} \State Read the type counts, the masses and the coordinate rows \State Round each decimal to the nearest binary64 value; \textbf{error} on a value that is not finite; check each mask against Eq.~\eqref{eq:mask} \If{line 2 has no \texttt{sections} key} \State Read a legacy velocity block when a blank line and a complete block follow \Else \For{each name in \texttt{sections}, in order} \State Read a reserved section, or count the rows of a later minor's section of declared width, else \textbf{error} \EndFor \EndIf \State \textbf{error} on a velocity section without \texttt{units.time} when \(M=3\) and \(\mu\ge 1\) \EndFunction \end{algorithmic} \end{algorithm} % snapper:on.

One frame of \(N\) atoms costs \(\Theta(N)\) time and memory.
For a text of \(B\) bytes, after inflation for a gzip or zstd file, the read costs one serial \(\Theta(B)\) boundary walk and a \(\Theta(B)\) parse that \(P\) threads share, and the frames it returns occupy \(\Theta(B)\) memory.
A compressed file of \(C\) bytes is first inflated by one serial decoder in \(\Theta(C+B)\) time.
The peak resident set of each reader on this branch is in Section~\ref{sec:host}.

Every writer that takes a path writes its frames to a temporary file in the directory of the destination, flushes and syncs that file once the last frame is accepted, and renames it over the destination.
A frame that fails deletes the temporary file, so the destination keeps its earlier bytes.
The uncompressed writers of the C interface write a device or a named pipe in place, and a writer to a string or to a stream that the caller opened writes no temporary file.
Each language binding has a test that fails a write midway and compares the destination with its earlier bytes.
Listing~\ref{lst:py} reads a band from Python and writes it back to the same path, after which the file contains either its earlier frames or the frames written.

\begin{lstlisting}[language=Python,caption={\textbf{A checkpoint round trip in Python.} The default printer keeps every binary64 value; six decimals are a separate argument.},label={lst:py}]
import readcon
frames = readcon.read_con("band.con")
readcon.write_con("band.con", frames)
\end{lstlisting}

\section{Zero-copy tensor exchange}\label{sec:dlpack} A caller that already has a frame should read its coordinates as a tensor.
readcon-core exposes that tensor through DLPack \cite{dlpackDLPack2026}.
On the Rust builder the methods for positions, velocities, forces, per-atom energies and masses return a borrowed float64 tensor, and the method for atom identifiers returns a borrowed uint64 tensor.
The lifetime of each borrowed tensor is the builder, and the default build places it on the CPU.
A C caller that needs the tensor after the builder is gone takes the versioned managed tensor, and that export copies the storage.
Python materialises a contiguous NumPy array, and that array implements the DLPack protocol, so PyTorch, JAX and CuPy take the array with no second copy.
The measured exchange is the borrowed view against an explicit copy of the same positions, on a builder of \dlpackAtoms{} copper atoms.
One warm-up is followed by six repeats, and each repeat runs both arms, alternating which arm is first.
The machine line is \texttt{x86\_64}, 8 cores, Intel Xeon Processor.
The view takes a median of \dlpackViewUs{} microseconds and the copy a median of \dlpackCopyUs{} microseconds, so the view costs \dlpackRatio{} times the copy.
A 95 percent bootstrap interval for that ratio is \dlpackRatioLo{} to \dlpackRatioHi{}, and the interval excludes 1.
The type 7 interquartile ranges are \dlpackViewIqr{} microseconds and \dlpackCopyIqr{} microseconds.

\section{Conformance}\label{sec:conformance} A specification settles a dispute between readers only when each reader can be tested against it.
The conformance corpus of readcon-core~\readconversion{} contains \(\corpusConfValid\) legal and \(\corpusConfInvalid\) illegal files (Table~\ref{tab:corpus}), and its manifest names the error class of each illegal file.
Read through the Python module of the release, all \(\corpusConfAgree\) files return the verdict and error class of their manifest entries, and the release checks the same files from Rust, Python, C, Fortran and Julia.

Table~\ref{tab:corpus} is in the supplement.

That corpus has few files for the header, the sections and the units, so we wrote a second corpus of \(\cthreeoneFiles\) CON 3.1 files, \(\cthreeoneAccepted\) legal and \(\cthreeoneRejected\) illegal.
Its manifest names for each file the clauses that decide it and the outcome, the frame count and periodic flags of a legal file or the error class and line of an illegal one.
For \(\cthreeoneExplicit\) entries the outcome follows from the text of a clause, and the others record a reading where the text leaves a case open (Section~\ref*{sec:supp-corpus31}).
All \(\cthreeoneMatch\) files return the outcome of their entry at one, two and eight threads and at the default.
Both corpora also go through every read path of the Python module and the C library, in the default and the parallel build at each of those thread counts, and all \(\cpathsReads\) reads return the outcome that the manifests name (Table~\ref*{tab:corpus-paths}).

We also wrote an independent reader in \(\corpusIndepLines\) Python source lines that import nothing from readcon.
It follows the clauses of the specification, and where a clause requires a rejection without naming its class, or no clause decides a case, it follows the reading of the corpus manifest.
Of the \(\corpusFiles\) files of both corpora, the frame list and the frame iterator of readcon and the independent reader each return the manifest outcome on all \(\corpusIndepAgree\).
On the \(\corpusBoth\) files that both readers accept, all \(\corpusFieldIdentical\) carry the same bits in every coordinate, velocity and cell entry and equal masks, identifiers, units and periodic flags (Table~\ref*{tab:corpus-crosscheck}).
The two readers also read \(\mutantCases\) mutants of the \(\mutantFiles\) corpus files under \(\mutantMaxBytes\) bytes, \(\mutantPerSeed\) from each of \(\mutantSeeds\) seeds, each made by inserting, deleting or replacing characters and tokens at one to three random places.
They agree on \(\mutantSame\) of them, with the same frame count or error class.
The other \(\mutantDiffer\) fall in \(\mutantGroups\) cases that no clause decides: a count line that breaks two clauses at once, a number in the header past the binary64 range, and a carriage return as the last byte of the input.
A variant of the independent reader that follows readcon-core on each of those cases returns its verdict on all of them.

The release runs 19,545 differential cases mutated from its test files and its conformance corpus.
Every case is read from a string, from bytes, from a plain and a gzip file at one to sixteen threads, through the column readers and through the stream reader, and each read returns the frame count, coordinates and section presence of the one-thread string read or stops with its error at the same line.
Of the \(\clauseTotal\) clauses of the specification, \(\clauseCovered\) are named by a corpus file, a probe or a test of the library, and the other \(\clauseUncovered\) state no duty of a reader, such as the rules for revising the specification.

One name must mean one language for every reader that carries it.
The published wheels of readcon-core 0.17.0, 0.17.1, 0.17.2 and 0.17.3 do not return the same outcome on every probe file.
On files of two frames whose first line is empty, the oldest refuses the file and the later three read two frames, and on a blank symbol line the newest two refuse a file that the earlier two read (Section~\ref*{sec:supp-versions}).
Each of those changes decided a case that the text of its release left open, and Table~\ref{tab:versions} lists the clauses involved.

Extended XYZ is the text format to set beside CON on this test, because it has a published grammar, the specification of the libAtoms extxyz package \cite{kermodeLibatomsExtxyzV0462026}, and parsers in C, C++ and Python.

The adatom hops between neighbouring fourfold hollows along \(x\).
With the slab fixed, the EMT force on the adatom at that height exceeds the band tolerance.
That height is no stationary point of the free adsorbate, so a file that drops the hold resumes another relaxation.
A climbing-image band of five movable images with the improved tangent \cite{henkelmanClimbingImageNudged2000,henkelmanImprovedTangentEstimate2000} converges under fixed-step steepest descent on the projected force, which keeps no step history, so a difference after the restart comes from the file.

\subsection{The mask and the prefactor}\label{sec:prefactor} A barrier is one number, and the harmonic prefactor needs the free modes at the saddle.
In harmonic transition state theory the rate is \(k=\nu\exp(-\Delta E^\ddagger/k_{\mathrm{B}}T)\) with the Vineyard prefactor \cite{vineyardFrequencyFactorsIsotope1957}
\begin{equation}
\label{eq:vineyard}
\nu=\frac{\prod_{i=1}^{n}\nu_i^{\mathrm{min}}}{\prod_{i=1}^{n-1}\nu_i^{\ddagger}},
\end{equation}
where the products run over the \(n\) free modes of the minimum and the \(n-1\) real modes of the saddle.
A mask that frees one more component can move the saddle itself, besides adding a mode to each product.
We wrote the endpoints of the same slab through each route and read them back before relaxing them, converged a climbing-image band with the fast inertial relaxation engine (FIRE) \cite{bitzekStructuralRelaxationMade2006}, and took the Hessian of the highest image.
With the height held, the barrier is \(\eFiveBarrierHeld\,\mathrm{eV}\) on a path of \(\eFivePathHeld\,\text{\AA}\).
The highest image has \(\eFiveModesHeld\) free modes, one imaginary mode of \(\eFiveImagHeld\,\mathrm{meV}\) with \(\eFiveWeightHeld\) of its weight on the lateral motion of the adatom, and a prefactor of \(\num{\eFivePrefactorHeldNum}\,\mathrm{Hz}\).
CON 3.1, the ASE trajectory, FixScaled POSCAR and h5py H5MD all return that prefactor (Table~\ref{tab:prefactor-routes}).
With the height free, the problem a reader solves when the file has lost the hold, the band crosses a saddle at \(\eFiveBarrierFree\,\mathrm{eV}\) with \(\eFiveModesFree\) free modes and a prefactor of \(\num{\eFivePrefactorFreeNum}\,\mathrm{Hz}\), \sigfig{2}{\eFivePrefactorRatioFree} times the held value.

\subsection{The velocity unit} A \(\velFixtureAtoms\)-atom fixture stores velocities in the declared natural unit.
Its kinetic energy is \(\velFixtureKe\,\mathrm{eV}\) in that unit and \(\velFixtureKeFs\,\mathrm{eV}\) with the same numbers read as \(\text{\AA}/\mathrm{fs}\), the factor \(\velFactorSq\) of Eq.~\eqref{eq:tau}.
After one velocity Verlet step of 1~fs \cite{swopeComputerSimulationMethod1982}, the misread positions differ from the declared ones by \(\velVerletRmsd\,\text{\AA}\) root mean square and by at most \(\velVerletMax\,\text{\AA}\) (Section~\ref*{sec:supp-velocity}).
A \(\velSlabAtoms\)-atom slab drawn at \(\velSlabTemperature\,\mathrm{K}\) has a kinetic energy of \(\velSlabKe\,\mathrm{eV}\), and the misread gives \(\num{\velSlabKeFsNum}\,\mathrm{eV}\).

\FloatBarrier \section{Conclusions}\label{sec:conclusions} A resumed saddle search repeats the interrupted one only when its checkpoint returns the fixed components, the identifiers, the time unit and the binary64 coordinates as written.
CON 3.1 states these fields as a versioned grammar for the CON format, which many codes already write and read.
readcon-core is the reference implementation of that grammar, in Rust, with C, C++, Python, Julia and Fortran interfaces.
Every read path of the readcon-core Python module and C library returns the verdict of the corpus manifests on all \corpusFiles{} legal and illegal files.
On the held Pt(100) slab, a band resumed from CON 3.1 repeats the uninterrupted band bit for bit, and a reader that drops the hold sends the band to a saddle with a prefactor \sigfig{2}{\eFivePrefactorRatioFree} times larger.
The reads measured on this branch are in Section~\ref{sec:host}.
A format that defines no place for the mask cannot return that field.
Unlike a format whose meaning lives in the code of one reader, CON 3.1 lets any program test its reader against the corpus, add a section under a later minor without breaking older readers, and resume a search from the files of another code.
