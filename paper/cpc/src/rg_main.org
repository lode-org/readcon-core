\begin{frontmatter}

\title{readcon-core: a reader and writer for the CON checkpoint format}

\input{authors.tex}

\begin{abstract}
Rare-event methods store an atomic geometry many times while they search for a saddle or a path.
The eOn family writes that checkpoint as CON text.
A restart needs a per-axis constraint, the atom order from before type grouping, and a velocity time unit.
Specification 3.1 states that contract.
readcon-core 0.16.2 is a Rust reader and writer for CON versions 1, 2, and 3, with a C ABI and bindings for C++, Python, Julia, and Fortran.
This paper summarises the specification and records where the 0.16.2 code does not yet implement a clause.
The public HCN to HNC endpoints of an eOn nudged elastic band workflow are rewritten as CON 3.1.
readcon-core returns the mask, the id, and the velocity numbers from that file and stores the time-unit string.
The ASE eon reader does not keep the mask or the id.
Paired timings against ASE, a chemfiles XYZ read, MDAnalysis H5MD, and h5py are reported with bootstrap intervals.
\end{abstract}

\begin{keyword}
CON \sep checkpoint format \sep nudged elastic band \sep saddle search \sep units
\end{keyword}

\textit{Nature of problem:}
Saddle searches, adaptive kinetic Monte Carlo, and nudged elastic band calculations store a geometry after many potential calls.
The checkpoint has to carry the cell, the masses, a constraint on each Cartesian axis, the atom order from before the file groups atoms by type, and, when a trajectory is restarted, the velocities in a declared time unit.
eOn writes this state as CON text.
Independent readers do not agree on column 4.
The ASE eon reader treats a nonzero flag as a fully fixed atom and does not keep column 5.
A force section after the coordinates does not parse in that reader.
Files from specification 3.0, including those written by eOn 3.5 and later through this library, can carry natural-unit velocities under a time label of fs.
A reader that trusts the label fs scales the kinetic energy by the square of the time-unit factor.
A campaign that mixes eOn, ASE, and readcon-core needs one reading of the mask, the id, and the time unit.
\textit{Solution method:}
Specification 3.1 is the contract, and the normative text is \texttt{docs/orgmode/spec.org}.
Line 2 is one JSON object.
\texttt{con\_spec\_version} is the major version, written as a JSON number, and \texttt{con\_spec\_minor} is the minor.
Column 4 is an integer flag.
In spec 1 the value 1 means fixed on all three axes, and from spec 2 the value is a bitmask with bit 0 for x, bit 1 for y, and bit 2 for z.
Column 5 is an integer atom id from 0 through $2^{64}-1$, parsed as an integer.
From minor 1, a velocities section requires \texttt{units.time}, and the natural unit is written \texttt{(amu*angstrom\^{}2/eV)\^{}0.5}.
readcon-core is a Rust reader and writer for this text.
The shipped C header \texttt{include/readcon-core.h} is the language-neutral surface.
Python, Julia, and Fortran call that surface, and the Python extension can also call the Rust parser.
Text CON remains the file that other codes have to read.
gzip and zstd are compression envelopes around that text.

The crate on this tree is 0.16.2.
The C ABI is not described as a frozen 0.14 series.
\texttt{rkr\_frame\_builder\_build} returns a null pointer when the builder rejects the frame, and this tree has no \texttt{rkr\_last\_error}, so the reason does not reach C, Fortran, or Julia.
The default writer prints six digits after the decimal point.

The Python extension uses pyo3 0.28 with the extension-module feature and is not a free-threaded 3.13t or 3.14t build.
Cite the software through \texttt{CITATION.cff} and the concept DOI \texttt{10.5281/zenodo.18753567}.

* Introduction
:PROPERTIES:
:CUSTOM_ID: sec:introduction
:END:

Saddle searches, adaptive kinetic Monte Carlo, and the nudged elastic band build a path or a rate from many atomic geometries.
Each geometry is a checkpoint: the cell, the masses, which Cartesian axes are held fixed, the order the atoms had before they were grouped by chemical type, and sometimes the velocities.
CON is the checkpoint used by eOn in those workflows
\cite{goswamiNEBOrchestration2026,goswamiRMSDProjections2026,goswamiGaussianProcessSaddle2025,chillEONSoftwareLong2014}.
A surface atom that is fixed in one direction and free in the others cannot be described by a single boolean.
Type grouping reorders the atoms, so an image of a path cannot be compared with the next image unless the pre-grouping id is kept.
Velocities are useless for a restart if two readers apply different time units to the same numbers.
Historical CON readers treat column 4 as a boolean, drop column 5, and have no units object on a version 1 file
\cite{larsenAtomicSimulationEnvironment2017,chillEONSoftwareLong2014}.
Extended XYZ can name extra columns on a comment line, and it does not define this mask or this id
\cite{larsenAtomicSimulationEnvironment2017}.
H5MD can store positions, velocities, forces, and unit attributes, and it has no per-axis freeze mask
\cite{deBuylH5MDStructuredEfficient2014}.
A LAMMPS dump can store ids and forces, and it has no specification version for a three-bit mask
\cite{thompsonLammpsFlexibleSimulation2022}.
chemfiles reads many trajectory formats and does not read CON
\cite{frauxChemfiles2023}.
The OVITO 3.15.4 input list and the Atomsk formats table likewise have no CON reader
\cite{stukowskiOVITO2010,hirelAtomskToolManipulating2015}.
This paper states specification 3.1, compares that text with readcon-core 0.16.2, and runs one public path through the file.
The significance for a campaign is that the mask, the id, and the time unit then have one reading.

* The CON format v3.1
:PROPERTIES:
:CUSTOM_ID: sec:format
:END:

The normative text is =docs/orgmode/spec.org=, dated 2026-10-11, major 3 and minor 1.
This section is a summary.
Where this summary and the specification disagree, the specification wins.
A file is a concatenation of frames.
The extensions are =.con=, =.convel=, and the envelopes =.con.gz=, =.convel.gz=, =.con.zst=, and =.convel.zst=.
Figure \ref{fig:layout} shows one frame and the fields a spec 1 reader does not use.

Line 2 of a version 2 or 3 frame is one UTF-8 JSON object, with no byte-order mark.
=con_spec_version= is a JSON number, the major version.
A missing =con_spec_minor=, or an explicit 0, means minor 0.
Readers accept unknown minors of a known major and reject an unknown major.
JSON with major 0 or 1 is invalid (CON-line2.5).
Unknown line-2 keys are preserved on rewrite (CON-line2.8, D14, D15, D17).
Line 3 is the lengths of a, b, and c.
Line 4 is alpha, beta, and gamma in degrees, with alpha the angle between b and c, beta the angle between a and c, and gamma the angle between a and b.
The vector a lies along x and b lies in the xy plane (CON-cell.6, D12).
When =lattice_vectors= is present, a reader prefers those three row vectors, and a writer keeps lines 3 and 4 consistent with them at the precision it is using (CON-cell.1, CON-cell.2).
A missing =pbc= key means periodic in all three directions (CON-cell.3).
A type count of 0 is a legal zero-atom frame: lines 8 and 9 are empty, no coordinate or section block follows, and the legacy velocity fallback does not apply (CON-count.1, D4).
When the type count is at least 1, each per-type count is at least 1 (CON-count.3).
Column 4 is an unsigned integer token.
In spec 1, 0 is free and 1 is fixed on all three axes.
From spec 2, values 0 through 7 are a bitmask, bit 0 for x, bit 1 for y, and bit 2 for z, and a writer emits 7 for an atom fixed on all three axes (CON-mask.1 through CON-mask.7, D8).
A float spelling, a sign, or any other value is =InvalidFixedFlag= in every mode (CON-mask.5).
Column 5 is an integer id from 0 through $2^{64}-1$, parsed as an integer and not through binary64 (CON-id.1, D9).
No base is implied.
Writers emit ids that are unique within the frame.
Readers accept repeated ids and keep file order in that case.
When the ids are unique, ascending id is the pre-grouping order.
A line with four columns takes the 0-based position of the atom in the frame (CON-id.9).
A section is present exactly when its name is in =sections= (CON-section.1, D3).
Exactly one blank line precedes each section block, and the component blocks inside a section are not separated by a blank line (CON-section.2, CON-section.3, D5).
The per-atom energy section is named =energies= (CON-section.5, D6).
An unknown section name is an error when the frame minor is not newer than the reader.
A newer minor may skip an unknown section whose value-field count is given by =section_arity= (CON-section.7, CON-section.8, D14).
=bonds= is optional topology on major 3 and is not a section (CON-bonds.1, D7).
Version 3 requires =units.length= and =units.energy=.
Velocity is length divided by time.
Versions 1, 2, and 3.0 read velocities in the natural unit, and a =units.time= label on those versions is not trusted (CON-units.8, CON-units.9, D10).
From minor 1, =units.time= is authoritative, a velocities section requires it, and the natural unit is written exactly =(amu*angstrom^2/eV)^0.5= (CON-units.3, CON-units.5, CON-units.10).
A writer that is given an invalid unit fails with =InvalidUnits= and does not substitute a default (CON-units.13, CON-units.14, D11).
Readers reject NaN, Inf, and the spellings of those words in every numeric field and in every mode, as =NonFiniteValue= (CON-num.1, D1).
=validate= true adds checks and does not relax that rule (CON-validate.2, D1).
The C ABI uses a NaN return for some absent numeric getters.
That NaN is an API sentinel, it is documented in =docs/orgmode/implementation-notes.org=, and it is not written to a file (CON-num.4).
A conforming writer in its default mode writes each finite float so that it parses back to the same binary64 (CON-num.6, D13).
Fixed-decimal text is allowed only when the caller asks for it.
Trailing whitespace after the last complete frame is ignored.
Any other partial frame is =IncompleteHeader=, =IncompleteFrame=, or =IncompleteSection= (CON-frame.1 through CON-frame.6, D2).
A blank line followed only by whitespace to end of file is not a legacy velocity block (CON-frame.5).
gzip exposes every member of a multi-member file, and zstd exposes every frame (CON-compress.1, CON-compress.2, D16).
Labels are compared without regard to case after runs of spaces are collapsed (CON-file.5, D17).

* Implementation
:PROPERTIES:
:CUSTOM_ID: sec:implementation
:END:

The crate on this tree is readcon-core 0.16.2.
The Rust types =ConFrame= and =ConFrameBuilder= own the frame.
The hot path is the hand-written parser in =src/parser.rs=.
The optional Pest grammar in =grammar/readcon.pest= is not used on that path.
That grammar accepts a signed integer in column 4.
The lax parser reads column 4 and column 5 as binary64 and then casts them (=src/parser.rs:668-676=).
With =validate= true, column 4 is parsed as an integer and values above 7 become =ValidationError=, which is not the =InvalidFixedFlag= result the specification names for every mode.
The error enum in =src/error.rs= has no =NonFiniteValue=, =InvalidFixedFlag=, =InvalidCount=, or =InvalidUnits= variant.
=src/ffi.rs= generates the shipped header =include/readcon-core.h=.
C++ uses that header.
Python, Julia, and Fortran call the C ABI, and the Python extension can also call the Rust parser.
=rkr_frame_builder_build= returns a null pointer when =ConFrameBuilder::build= returns an error, and it discards the error (=src/ffi.rs:3371-3373=).
This tree does not define =rkr_last_error=.
Fortran and Julia therefore cannot read a builder failure.
Several numeric getters return an IEEE NaN when the value is absent.
That sentinel is the C API described in =docs/orgmode/implementation-notes.org=.
The writer default is six digits after the decimal point (=src/writer.rs= =DEFAULT_FLOAT_PRECISION=).
=FloatFormat::RoundTrip= is available when the caller selects it, and =Default= for =FloatFormat= is the six-digit mode.
For a major-3 frame whose units are missing or fail validation, the writer inserts =units= with =time= set to =fs= (=src/writer.rs:269-277= and =src/units.rs:439-445=).
The specification forbids that substitution (CON-units.14).
=src/units.rs= parses the natural spelling =(amu*angstrom^2/eV)^0.5= as a time.
=canonicalize_unit_expression= rewrites that spelling with spaces, so a rewrite does not keep the pinned characters (CON-units.5).
The gzip path uses =GzDecoder=, which stops after the first member (=src/compression.rs:82-88=).
zstd is an optional Cargo feature and is not part of a default build.
=read_all_frames= parses sequentially unless the crate is built with =parallel= and the buffer is at least 48 KiB.
=read_all_frames_with_threads= takes =Some(1)= for one thread and =Some(n)= for a pool of =n= workers when =n= is at least 2.
The frame boundaries are computed before that pool runs, so the partition depends on the input and not on the worker count.
The Python package enables =parallel=.
Its pyo3 dependency is version 0.28 with the feature =extension-module=.
The manifest does not select a free-threaded build, and this paper does not claim a 3.13t or 3.14t wheel.
=to_ase= builds the cell from lines 3 and 4 and passes =pbc= true (=src/python.rs:1498-1516=).
It does not read =lattice_vectors=, and it does not read a =pbc= array from the metadata.
readcon-db is a separate LMDB index of energy, formula, and section presence over the same CON text.
It is not a second program in this paper.
A Cap'n Proto schema in the repository is an in-process RPC encoding.
It is not the on-disk CON file.

* Application
:PROPERTIES:
:CUSTOM_ID: sec:application
:END:

The public campaign is the HCN to HNC isomerization used to test an eOn nudged elastic band workflow
\cite{goswamiNEBOrchestration2026}.
The endpoint files are =examples/hcn_isom/hcn.con= and =examples/hcn_isom/hnc.con= at commit =669a58ef= of =eon_orchestrator=
\cite{goswamiEonOrchestrator2026}.
Copies are =paper/cpc/data/hcn.con= and =paper/cpc/data/hnc.con=.
Those files are spec 1 text written by ASE: column 4 is 0, the ids are 0, 1, and 2, and there is no velocity block.
=paper/cpc/scripts/hcn_case.py= rewrites them as specification 3.1 with =units.time= set to the natural spelling and a velocities section.
A third frame keeps the HCN coordinates, sets column 4 of H to 1, and stores the ids 2, 0, and 1 in file order.
Under spec 2 and later, column 4 equal to 1 is fixed on x only (CON-mask.4).
The published endpoints themselves use column 4 equal to 0.
The third frame is a reader probe on those coordinates, not a claim that the published path fixed an axis.
Table \ref{tab:loss} is the result.
readcon-core 0.16.2 returns the masks, the ids, and the velocity numbers, and it keeps the time string on the metadata.
It does not convert the velocities into femtoseconds.
ASE =format="eon"= fails on the file that contains the velocities section.
On the coordinates-only probe it returns an all-fixed constraint on H and does not return column 5.
No eOn binary was run in this archive.
eOn 3.6.0 reads masks through =getFixedMask= (=client/ConFileIO.cpp:386=) and writes velocities at six decimals in the natural unit.
eOn 2.17.10 collapses any fixed bit to 1 (=client/ConFileIO.cpp:384-385=).
