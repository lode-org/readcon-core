\begin{abstract}
Rare events in solids and molecules are too slow for a direct trajectory, so a rate calculation searches for saddle points and for the path that joins two minima.
The search calls a force evaluator many times, passes geometries between codes, and restarts from a checkpoint.
That checkpoint has to carry the cell, a constraint on each Cartesian axis, an atom identity that survives grouping by element, and velocities in a declared time unit.
Here we present readcon-core, a Rust reader and writer for the CON checkpoint, with a C interface and bindings for C++, Python, Julia and Fortran.
On a band of ten thousand frames the library is about \spBandAse{} times faster than the ASE reader of the same text.
The checks are a conformance corpus, round trips of producer files, and the public HCN to HNC path of a nudged elastic band.
The program is released under the MIT licence.
\end{abstract}

\begin{keyword}
CON \sep checkpoint \sep nudged elastic band \sep saddle search \sep rare events
\end{keyword}

\textit{Nature of problem:}
Harmonic transition state theory estimates a rare-event rate from the barrier and the curvatures at a minimum and at a first-order saddle \cite{vineyardFrequencyFactorsIsotope1957,hanggiReactionrateTheoryFifty1990}.
Finding those points, and the path that connects two minima, is the work of the nudged elastic band, its climbing-image form, the dimer method, and adaptive kinetic Monte Carlo \cite{jonssonNudgedElasticBand1998,henkelmanClimbingImageNudged2000,henkelmanDimerMethodFinding1999,henkelmanLongTimeScale2001}.
A campaign of that kind calls a force code thousands of times, writes a geometry after many of those calls, and starts again from the last good frame.
The frame has to remember which Cartesian axes are held fixed, because a slab or a surface is rarely frozen in every direction.
It has to remember which atom is which after the file groups atoms by chemical type, because images of a path are compared atom by atom.
When the restart continues a trajectory, the velocities have to be in a known time unit, because the kinetic energy scales with the square of that unit.
CON is the text checkpoint used for this state.
\textit{Solution method:}
readcon-core is one parser and one writer for CON text.
A frame is a short header, coordinates with a constraint flag and an atom id, and optional sections for velocities, forces and other per-atom fields.
Line 2 of a current file is a single JSON object that records the major version, the minor version, the unit system and the section names.
From the minor version that makes the time label authoritative, a velocities section is written only with an explicit time unit, and the natural unit shared with existing producers is \texttt{(amu*angstrom\^{}2/eV)\^{}0.5}.
Decimal numbers are read with correct rounding and, unless the caller asks for a fixed number of digits, written so that they parse back to the same binary64 value.
A C header is the narrow waist: C++, Python, Julia and Fortran call that waist, so each language sees one parse.
Parallel ingest splits the file on frame boundaries that depend only on the text, and the frames come back in file order at every thread count.
gzip and, when the optional feature is built, zstd are compression envelopes around the same text.
\textit{Additional comments including restrictions and unusual features:}
The C interface reports a failed build or a failed read through a status code and does not keep an error string for a later call.
The Python extension is not a free-threaded build.
zstd input is accepted only when the library is built with that feature.
A pool of threads is used automatically only for files above 48 KiB, and a file that holds a single frame is parsed as one task even if that frame is large.
The same fixtures are exercised from the Rust core and from the C, Python, Julia and Fortran bindings.

* Introduction
:PROPERTIES:
:CUSTOM_ID: sec:introduction
:END:

Thermally activated events set the rates of diffusion, reactions and structural change, and they are rare on the clock of a direct molecular dynamics run.
Harmonic transition state theory estimates such a rate from the barrier height and from the curvatures at the minimum and at a first-order saddle \cite{eyringActivatedComplexChemical1935,vineyardFrequencyFactorsIsotope1957,hanggiReactionrateTheoryFifty1990}.
The practical task is to find those stationary points and the path that joins two known minima \cite{walesExploringEnergyLandscapes2018}.
The searches that do that work fall into a double-ended family and a single-ended family.
A double-ended search, the nudged elastic band and its climbing-image form, discretizes the path into a chain of images and relaxes that chain until the highest image sits near the saddle \cite{jonssonNudgedElasticBand1998,henkelmanClimbingImageNudged2000,sheppardOptimizationMethodsFinding2008}.
The relaxation of the chain is commonly a limited-memory quasi-Newton step, which stores a short gradient history rather than a full Hessian \cite{nocedalUpdatingQuasinewtonMatrices1980}.
A single-ended search, the dimer method, rotates a pair of replicas until the lowest curvature points uphill and then walks toward the saddle from one basin \cite{henkelmanDimerMethodFinding1999}.
Adaptive kinetic Monte Carlo accepts an escape, advances a physical clock by the waiting time of that escape, and repeats the search from the new minimum \cite{voterIntroductionKineticMonte2007,henkelmanLongTimeScale2001,goswamiEfficientExplorationChemical2025}.
Energy-weighted springs, together with eigenvector following, keep a molecular band from cutting the corner of a sharply curved path \cite{asgeirssonNudgedElasticBand2021}.
An improved estimate of the tangent keeps the elastic band from forming kinks at places where the path bends sharply \cite{henkelmanImprovedTangentEstimate2000}.
The image-dependent pair potential starts the chain of images closer to the minimum energy path the band will converge to \cite{smidstrupImprovedInitialGuess2014}.
The string method was introduced for the sampling of rare events as a curve that is evolved between two known states \cite{eStringMethodStudy2002}.
A later form of that method finds a minimum energy path by evolving the curve rather than by relaxing a chain of springs \cite{eSimplifiedImprovedString2007}.
A growing string builds that curve from the reactant outward, instead of laying down a complete chain between two known ends \cite{petersGrowingStringMethod2004}.
A comparison of those single-ended searches showed that a saddle can still be found when the product state is unknown \cite{olsenComparisonMethodsFinding2004}.
A later dimer method converges faster than the original rotation because it uses a better estimate of the curvature \cite{kastnerSuperlinearlyConvergingDimer2008}.
An improved dimer and a partitioned rational-function step have been compared as two ways to reach that same saddle \cite{heydenEfficientMethodsFinding2005}.

These campaigns spend most of their effort on force calls, and they spend the rest on moving the current geometry from one program to another and on starting again after a stop.
A reproducible band optimization calls a potential for every image at every iteration, and the checkpoint is what lets that run resume \cite{goswamiReproducibleOrchestrationBest2026}.
A model fitted to earlier force calls can propose the next saddle step and so spare some evaluations of the potential \cite{petersonAccelerationSaddlepointSearches2016}.
A tutorial review of Gaussian-process searches shows how a surrogate can cut the number of force evaluations on a stationary-point problem \cite{goswamiTutorialReviewBayesian2026}.
The same idea has been implemented for molecular saddle searches, where the surrogate still has to land on a force evaluator \cite{goswamiEfficientImplementationGaussian2025}.
Adaptive pruning then drops training points that no longer change the next step, which keeps a long search from storing every geometry \cite{goswamiAdaptivePruningIncreased2026}.
An earlier Gaussian-process band uses inverse interatomic distances so that a nudged elastic band needs fewer calls to the potential \cite{koistinenNudgedElasticBand2019}.
A Gaussian-process minimum-mode search uses the same kind of covariance to rotate a dimer toward a saddle from one basin \cite{koistinenMinimumModeSaddle2020}.
Eigenmode alignment of the climbing image keeps the highest bead on the softest mode of the Hessian while the band relaxes \cite{goswamiEnhancedClimbingImage2026}.
The same files are read again when a path is projected onto two dimensions and compared with the band that produced it \cite{goswamiTwodimensionalRmsdProjections2026}.
A long kinetic Monte Carlo run writes a checkpoint whenever it accepts a move, and that file has to be readable after the job has stopped \cite{henkelmanLongTimeScale2001}.
Distributed adaptive kinetic Monte Carlo farms the saddle searches across ranks, so each rank has to read the checkpoint the search will continue from \cite{pedersenDistributedImplementationAdaptive2010}.
Between those reads the file may sit on disk for hours while a queue waits, or it may be copied onto another machine that has a different build of the force code.
Long-timescale atomistic methods extend a simulation until a rare event is visible on a laboratory clock, which is the setting in which this checkpoint is reread \cite{voterHyperdynamicsAcceleratedMolecular1997,voterExtendingTimeScale2002}.
The older eOn paper is the reference for the code in which this checkpoint became the working file, and a restart is only as faithful as the frame that code wrote \cite{chillEonSoftwareLong2014}.

The checkpoint has to carry a per-axis mask, an atom id, and a time unit for any velocities.
The mask has one bit for x, one for y and one for z, so a buried atom carries 7, a free surface atom carries 0, and an adsorbate whose height is held carries 4.
The id has to survive grouping by chemical type, so that image \(i\) of a band still names the same atom as image \(i+1\) when the frames are compared \cite{gundeIraShapeMatching2021}.
A velocity is stored with its time unit, because the kinetic energy scales with the square of that unit.
A velocity Verlet step and a velocity-rescaling thermostat both advance those components, so the clock has to travel with them \cite{swopeComputerSimulationMethod1982,bussiCanonicalSamplingThrough2007}.
The natural unit used by eOn and by ASE is \(({\rm amu}\cdot{\rm angstrom}^{2}/{\rm eV})^{0.5}\), which equals \(\timeFac\,\text{fs}\), and \(1\,\text{fs} = 10^{-15}\,\text{s}\).
The conversion of that natural unit into femtoseconds uses the constants that define the electronvolt and the atomic mass unit \cite{tiesingaCodataRecommendedValues2021}.

CON is the text form of that checkpoint, written so that a failed search can be inspected without a decoder.
It grew up inside eOn \cite{chillEonSoftwareLong2014}.
The current code writes one frame per minimum, saddle or band image and reads it back on the next cycle \cite{goswamiEon2026}.
The Atomic Simulation Environment began as a scripting interface to an electronic-structure code \cite{bahnObjectorientedScriptingInterface2002}.
It reads and writes the same text, which is how a geometry moves from the saddle search into a Python workflow \cite{larsenAtomicSimulationEnvironmenta2017}.
A band file is therefore a sequence of frames that several programs already agree to exchange.

Neighbouring formats store a trajectory or a structure, and the fields that differ from this checkpoint are the integer mask, the id that survives grouping inside the frame, and the versioned time label.
H5MD stores positions and optional velocities in HDF5, defines an id element for each particle, and can attach a time unit as a dataset attribute \cite{buylH5mdStructuredEfficient2014,folkOverviewHdf5Technology2011}.
That id and that attribute cover identity and the clock for a molecular trajectory, while the integer mask and the versioned time label stay with this checkpoint.
NetCDF is an array container, so any checkpoint convention built on it has to be agreed by the programs that share the file \cite{rewNetcdfInterfaceScientific1990}.
The TNG format stores coordinates, velocities, forces and a box, and it takes atom identity from the molecular topology \cite{lundborgEfficientExtensibleFormat2014}.
ASE's extended XYZ writer stores a per-axis move_mask, one boolean for each Cartesian axis, which records a constraint in a different encoding from the integer mask in this file \cite{larsenAtomicSimulationEnvironmenta2017}.
A LAMMPS dump can carry an atom id and, when the dump style asks for them, velocities and forces, while the unit style of the run stays outside the frame \cite{thompsonLammpsFlexibleSimulation2022}.
The LAMMPS data file holds the starting geometry and the dump holds the trajectory, so neither file is the band of images this checkpoint exchanges \cite{thompsonLammpsFlexibleSimulation2022}.
Zarr is a chunked array store, and its community standard defines how those chunks are laid out on disk \cite{opengeospatialconsortiumZarrStorageSpecification2022}.
CHARMM writes a DCD trajectory of coordinates and of the box, which is the record of a finished dynamics run \cite{brooksCharmmBiomolecularSimulation2009}.
GROMACS writes XTC and TRR trajectories, so a reader of those files gets positions and sometimes velocities from a molecular run \cite{abrahamGromacsHighPerformance2015}.
MDTraj reads DCD and XTC when the task is analysis of a finished trajectory \cite{mcgibbonMdtrajModernOpen2015}.
d-SEAMS rereads a saved trajectory to identify the structure that formed in the frames a simulation stored \cite{goswamiDseamsDeferredStructural2020}.
A protein structure is often stored as a PDB file, and atom identity there comes from the residue and the atom name \cite{bermanProteinDataBank2000}.
mmCIF is the macromolecular archive form of that structure, with the same residue and atom-name identity \cite{westbrookStarmmcifOntologyMacromolecular2000}.
A small-molecule crystal structure travels as a CIF, which archives the published cell and the published coordinates \cite{hallCrystallographicInformationFile1991}.
A plane-wave calculation reads a POSCAR geometry, the cell and the coordinates that VASP will relax \cite{kresseEfficientIterativeSchemes1996,kresseEfficiencyAbinitioTotal1996}.
pymatgen converts among the crystal files used in solid-state work, including POSCAR and CIF, and the result is still one geometry \cite{ongPythonMaterialsGenomics2013}.
Atomsk converts among the files used for defects and for classical potentials, which is how a geometry changes dialect before a run \cite{hirelAtomskToolManipulating2015}.
Open Babel converts among the chemical formats used for molecules, and those formats name bonds and residues \cite{oboyleOpenBabelOpen2011}.
OVITO displays atomistic snapshots and can read several of these files when the task is to look at a geometry \cite{stukowskiVisualizationAnalysisAtomistic2010}.
i-PI drives a calculation by passing coordinates to a client and reading forces back, one geometry at a time \cite{kapilIpi20Universal2019,litmanIpi30Flexible2024}.
That coordinate exchange began with i-PI as the server, which sent positions to a force code and received forces back \cite{ceriottiIpiPythonInterface2014}.
A liquid or a mixture is often packed into a cell before the first minimization, and that packed geometry is what the checkpoint then stores \cite{martinezPackmolPackageBuilding2009}.
Machine-learning potentials exchange atomic features as tensors, including a universal potential written on that interface, and a tensor of features is a different object from the geometry a search writes \cite{bigiMetatensorMetatomicFoundational2026,mazitovPetmadLightweightUniversal2025}.
A repository API and a materials archive keep a geometry findable after it leaves this file, which is what the data principles ask \cite{andersenOptimadeApiExchanging2021,draxlNomadLaboratoryData2019,wilkinsonFairGuidingPrinciples2016}.
Table \ref{tab:compat} puts the checkpoint next to those files, after the layout of one frame has been described.

readcon-core is a reader and writer for the CON checkpoint used by saddle searches.
The library is a Rust parser and writer, exposed through one C header so that C++, Python, Julia and Fortran share one reading of the file.
The parts a restart depends on are the versioned time label, the round-trip default for floating-point text, and the preservation of unknown metadata keys.
The parallel read finds frame boundaries from the text alone, so the frames come back in file order at every worker count, as Figure \ref{fig:pipeline} shows.
The same program also opens the older files that eOn and ASE have been writing, including velocities stored in the natural unit.
Section \ref{sec:format} describes the file, Section \ref{sec:implementation} describes the parser, and Section \ref{sec:validation} reports the corpus, the round trip, the slab and the HCN path.
Section \ref{sec:performance} reports one-thread Python timings against one-thread peers, and it reports thread scaling from a separate run.
Section \ref{sec:scope} states what the release covers, and Section \ref{sec:conclusions} collects the result of those checks.

* The CON format
:PROPERTIES:
:CUSTOM_ID: sec:format
:END:

A CON file is a sequence of frames in plain text, so that a failed search can be inspected without a decoder, and Figure \ref{fig:layout} shows how one frame is laid out.
The first nine lines are the header: a generator note, a metadata line, three cell lengths, three cell angles, and two further text lines.
The last three of those nine lines are the number of chemical types, the count of atoms of each type, and the mass of each type.
Coordinates follow, grouped by chemical symbol, and each group is a symbol, a line that names the component, and one row per atom.
A coordinate row holds \(x\), \(y\), \(z\) and the mask, and it holds the id when the line carries a fifth token.
A line of four tokens is legal, and the id is then the zero-based index of that row in the frame.
Any other number of tokens makes the row illegal.
Optional sections repeat that grouping after a blank line, velocities first when a velocity block is present.
Lengths in these files are in angstrom, \(1\,\text{\AA} = 10^{-10}\,\text{m}\), and energies are in electronvolts.

The cell is three lengths and three angles in degrees, which is enough to rebuild the box once the angle convention is fixed.
The angle on line 4 between \(b\) and \(c\) is \(\alpha\), the angle between \(a\) and \(c\) is \(\beta\), and the angle between \(a\) and \(b\) is \(\gamma\).
The convention puts \(a\) along \(x\) and \(b\) in the \(xy\) plane, which is how both eOn and ASE turn those six numbers back into vectors \cite{chillEonSoftwareLong2014,larsenAtomicSimulationEnvironmenta2017}.
When the metadata also carries lattice vectors, those vectors are three rows of the cell matrix and they take priority on read, and the writer keeps lines 3 and 4 consistent with them.
A missing periodicity flag means the cell is periodic in all three directions, which is the usual case for a bulk crystal and for a slab that is periodic in the plane.
Column 4 is the mask from the introduction, stored as an integer token, and column 5 is the id.
Version 1 stores 0 or 1 in the mask column, and from version 2 the column is the three-bit integer.
The reader rules for a flag outside that range, for a missing id, and for a repeated id are in \ref{sec:appendix-rules}.
The id is read as an integer up to \(2^{64}-1\), so a large identity is not rounded through a floating-point conversion.
When the ids inside a frame are unique, sorting them recovers the order the atoms had before the file grouped them by chemical type.
That order is what a distance or a projection expects when it compares one image of a band with the next.

Line 2 of a current file is one line of JSON, without a byte-order mark, and it records the major version, the minor version, the units and the section names \cite{brayJavascriptObjectNotation2017}.
A reader accepts an unknown minor of a major it knows, and it refuses an unknown major, so a later clarification can travel in a file that an older program of the same major still opens.
Unknown keys on that line are kept when the frame is written again, so a campaign can attach an energy, a bead index or a potential name without waiting for every reader to learn the key.
The time unit on the metadata line is the label already stated in the introduction, and the writer copies that spelling.
From the minor version that records time, the label is authoritative, and a writer that emits velocities must emit the time unit with them.
On older files the velocities, when a velocity block is present, are in the natural unit, because that is the unit those producers wrote.
A writer that is given a time unit it cannot parse fails at the moment the frame is built, and the library keeps the natural-unit spelling so that a later textual comparison still matches.
Length and energy are required once the file is major version 3, and mass is optional on that object.

Sections are named blocks that follow the coordinates, and each block repeats the grouping by chemical symbol.
A velocities section, a forces section and an energies section follow the coordinates, and so do blocks for charges, spins, magnetic moments, displacements and spreads.
Each of those blocks repeats the coordinate pattern: a symbol, a heading, and one row per atom.
Exactly one blank line stands before each section, and no blank line stands between the component blocks inside a section, which is how a new name is recognized as a new section.
The metadata lists the names that are present, so a reader knows what to expect before the first row of a section, and a listed name that never arrives is an incomplete frame.
A count of zero chemical types is a legal empty frame, with no coordinate block and an empty section list.
A header that stops early, or a section with fewer rows than the header declared, is rejected, and the partial frame is not returned.
The remaining reader rules, including unknown section names, non-finite numbers and a gzip archive with several members, are the rows of \ref{sec:appendix-rules}.

Readers convert every decimal field to binary64 with correct rounding, which is the numeric contract a second parse relies on \cite{ieeecomputersocietyIeeeStandardFloatingpoint2019,goldbergWhatEveryComputer1991,clingerHowReadFloating1990,clingerHowReadFloating2004}.
The default writer prints each finite value with Rust's shortest formatter, in exponential form, so that reading the text back yields the same binary64 number.
That formatter tries Grisu, an integer conversion that checks its own digits, and falls back to Dragon when the check fails \cite{loitschPrintingFloatingpointNumbers2010,burgerPrintingFloatingpointNumbers1996,steeleHowPrintFloatingpoint1990,steeleHowPrintFloatingpoint2004}.
A caller may ask for a fixed number of digits after the decimal point, and that mode is lossy: values that differed in the last bits can collide, and values that needed more digits no longer parse back to themselves.
gzip and zstd are envelopes around the same bytes, and the bytes that come out of either envelope are parsed by the same reader as an uncompressed file \cite{deutschGzipFileFormat1996,colletZstandardCompressionApplicationzstd2021}.

* Implementation
:PROPERTIES:
:CUSTOM_ID: sec:implementation
:END:

The core is a Rust library with a single parser, and file reads, string reads and the bindings all go through that parser, so a change in the grammar shows up once.
The parser walks the header, checks the counts, reads each coordinate row as an integer flag and an integer id, and then reads the sections named in the metadata.
Decimal fields in that parser go through a fast correctly rounded conversion \cite{lemireNumberParsingGigabyte2021}.
Keeping one parser is what makes the conformance story possible, because a second implementation in each language would be a second place for a mask or a time label to drift.
The C header owns the frame on the far side of the call and returns a status code, and the caller frees what it was given.
C++ is a header over that interface, and Julia and Fortran call the same symbols, with the Fortran side using the standard C binding \cite{bezansonJuliaFreshApproach2017}.
Python uses the same parse, so a file that is legal in one binding is legal in the others, and a file that is rejected is rejected for the same reason.
That binding can return coordinates and velocities as arrays, so the caller is not handed one object per atom \cite{harrisArrayProgrammingNumpy2020}.
The status code is the whole of the error report on the C side, and Section \ref{sec:scope} states that boundary as part of the release.
Every language maps one integer, and none of them invents a second message for the same failure.

A caller builds a frame from a cell, symbols, coordinates, the mask, the id, and any velocities or forces.
On a current frame the builder writes the minor number when the caller did not set one, and it writes a units object when the caller did not supply one.
Velocities are written only with the time unit the caller set, which is the rule that keeps a restarted kinetic energy on the clock that was stored.
If the frame has velocities and the minor version requires a time unit, the build fails unless that unit was set.
When the Python binding rewrites a version 1 or version 2 frame that already contains velocities and has no time unit, it records the natural unit on the metadata line.
The default text of every floating-point field is the round-trip form, and fixed digits remain a separate request for a caller who wants a shorter file and accepts the loss.

Figure \ref{fig:pipeline} is the parallel read of a band, which is already a list of frames rather than one array of atoms.
A serial scan finds the byte offset where each frame starts, using the header counts, and that scan does not build the atoms.
The pool then parses each recorded slice on its own worker, and the frames are assembled in the order the scan found them.
The offsets depend only on the bytes of the file, so the split is the same however many workers are waiting.
Below 48 KiB the read stays on the serial parser, because the cost of starting the pool is larger than the parse.
A file with one frame is one task, however many atoms that frame contains, because the split is on frames and not on atoms.
The Python call can pin the worker count: one worker forces the serial path, and two or more pin a pool of that size.
The result is the same sequence of frames at every count, which Section \ref{sec:performance} checks by hashing coordinates, the mask, the id and the velocities when a velocity section is present.
The Python call releases the interpreter lock while the file is parsed, and it takes the lock back to build the objects the caller sees, so other Python work can run during a long parse.

The Python surface can also build a frame from an ASE atoms object, copying the geometry into the frame type the parser returns.
That copy takes positions, the cell, masses, a fully fixed atom where ASE stored that constraint, a per-axis mask where ASE stored one, and velocities when ASE has them.
The numbers are copied as ASE holds them, so a caller who has velocities in a known unit sets that unit on the builder, and the components stay in the unit the caller already chose.
The reverse direction writes that frame back out as the CON text the ASE eon reader expects.
chemfiles is an optional ingress for formats other than CON, and a build that includes it can open an XYZ file into the same frame type \cite{frauxChemfiles2023}.
The CON text remains the checkpoint that eOn and ASE exchange, and the other formats are a way in.

A campaign touches the same frame more than once, which is why these checks run at each touch.
The builder records the cell, the mask and the id before the first force call, and the writer emits the text a queue will store.
A later rank reads that text, compares the ids, and calls the potential on the free axes only.
If that rank writes the frame again, unknown keys such as a bead index or a stored energy are still on the metadata line.
The round-trip printer is what keeps the coordinates on that second write, because a short fixed-digit print would move atoms by a last-bit rounding on every restart.

* Validation
:PROPERTIES:
:CUSTOM_ID: sec:validation
:END:

The conformance corpus has \nValid{} legal files and \nInvalid{} files that must be rejected.
The legal files cover the header, both meanings of the mask column, an empty frame and the units line.
The rejected files omit the version, omit or swap the version 3 units, or store 8 in the mask.
The rest name an unknown major, name an unknown section, set validation without a section list, or give one chemical type a count of zero.
The same files are read from the Rust core and from \nBind{} bindings, C, C++, Python, Julia and Fortran, so a binding cannot quietly accept a file the core rejects.
A legal file that one binding dropped, or an illegal file that one binding accepted, would show up as a different status on that binding.
Table \ref{tab:compat} places this checkpoint next to the ASE eon reader, extended XYZ, H5MD and a LAMMPS dump.
What differs, once the extended XYZ move_mask and the H5MD id element are taken into account, is the integer mask in this file, the id that survives grouping inside the frame, and the versioned time label \cite{larsenAtomicSimulationEnvironmenta2017,buylH5mdStructuredEfficient2014}.
The ASE eon reader follows the original eOn layout: a comment on the second line, a single fixed flag, and no velocity section.

A \nRound{}-atom copper-hydrogen frame from the eOn tests is read, written with the default printer, and read again, and every coordinate bit matches the value that was stored.
The same coordinates match the ASE eon reading of that file, bit for bit, so the two programs agree on the positions of a producer file.
The single-frame geometry used below and in Section \ref{sec:performance} is a platinum (111) slab of \nSlab{} atoms, built with ASE rather than by repeating one coordinate row.
Exchange on Pt(001) is one surface event a per-axis mask is meant to record \cite{kelloggSurfaceSelfdiffusionPt0011990}.
The cell is an orthogonal fcc111 slab of 50 by 20 by 10 layers, with 8 angstrom of vacuum, plus one hydrogen placed 1.5 angstrom above an on-top site.
The bottom two layers are fixed on every axis, the other platinum atoms are free, and the adsorbate is fixed on z, which is the mask case a surface calculation actually writes.

** A time unit and a kinetic energy
:PROPERTIES:
:CUSTOM_ID: sec:velocity
:END:

The velocities on that slab are a Maxwell-Boltzmann sample at 300 K, drawn with ASE on a NumPy Generator and seed 20261011, and the kinetic energy is computed from those components \cite{harrisArrayProgrammingNumpy2020}.
The energy is one half the sum of mass times speed squared, with the speeds in the natural unit, and on this frame it is \(\keNat\,\text{eV}\).
Reading those same numbers as though they were angstrom per femtosecond multiplies the energy by \(\timeFacSq\), the square of that factor, and gives \(\keFs\,\text{eV}\).
From the minor version that stores the time unit, the label selects the clock, and on older files the reader uses the natural unit those producers wrote.

** HCN to HNC
:PROPERTIES:
:CUSTOM_ID: sec:hcn
:END:

The public HCN and HNC endpoints of an eOn nudged elastic band are the hydrogen cyanide isomerization used to illustrate a reproducible path optimization \cite{mourikAbInitioGlobal2001,goswamiReproducibleOrchestrationBest2026}.
Those endpoints are rewritten here as current CON, with the natural time unit declared and a velocities section added.
A third frame keeps the HCN coordinates, fixes hydrogen on x only, and stores the ids 2, 0 and 1 in file order.
The file still groups the atoms as carbon, then nitrogen, then hydrogen, so the third row is hydrogen even though its id is 1 and the carbon in the first row carries id 2.
Ascending id is the order those atoms had before the file grouped them by element, and a caller who zips the rows as they appear pairs the wrong atoms.
Table \ref{tab:hcn} lists each atom of the HCN and HNC endpoints, of the probe, and of the generated slab.
readcon-core returns the mask, the id and the velocities that were written, including the permutation 2, 0, 1 on the probe.
On the coordinate form of the probe, which has no velocity section, the ASE eon reader reports the x-only hydrogen as fixed on every axis, which is the single flag of the original layout.

* Performance
:PROPERTIES:
:CUSTOM_ID: sec:performance
:END:

We compare the Python binding of readcon-core, at one worker, with four Python readers, each also at one thread, on one \cpuName{} with \nCores{} hardware threads.
The peers are the ASE eon reader on the same CON text, a chemfiles read of an XYZ file with the same coordinates, an MDAnalysis read of an H5MD file with those coordinates, and an h5py read of that file's position array \cite{larsenAtomicSimulationEnvironmenta2017,frauxChemfiles2023,michaudagrawalMdanalysisToolkitAnalysis2011,gowersMdanalysisPythonPackage2016,jakupovicMpiparallelMolecularDynamics2021}.
OpenMP, BLAS and the related math libraries are held at one thread for the whole run, and that limit is set before any of those libraries is imported.
The payloads are 1, 100 and @@latex:10\,000@@ frames of a 218-atom copper-hydrogen geometry, and the platinum slab of Section \ref{sec:validation}.
Each cell is 30 paired repeats, interleaved so that a slow drift hits both sides of the pair, and the ratio is the readcon-core time divided by the peer time \cite{kaliberaRigorousBenchmarkingReasonable2013,mytkowiczProducingWrongData2009}.
We report the median and a bias-corrected and accelerated 95 percent interval, and we apply a Holm adjustment across the cells that produced a ratio \cite{efronBetterBootstrapConfidence1987,holmStepdown1979}.
The full protocol, including the bootstrap seed and the Holm adjustment, is in \ref{sec:appendix-bench}, and Figure \ref{fig:ratios} shows the intervals.

Against the ASE eon reader the speedup, the reciprocal of the ratio, runs from \aseLo{} to \aseHi{} on the files both programs finish.

On the band of @@latex:10\,000@@ frames, readcon-core is \spBandAse{} times faster than ASE and \spBandMda{} times faster than MDAnalysis.
On that same band the readcon-core time is \ratBandChem{} times the chemfiles time.
h5py is faster on that band: the readcon-core time is \ratBandHpy{} times the h5py time, which is the direction expected when the peer reads one dense array and readcon-core parses text.
On a single small frame the comparison with h5py goes the other way, and readcon-core is \spOneHpy{} times faster, because the cost of opening the container dominates a tiny array.
On the platinum slab, which is one frame and therefore one task, readcon-core is \spSlabAse{} times faster than ASE, and the h5py ratio on that same frame is \ratSlabHpy.

* Scope
:PROPERTIES:
:CUSTOM_ID: sec:scope
:END:

The release reads and writes CON text, through one parser and one C header, with bindings for C++, Python, Julia and Fortran.
The C call reports success or failure as a status code, and the caller maps that integer in whichever language sits above the header.
The Python extension follows ordinary interpreter locking, and the parse itself runs without holding that lock, so other Python work can proceed during a long read.
zstd envelopes are part of a build that includes that feature, and the same text comes out of a gzip envelope on every build.
Parallel work is the set of frames, so one large frame stays one task, which is the slab timing above.
Fixed-digit printing is available for a caller who wants a shorter file, and a geometry that must come back unchanged stays on the default writer.

* Conclusions
:PROPERTIES:
:CUSTOM_ID: sec:conclusions
:END:

readcon-core is a reader and writer for the CON checkpoint used by eOn and ASE, with one parser behind a C header and bindings for C++, Python, Julia and Fortran.
The versioned time label keeps a restarted kinetic energy equal to the stored one, which on the generated platinum slab is the difference between \(\keNat\,\text{eV}\) and \(\keFs\,\text{eV}\).
The HCN to HNC endpoints and the slab atoms in Table \ref{tab:hcn} come back with the mask and the id that were written, including the per-atom bits on the buried atom, the surface atom and the adsorbate.
On the @@latex:10\,000@@ frame band, at one worker, the Python binding is \spBandAse{} times faster than the ASE eon reader, while h5py remains faster on a dense position array.
Thread scaling is reported from its own interleaved run, and the hashed fields match across the worker counts that run covers.
readcon-db is a downstream store that indexes this text for a search over many checkpoints.
\ref{sec:appendix-db} describes what that store keeps and how the indexes are derived.

* Benchmark protocol and ratios
:PROPERTIES:
:CUSTOM_ID: sec:appendix-bench
:END:

The processor, the hardware-thread count, the compiler, the library revision, the script revision and the UTC date are columns of the per-repeat table.
The comparison calls the Python binding with one worker, and ASE, chemfiles, MDAnalysis and h5py run in the same process with OpenMP and BLAS limited to one thread.
The 1-frame, 100-frame and @@latex:10\,000@@-frame files repeat one 218-atom copper-hydrogen frame, and the slab is a separate single frame.
The slab is built with ASE 3.29 as an orthogonal fcc111 platinum cell of size 50 by 20 by 10, vacuum 8 angstrom, plus one hydrogen adsorbate at height 1.5 angstrom on an on-top site.
The bottom two layers are fixed on every axis, the other platinum atoms are free, and the adsorbate is fixed on z.
Velocities for the kinetic-energy check are a Maxwell-Boltzmann sample at 300 K on that slab, drawn with a NumPy Generator and seed 20261011, and that velocity section is left out of the timing file so the ASE eon reader can finish the frame.
XYZ and H5MD peers receive the coordinates of the same frames, written beside the CON text before the timed loop starts.
For each payload and each peer the loop is one-worker readcon-core, then the peer, thirty times, after one untimed call of each side.
A repeat that exceeds 240 seconds is recorded as a timeout, and a peer that raises is recorded as a failure, and neither of those outcomes is turned into a time.
The ratio uses only pairs in which both sides returned a time, and the interval is a bias-corrected and accelerated bootstrap of the median, with 9999 draws and seed 20261011 \cite{efronBetterBootstrapConfidence1987}.
A two-sided bootstrap probability for the median ratio equalling 1 is adjusted by the Holm step-down across those cells \cite{holmStepdown1979}.
Thread scaling is a second loop on the @@latex:10\,000@@-frame file, and for 2, 4 and 8 workers each repeat times one worker and then that worker count.
The field hash covers the stored coordinates, the masks, the ids and the velocities when a velocity section is present, and it is taken at 1, 2, 3, 4 and 8 workers.

* A corpus of CON frames
:PROPERTIES:
:CUSTOM_ID: sec:appendix-db
:END:

readcon-db keeps a campaign of CON frames, and it does not define a second geometry.
The stored object is the CON text of one frame, addressed by a trajectory number and the index of that frame inside the trajectory.
A 128-bit xxHash3 digest of those bytes finds an exact copy, and the first stored frame keeps the key when the same bytes arrive again.
The file is an LMDB store, memory-mapped, with one writer, so several readers can scan indexes during an ingest.
The text is parsed once to fill secondary indexes, and those indexes can be rebuilt from the text alone.
Atom count, chemical symbols and a composition key come from the type-grouped coordinates.
The composition key lists each symbol with its count, in symbol order, so the order of types in the file does not change it.
A finite energy on the metadata line is entered so a range scan stays ordered, and a non-finite energy is omitted.
That range uses the metadata energy, not the per-atom energies section.
The largest force magnitude is indexed only for a frame that has forces, and separate flags record forces and velocities.
Total mass is indexed when every per-type mass is finite, and the cell volume comes from the lattice vectors or, if they are absent, from the lengths and angles.
Periodicity is indexed only when the metadata states it, and an omitted flag is not filled in as periodic in all three directions.
Time, timestep, frame index, bead, band, charge and magnetic moment are indexed when each value is finite.
A selection intersects those indexes and returns keys, and the stored text is parsed only for a key the caller opens.
An optional numeric cache stores positions and, when the frame has them, forces and velocities, and that cache is ignored by the hash and by a rebuild.
An optional topology index stores a fingerprint of bonded neighbourhoods, and it is written only after a separate annotation \cite{goswamiDseamsDeferredStructural2020}.
The mask, the atom id, the units and the section names stay in the text, so a search does not stand in for the specification.
Finding a frame by composition or energy, after it has left the campaign, is the role of a repository API and a materials archive, which is what the data principles ask \cite{andersenOptimadeApiExchanging2021,draxlNomadLaboratoryData2019,wilkinsonFairGuidingPrinciples2016}.
