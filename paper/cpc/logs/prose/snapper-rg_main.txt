\title{readcon-core reads and writes the CON checkpoint format}

\input{authors.tex}

\begin{abstract}
CON is a file format used by rare-event and saddle-search codes to store atomic checkpoints.
readcon-core formalizes that format and is the reference reader and writer.
The parsed positions, velocities, forces, per-atom energies, masses and atom ids are exposed through DLPack.
At 32768 atoms the NumPy \texttt{from\_dlpack} median is $\dlpackExMed$\,s and the copy median is $\dlpackCpMed$\,s, from $\dlpackRepeats$ repeats on one host.
Text CON remains the file other codes read.
\end{abstract}

\section{Introduction}
\label{sec:introduction} Saddle searches, adaptive kinetic Monte Carlo, and nudged elastic band calculations checkpoint atomic configurations many times per image.
CON is a file format used in many places for that checkpoint.
readcon-core formalizes the file and improves the reader and the writer.
The layout is a short header, then atoms grouped by chemical type, each line a position, a constraint flag, and a fifth integer that historical writers used as a display index \cite{chillEONSoftwareLong2014}.
Velocities were stored in a sibling \texttt{.convel} file.
Later files add force blocks and free-form comments on line 2.
readcon-core exchanges the parsed position array through DLPack, and at 32768 atoms the NumPy exchange median is $\dlpackExMed$\,s against a copy median of $\dlpackCpMed$\,s.

The format is small and human-readable.
Independent implementations have treated column 4 as ``fixed or not'' and have ignored line 2.
ASE's \texttt{ase.io.eon} reader is of that class \cite{larsenAtomicSimulationEnvironment2017}: it decodes column 4 with \texttt{bool(int(...))}, discards column 5, and treats leftover force-section lines after the coordinate parse as an error.
Archived eOn C++ does the same boolean decode while keeping the fifth integer on \texttt{.con} (not on \texttt{.convel}).
Neither stack has a units object.
Column 4 therefore cannot carry a per-axis mask unless the reader consults a spec version.

\texttt{readcon-core} is the reference reader and writer for that contract.
Versions 2 and 3 are defined in the accompanying specification (\texttt{docs/orgmode/spec.org}); this paper states the parts that matter for interchange.
The design goal is one on-disk checkpoint and one C ABI, so a Fortran optimizer, a C++ driver, and a Python notebook see the same constraints, identities, and metadata.
\section{Related work}
\label{sec:related} CON is a rare-event checkpoint, not a general structure archive and not an MD analysis tape.
The nine-line type-grouped layout is the unversioned eOn de facto format.
Chill et al. describe the eOn software and do not specify atom-line columns \cite{chillEONSoftwareLong2014}.

Extended XYZ puts \texttt{Lattice=} and a \texttt{Properties=} column schema on the comment line; lean XYZ has neither.
There is no journal specification of extXYZ; the living grammar is the ASE/libAtoms dialect \cite{larsenAtomicSimulationEnvironment2017}.
CON uses a JSON object on line 2 for the same job (machine metadata on a line that old tools treat as a comment) and keeps a first-class three-bit constraint mask and a pre-grouping \texttt{atom\_id}.
Lean XYZ, as timed in this paper, has no constraint mask.
The library's ASE adapters convert a parsed \texttt{ConFrame} to \texttt{Atoms} and back; they do not register a \texttt{format}'con'= plugin and do not replace \texttt{ase.io.eon}.
That reader treats leftover force-section lines after the coordinate parse as an error.

H5MD is the structured particle container in this journal \cite{deBuylH5MDStructuredEfficient2014}.
It can carry per-particle mass, force, velocity, SI unit attributes, and an observables tree.
It has no first-class per-axis freeze mask and no type-grouped atom-index recovery.
The equal-geometry timings below treat H5MD as a peer load path, not as ``MD tape.''
GROMACS XTC/TRR and CHARMM/NAMD DCD are engine tapes: masses and restraints live in the TPR or PSF, and restart is a separate checkpoint (\texttt{cpt}, \texttt{namdbin}) \cite{abrahamGromacsHighPerformance2015}.
They are cited here and are not timed.

LAMMPS \texttt{dump custom} can store ids and optional forces on one row \cite{thompsonLammpsFlexibleSimulation2022}.
It does not store a spec-versioned constraint bitmask and does not require type-grouped blocks.
Atomsk converts among many crystal and MD formats and does not read or write eOn CON \cite{hirelAtomskToolManipulating2015}.
chemfiles is the optional ingress library \cite{frauxChemfiles2023}: it opens many formats; this paper measures XYZ\(\to\)\texttt{ConFrame}.
MDAnalysis is used only as the H5MD Python API in the wall-time table \cite{michaudAgrawalMDAnalysisToolkit2011,gowersMDAnalysisPythonPackage2016}; MDTraj is not timed \cite{mcgibbonMDTrajModernOpen2015}.
An optional metatensor export copies four \texttt{TensorBlock}s (positions, velocities, forces, per-atom energies) \cite{bigiMetatensorMetatomicFoundational2026}; it is not a TensorMap or metatomic \texttt{System} path.
\section{The CON format}
\label{sec:format} A spec 2 file places a JSON object on line 2 with at least \texttt{con\_spec\_version}.
Spec 3 requires a \texttt{units} object with non-empty \texttt{length} and \texttt{energy} keys.
The \texttt{sections} array names the data blocks that follow the coordinates (velocities, forces, energies, charges, spins, magnetic moments).
The Rust writer fills \texttt{sections} from the frame.

Column 4 is a bitmask \(0\ldots 7\).
Historical writers emit \(0\) or \(1\) (free or all-fixed).
This specification assigns a three-bit mask for spec 2+: \(1\) is \(x\)-only and \(7\) is all-fixed.
Writers emit \(7\) for all-fixed, never \(1\).
The decoder is spec-aware so that a legacy file with \(1\) remains all-fixed.
Old readers that test ``nonzero means fixed'' over-constrain \(y\) and \(z\) on a legal spec 2 file whose mask is 1 to 6; they still freeze the atom.
Column 5 is \texttt{atom\_id}.
Readers accept four-column lines and default the missing index to the sequential position in the frame.

Line 2 was chosen because existing tools treat it as a comment.
Adding a tenth header line, overwriting the postbox on lines 5 to 6, or shipping a sidecar \texttt{.con.meta} breaks those parsers or loses pairing.

Velocities live in a declared \texttt{sections} entry on a \texttt{.con} file.
The \texttt{.convel} extension is the historical name and the blank-separator fallback when the \texttt{sections} key is absent.
A present key, including an empty array, disables that fallback.

Gzip is the portable compression. zstd is an optional feature with the same magic-byte detection.
Both decompress to text and then parse.
They are not a new format.

A Cap'n Proto schema (\texttt{schema/ReadCon.capnp}) exists for an optional Rust RPC service.
It is a parsed-frame transport.
It is not an on-disk ``bcon'' authority.
The campaign store \texttt{readcon-db} keeps cooked SoA numerics in LMDB (RCSO) as a derived cache.
Text CON remains the file that independent tools must implement.

\subsection{Historical decode}
\label{sec:historical} The standard reader treats column 4 as a boolean.
A value of 0 leaves the atom free and any other value fixes x, y and z together.
That reader does not read a units object and it does not read a declared section.

\subsection{Spec-aware decode}
\label{sec:spec-aware} The reader in this paper takes four steps.
\begin{equation}
r \leftarrow \mathrm{next\ record}
\label{eq:propose}
\end{equation}
\begin{equation}
\mathrm{accept}(r) \iff v(r)\in\{2,3\} \land (v(r)\neq 3 \lor \mathrm{units}(r))
\label{eq:accept}
\end{equation}
\begin{equation}
F \leftarrow \mathrm{decode}(r)
\label{eq:update}
\end{equation}
\begin{equation}
\mathrm{stop} \iff \mathrm{no\ further\ record}
\label{eq:stop}
\end{equation}
Equation~\eqref{eq:propose} proposes the next header and its atom lines.
Equation~\eqref{eq:accept} accepts the record when the declared version is 2 or 3 and a version 3 record carries units.
Equation~\eqref{eq:update} writes the cell, the symbols and the constraint mask into the frame.
A legacy column-4 value of 1 is stored as the mask 7.
Equation~\eqref{eq:stop} stops at the end of the file.

\section{Library architecture}
\label{sec:architecture} The crate is an hourglass.
The Rust core owns \texttt{ConFrame}, the writer, and optional chemfiles import.
Figure~\ref{fig:architecture} draws that layering.

\begin{figure}[tbp]
\centering
\includegraphics[width=\textwidth]{figures/generated/architecture.pdf}
\caption{The Rust core parses and writes CON.
The C interface is the waist, and the language wrappers sit above it.}
\label{fig:architecture}
\end{figure} An optional Pest grammar (\texttt{grammar/readcon.pest}) is a surface-syntax companion; the I/O hot path is the hand-written parser. The C ABI in \texttt{src/ffi.rs} is generated into \texttt{include/readcon-core.h} and that header is what CMake FetchContent, the Meson wrap-file, and \texttt{pkg-config} install.
Consumers do not run cbindgen.

Python (\texttt{readcon} / \texttt{readcon-chemfiles}), Julia, and Fortran bind the C ABI (Python also calls the Rust parser directly).
The \texttt{python} feature enables Rayon.
Then \texttt{read\_all\_frames} / \texttt{read\_con} parse in parallel when the buffer is at least \$48\$$\backslash$,KiB; \texttt{n\_threads=1} forces the sequential iterator.
A default \texttt{cargo build} is sequential.
The published C prefix is built with \texttt{parallel}, so \texttt{rkr\_read\_all\_frames} follows the same automatic policy.
\texttt{rkr\_read\_all\_frames\_n\_threads} selects the worker count (\(0\) auto, \(1\) sequential, \(n\geq 2\) a pool).
Lean builds return \texttt{RKR\_STATUS\_FEATURE\_DISABLED} for chemfiles, metatensor, and CUDA rather than hiding the symbol.
RPC is a Rust feature and is not on the C ABI.
Builder \texttt{rkr\_frame\_builder\_build} returns \texttt{NULL} on validation errors (including type-mass mismatch); it does not abort.

The 0.14.x contract freezes ownership, sentinels (\texttt{NaN}, \texttt{UINT64\_MAX}, \texttt{NULL}), and the Z \(=1\ldots 92\) (+ D/T) helpers.
Additive symbols appear in a 0.14.z patch when the C ABI grows.
A breaking C change is a 0.15+ minor.

\section{Multi-language fidelity}
\label{sec:fidelity} A clause-keyed Phase A corpus under \texttt{resources/conformance/} locks the column-4 collision (spec 1 value \(1\) is all-fixed; spec 2 value \(1\) is \$x\$-only; spec 2 value \(7\) is all-fixed), required v3 units, missing \texttt{con\_spec\_version}, unsupported version \(4\), unknown section names, and \texttt{validate=true} without \texttt{sections}.
Each valid id has a JSON golden for spec version, column-4 mask, positions, atom ids, and symbols.
Rust, the C ABI, and Python share the same parser.
Fortran and Julia call the C ABI.
The optional Pest grammar is exercised separately (\texttt{cargo test -{}-{}features grammar}).
The published cxx tarball on the \texttt{v0.14.9} GitHub Release is the CMake FetchContent URL (SHA256 \texttt{4bf6b1809da292a7ea5cc59376e57220f31afa052c7365aecdc3b039c70b52f3}).
\section{Applications}
\label{sec:applications} eOn and the amsel campaign stack consume CON as the checkpoint between potential evaluations and saddle searches.
\texttt{readcon-db} indexes those files for energy, formula, and section presence.
\texttt{resources/examples/neb\_band.con} is a four-image spec-3 band (two atoms).
\texttt{resources/examples/cuh2\_band.con} is the same declared bead tags on the 218-atom \texttt{cuh2.con} geometry.
Each frame declares \texttt{neb\_bead}, \texttt{neb\_band}, \texttt{energy}, \texttt{fmax}.
\texttt{scripts/print\_neb\_band.py}, \texttt{examples/print\_neb\_band.cpp}, and \texttt{examples/print\_neb\_band.f90} print bead, energy, and \(f_{\max}\).
The energies are line-2 JSON.
They are not a production NEB.
The declared barrier \(E_1-E_0\) is $\nebBarrierEv$\,eV.
The declared \(f_{\max}\) is not recomputed from the force block.
The supplement lists the bead table.
Python \texttt{index\_projection()} returns the same campaign scalars (formula, energy, \texttt{neb\_bead}) that \texttt{readcon-db} indexes.
Python notebooks use \texttt{readcon} for lean I/O and \texttt{readcon-chemfiles} when the input arrives as XYZ.
This paper reports the XYZ mapping.
It does not report residue or occupancy for PDB and GRO.
The C++ RAII header is the path for in-process drivers that cannot embed a Python interpreter.
\section{DLPack exchange}
\label{sec:dlpack} The Rust frame stores positions, velocities, forces, per-atom energies, masses and atom ids in contiguous arrays.
\texttt{positions\_dlpack}, \texttt{velocities\_dlpack}, \texttt{forces\_dlpack}, \texttt{atom\_energies\_dlpack}, \texttt{masses\_dlpack} and \texttt{atom\_ids\_dlpack} borrow those arrays as DLPack views.
The C ABI exports the same fields as \texttt{rkr\_frame\_*\_dlpack} and \texttt{rkr\_frame\_builder\_*\_dlpack}.
The Python \texttt{xyz}, \texttt{vel} and \texttt{frc} getters allocate a fresh NumPy array from that storage, and that array implements \texttt{\_\_dlpack\_\_}.
NumPy \texttt{from\_dlpack} and PyTorch \texttt{from\_dlpack} share that array's pointer.
JAX \texttt{from\_dlpack} does not share the pointer on this build.
CuPy did not import.
A copy allocates a second array with \texttt{numpy.array(copy=True)}.
Table~\ref{tab:dlpack-params} fixes the repeats, the sizes and the dtype.
The hardware line is x86\_64, 8, Intel(R) Xeon(R) Processor.
Figure~\ref{fig:dlpack} and Table~\ref{tab:dlpack} report the median and the type 7 quartiles.
