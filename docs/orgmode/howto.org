* Querying the spec version

/Added in v0.5.0. Per-frame spec_version added in v0.6.0.

There are two distinct version queries:

1. *Library spec version*: the highest spec version the library
   implements (compile-time constant).
2. *File spec version*: the version a particular file was written
   with, parsed from the JSON metadata on line 2. Legacy files
   without JSON metadata report version 1.

** Rust

#+begin_src rust
use readcon_core::{CON_SPEC_VERSION, VERSION};

// Library version
assert_eq!(CON_SPEC_VERSION, 2);
println!("readcon-core {} (spec v{})", VERSION, CON_SPEC_VERSION);

// Per-frame version (from parsed file)
use readcon_core::iterators::read_first_frame;
let frame = read_first_frame(std::path::Path::new("input.con")).unwrap();
println!("File spec version: {}", frame.header.spec_version);
println!("Extra metadata: {:?}", frame.header.metadata);
#+end_src

** C/C++

#+begin_src c
#include "readcon-core.h"

// Compile-time library version check
#if RKR_CON_SPEC_VERSION >= 2
    // atom_id semantics available
#endif

// Runtime library version
printf("spec v%u, lib %s\n",
       rkr_con_spec_version(), rkr_library_version());

// Per-frame version (from parsed file)
RKRConFrame *handle = rkr_read_first_frame("input.con");
printf("File spec version: %u\n", rkr_frame_spec_version(handle));

// Full JSON metadata
char *json = rkr_frame_metadata_json(handle);
printf("Metadata: %s\n", json);
rkr_free_string(json);
free_rkr_frame(handle);
#+end_src

* Working with JSON metadata

/Added in v0.6.0.

Line 2 of every v2 CON file contains a JSON object. The writer always
stamps =con_spec_version=; additional keys survive round-trips.

** Rust: attaching custom metadata

#+begin_src rust
use readcon_core::types::ConFrameBuilder;
use std::collections::BTreeMap;

let mut meta = BTreeMap::new();
meta.insert("generator".to_string(),
            serde_json::Value::String("my-tool 1.0".to_string()));
meta.insert("temperature_K".to_string(),
            serde_json::json!(300.0));

let builder = ConFrameBuilder::new([10.0, 10.0, 10.0], [90.0, 90.0, 90.0])
    .metadata(meta);
// ... add atoms, build, write ...
// Line 2 of the output:
// {"con_spec_version":2,"generator":"my-tool 1.0","temperature_K":300.0}
#+end_src

** Python: reading and attaching metadata

#+begin_src python
import readcon

# Reading: metadata comes from the file's JSON line
frames = readcon.read_con("input.con")
print(frames[0].metadata)  # e.g. {"generator": "my-tool 1.0"}
print(frames[0].energy)    # typed accessors for common keys
print(frames[0].frame_index)

# Writing: metadata can be attached via typed setters
frame = readcon.ConFrame(
    cell=[10.0, 10.0, 10.0],
    angles=[90.0, 90.0, 90.0],
    atoms=[...],
)
frame.set_energy(-42.5)
frame.set_frame_index(5)
frame.set_time(2.5)
frame.set_timestep(0.5)
frame.set_neb_bead(3)
frame.set_neb_band(1)
frame.set_scalar_metadata("temperature_K", 300.0)
frame.set_string_metadata("generator", "my-tool 1.0")

# Direct item assignment uses the live metadata dict and is validated
# when the frame is written.
frame.metadata["workflow"] = {"name": "neb", "bead": 3}

# Or replace metadata from a raw JSON object
frame.set_metadata_json(
    '{"generator":"my-tool 1.0","temperature_K":300.0}'
)
readcon.write_con("output.con", [frame])
#+end_src

** Reading a convel file with velocities

The same iterator handles both =.con= and =.convel= files.
Velocity data is detected automatically by the parser.

#+begin_src rust
use std::fs;
use readcon_core::iterators::ConFrameIterator;

let contents = fs::read_to_string("trajectory.convel").unwrap();
let iter = ConFrameIterator::new(&contents);

for result in iter {
    let frame = result.unwrap();
    println!("Has velocities: {}", frame.has_velocities());

    for atom in &frame.atom_data {
        print!("{} ({:.4}, {:.4}, {:.4})", atom.symbol, atom.x, atom.y, atom.z);
        if atom.has_velocity() {
            print!(" vel=({:.6}, {:.6}, {:.6})",
                   atom.vx.unwrap(), atom.vy.unwrap(), atom.vz.unwrap());
        }
        println!();
    }
}
#+end_src

** Building frames from data

/Added in v0.4.0.

Use =ConFrameBuilder= to construct frames programmatically. The
=atom_id= parameter (6th argument to =add_atom=) is the original atom
index -- the position of this atom in your input before type-based
grouping. The builder groups atoms by symbol automatically, but
preserves each atom's =atom_id= so the original ordering can be
reconstructed.

#+begin_src rust
use readcon_core::types::ConFrameBuilder;

let mut builder = ConFrameBuilder::new([10.0, 10.0, 10.0], [90.0, 90.0, 90.0]);
// atom_id 0 and 1 for Cu, 2 for H -- these survive type-based reordering
builder.add_atom("Cu", 0.0, 0.0, 0.0, false, 0, 63.546);
builder.add_atom("H",  1.0, 2.0, 3.0, false, 2, 1.008);
builder.add_atom("Cu", 2.55, 2.55, 0.0, false, 1, 63.546);
let frame = builder.build()?;
// Atoms are now grouped: Cu(id=0), Cu(id=1), H(id=2)
#+end_src

** Writing with custom precision

/Added in v0.4.0.

Control the number of decimal places in output coordinates:

#+begin_src rust
use std::fs::File;
use readcon_core::writer::ConFrameWriter;

// Default text round-trips every finite binary64 value.
let file = File::create("output.con").unwrap();
let mut writer = ConFrameWriter::new(file);

// Fixed decimals are lossy. Ask for them explicitly.
let file = File::create("fixed.con").unwrap();
let mut writer = ConFrameWriter::with_precision(file, 6);
#+end_src

** Reading a single frame efficiently

/Added in v0.4.3.

When only the first frame is needed, =read_first_frame= stops after
parsing it.  Files under 64 KiB are read into memory directly; larger
files use memory-mapped I/O.

#+begin_src rust
use readcon_core::iterators::read_first_frame;
use std::path::Path;

let frame = read_first_frame(Path::new("single.con")).unwrap();
println!("Atoms: {}", frame.atom_data.len());
#+end_src

** Reading all frames from a file

For trajectory files with many frames, =read_all_frames= applies
the same small-file optimization and uses memory-mapped I/O for
larger files.

#+begin_src rust
use readcon_core::iterators::read_all_frames;
use std::path::Path;

let frames = read_all_frames(Path::new("large_trajectory.con")).unwrap();
println!("Loaded {} frames", frames.len());
#+end_src

** Reading a compressed trajectory in bounded memory

The path readers above decompress a =.con.gz= or =.con.zst= file into one buffer before parsing, so memory grows with the decompressed size.
=ConFrameReader= decodes and parses while it reads, and its buffer stays near one frame plus its read size (1 MiB, one mebibyte, by default).

#+begin_src rust
use readcon_core::stream::ConFrameReader;
use std::path::Path;

let mut atoms = 0;
for frame in ConFrameReader::open(Path::new("long_run.con.gz")).unwrap() {
    atoms += frame.unwrap().atom_data.len();
}
println!("Atoms over all frames: {atoms}");
#+end_src

=ConFrameReader::new= takes any =std::io::Read=, such as a socket or a decoder you have set up yourself.
=forward()= skips a frame without building it.
Frames and parse errors are those of =ConFrameIterator::from_bytes= over the whole stream.
The reader stops after the first error.
When the source fails, the reader first returns the frames that =from_bytes= finds in the bytes read before the failure, then the input or output error.
A frame is returned once the stream has ended, or once a line with text and one more line follow it, because the parser looks that far ahead to decide where a frame ends.
A frame larger than one read makes the buffer grow to that frame plus one read.
For a frame longer than eight reads, an eighth of the frame takes the place of that read.

** Parallel parsing

The =parallel= feature parses many frames on a Rayon pool. Python wheels
enable it. =read_all_frames=, =read_con= with =n_threads= omitted, and
=rkr_read_all_frames= stay on the calling thread. There is no file-size
cutoff that starts workers for you. A pool helps when the file has many
frames and the coordinate parse is the cost. One frame does not pay for
workers: starting a pool made that read slower.

=None=, =0=, and =1= are the calling thread. =n >= 2= is a pool of that
size. Equal-length frames, including a whitespace tail, use equal-span
boundaries, so the caller does not walk every header. Frames that do not
share a length still walk headers on the caller, then parse the spans on
the pool. A plain file of 64 KiB or more stays mapped. Smaller files, and
gzip or zstd input, are read into one buffer. The unit table is built once
and reused by the serial iterator, the C reader, and this pool.

#+begin_src rust
#[cfg(feature = "parallel")]
use readcon_core::iterators::{frames_from_text, parse_frames_parallel};

let contents = std::fs::read_to_string("large_trajectory.con").unwrap();
let sequential = frames_from_text(&contents, Some(1)).unwrap();
let results = parse_frames_parallel(&contents);
let frames: Vec<_> = results.into_iter().filter_map(|r| r.ok()).collect();
#+end_src

Python (wheels enable =parallel=):

#+begin_src python
frames = readcon.read_con("large_trajectory.con")
seq = readcon.read_con("large_trajectory.con", n_threads=1)
pinned = readcon.read_con("large_trajectory.con", n_threads=8)
assert readcon.has_parallel_support()
#+end_src

C (published prefix is built with =parallel=):

#+begin_src c
uintptr_t n = 0;
RKRConFrame **auto_p = rkr_read_all_frames(path, &n);
RKRConFrame **seq = rkr_read_all_frames_n_threads(path, &n, 1);
RKRConFrame **pool = rkr_read_all_frames_n_threads(path, &n, 8);
if (!rkr_has_parallel_support()) {
    /* seq and pool are the same sequential path */
}
#+end_src

** Appending, flushing, and buffering

=ConFrameWriter= keeps one frame of text in a scratch buffer and writes
that buffer through =std::io::BufWriter= (8 KiB). =write_frame= does not
always reach the file. =flush= does, and dropping the writer flushes too.
After =flush= returns, a reader sees a complete prefix.

=OpenMode::Append= and =from_path_append= extend an uncompressed file.
A missing file is created. A non-empty file that does not end in a newline
receives one. Gzip and zstd paths are refused. Python =write_con(..., append=True)=
streams one frame at a time and flushes before it returns. C is
=create_writer_from_path_append_c= and =rkr_writer_flush=.

#+begin_src rust
use readcon_core::writer::ConFrameWriter;
let mut writer = ConFrameWriter::from_path_append("run.con").unwrap();
writer.write_frame(&frame).unwrap();
writer.flush().unwrap();
#+end_src

#+begin_src python
readcon.write_con("run.con", frames)
readcon.write_con("run.con", more, append=True)
#+end_src

#+begin_src c
RKRConFrameWriter *writer = create_writer_from_path_append_c("run.con");
rkr_writer_extend(writer, frames, n);
rkr_writer_flush(writer);
free_rkr_writer(writer);
#+end_src

** Compression by extension, and stdin

A path ending in =.gz= is gzip and =.zst= is zstd, on read and on write.
The same choice is the magic bytes at the start of a read. Pass
=compression="gzip"=, ="zstd"=, or ="none"= to =write_con= to override the
extension. A =.zst= write needs the =zstd= Cargo feature.
=append=True= is only for an uncompressed file.

=ConFrameReader::new= takes any =std::io::Read=. Standard input is that
reader. A fifo opened by path is not mapped: the path readers take the
buffered branch for anything that is not a regular file of at least 64 KiB.
Python =read_con_string= parses text you already read, including
=sys.stdin.read()=.

#+begin_src rust
use readcon_core::stream::ConFrameReader;
use std::io::stdin;
for frame in ConFrameReader::new(stdin().lock()) {
    let frame = frame.unwrap();
    println!("{}", frame.atom_data.len());
}
#+end_src

#+begin_src python
import sys
import readcon
text = sys.stdin.read()
frames = readcon.read_con_string(text)
readcon.write_con("copy.con.gz", frames)
#+end_src

** Units

A CON =units= object names length, energy, and the other quantities.
=unit_conversion_factor(from, to)= returns the multiplier that takes a
value in =from= into =to=. The name table is built once per process.
Readers share it, including the C reader and a parallel parse.
Versions 1, 2, and 3.0 store velocities in the natural time unit.
From minor 1, =units.time= is the velocity time unit.

#+begin_src rust
use readcon_core::units::unit_conversion_factor;
let meters = unit_conversion_factor("angstrom", "m").unwrap();
#+end_src

#+begin_src python
frame.metadata["units"] = {"length": "angstrom", "energy": "eV"}
text = readcon.write_con_string([frame])
assert readcon.read_con_string(text)[0].metadata["units"]["length"] == "angstrom"
#+end_src

** Extended XYZ

=read_extxyz= returns a dict. =positions= has shape =(frames, atoms, 3)=,
=masses= is =(frames, atoms)=, =cell= is =(frames, 6)=, and =species= is
one tuple of symbols per frame. =arrays= holds every per-atom column.
A repeated symbol is one string, and a frame whose symbols match the
previous frame is that same tuple. =arrays["pos"]= is =positions=.
=write_extxyz= writes that dict back. A caller that unpacked a tuple
from an older =read_extxyz= should index the dict.

** ASE plugin

The =ase-readcon= package registers =readcon-con= and =readcon-convel=
on the =ase.ioformats= entry point. ASE loads that group when
=ase.io.read= or =ase.io.write= sees the format name.

#+begin_src shell
pip install readcon
pip install -e ase-readcon
#+end_src

#+begin_src python
from ase.io import read, write
images = read("run.con", index=":", format="readcon-con")

write("again.convel", images, format="readcon-convel")

A read walks =iter_con(stream=True)= unless the slice needs a length, in
which case it uses =count_frames= and =ConTrajectory=. A geometry write of
one species uses =write_coords=. Velocities and =append=True= go through
=write_con=.

** Streaming a large or compressed trajectory

=iter_con(path)= reads the whole file into memory before the first frame, and decompresses a gzip file whole.
For a long run, ask it to stream:

#+begin_src python
import readcon

energies = []
for frame in readcon.iter_con("long_run.con.gz", stream=True):
    energies.append(frame.energy)
#+end_src

Memory then stays near one frame plus 1 MiB, whatever the file size.
The frames are the same as without =stream=True=.
The loop raises =OSError= at a damaged frame, after it has processed the frames before it.
Without =stream=True=, invalid UTF-8 (Unicode Transformation Format, 8-bit) is raised by =iter_con= itself, before any frame.

** ASE Atoms conversion

/Added in v0.4.0.  atom_id, velocity, mass, forces, and per-axis
fixed-mask transfer are preserved.

Convert between =ConFrame= and ASE =Atoms= objects.  ASE MUST be
installed (it is an optional dependency).  The conversion preserves
atom_id (via a custom per-atom array), velocities, forces, masses,
and per-axis fixed masks.

#+begin_src python
import readcon

# ConFrame -> ase.Atoms
frames = readcon.read_con("input.con")
ase_atoms = frames[0].to_ase()

# ase.Atoms -> ConFrame
frame = readcon.ConFrame.from_ase(ase_atoms)

# Convenience: read a .con file directly as ase.Atoms list
ase_list = readcon.read_con_as_ase("trajectory.con")
#+end_src

*** atom_id in ASE roundtrips

=to_ase()= stores each atom's =atom_id= as a custom =atom_id=
per-atom array on the ASE =Atoms= object.  Tags are left untouched
so they remain available for other uses (slab layers, etc.).

#+begin_src python
import readcon

frames = readcon.read_con("saddle.con")
ase_atoms = frames[0].to_ase()

# atom_id is stored as a named per-atom array
print(ase_atoms.get_array("atom_id"))  # e.g. [3, 0, 1, 4, 2]

# Roundtrip preserves atom_id
frame_back = readcon.ConFrame.from_ase(ase_atoms)
assert [a.atom_id for a in frame_back.atoms] == [3, 0, 1, 4, 2]
#+end_src

When converting from an ASE =Atoms= object that was not created by
readcon, =from_ase()= checks for the =atom_id= array first, then
falls back to =tags= (if any are non-zero), and finally uses
sequential indices.

*** Velocities and masses in ASE roundtrips

Velocities from =.convel= files are transferred via
=set_velocities()= / =get_velocities()=.  Custom masses (when present
on the =ConFrame=) override ASE's atomic-number defaults via
=set_masses()=.

#+begin_src python
import readcon

# convel -> ASE preserves velocities
frames = readcon.read_con("trajectory.convel")
ase_atoms = frames[0].to_ase()
print(ase_atoms.get_velocities())  # non-zero velocity array

# Roundtrip back to ConFrame
frame_back = readcon.ConFrame.from_ase(ase_atoms)
assert frame_back.has_velocities
assert frame_back.atoms[0].fixed == frames[0].atoms[0].fixed
#+end_src

* C

** Reading and printing frames

#+begin_src c
#include "readcon-core.h"
#include <stdio.h>

int main(int argc, char *argv[]) {
    CConFrameIterator *iter = read_con_file_iterator(argv[1]);
    if (!iter) return 1;

    RKRConFrame *handle;
    while ((handle = con_frame_iterator_next(iter)) != NULL) {
        CFrame *frame = rkr_frame_to_c_frame(handle);

        printf("Cell: [%.4f, %.4f, %.4f]\n",
               frame->cell[0], frame->cell[1], frame->cell[2]);
        printf("Atoms: %zu, Has velocities: %s\n",
               frame->num_atoms, frame->has_velocities ? "yes" : "no");

        for (size_t i = 0; i < frame->num_atoms; i++) {
            CAtom *a = &frame->atoms[i];
            printf("  Atom %zu: (%.4f, %.4f, %.4f) fixed=%d id=%llu\n",
                   i, a->x, a->y, a->z, a->is_fixed,
                   (unsigned long long)a->atom_id);
            if (a->has_velocity) {
                printf("    vel=(%.6f, %.6f, %.6f)\n", a->vx, a->vy, a->vz);
            }
        }

        free_c_frame(frame);
        free_rkr_frame(handle);
    }
    free_con_frame_iterator(iter);
    return 0;
}

** Building frames from data

/Added in v0.4.0.

#+begin_src c
#include "readcon-core.h"

double cell[3] = {10.0, 10.0, 10.0};
double angles[3] = {90.0, 90.0, 90.0};

    rkr_frame_new(cell, angles, "", "", "", "");

                                      false, 1, 63.546);

    fprintf(stderr, "%s\n", rkr_status_message(status));
    free_rkr_frame_builder(builder);
    return 1;
}
status = rkr_frame_add_atom_with_velocity_and_forces_fixed_mask(
        builder, "Cu", 2.55, 2.55, 0.0,
        true, false, true,
        2, 63.546,
        0.1, 0.2, 0.3,
        -0.1, -0.2, -0.3);

    return 1;

    create_writer_from_path_with_precision_c("output.con", 17);

** Memory management

The C API uses two ownership patterns:

1. *Opaque handles* (=RKRConFrame=): allocated by Rust, freed with
   =free_rkr_frame()=. Used for lossless frame manipulation.
2. *Transparent structs* (=CFrame=): extracted copies freed with
   =free_c_frame()=. Used for direct data access.

Always free both the =CFrame= and the =RKRConFrame= separately.

** Exact numeric CON output from C

=create_writer_from_path_round_trip_c(path)= retains every finite binary64
value, including forces below the precision of fixed decimal output.
Use =rkr_writer_extend= to append frames and =rkr_writer_flush= to check
for write failures before calling =free_rkr_writer=. Decimal-place
formatting is available through =create_writer_from_path_with_precision_c=.
Seventeen decimal places do not preserve every binary64 value.
