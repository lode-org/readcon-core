This document is the normative CON format. CON checkpoints come from
rare-event work on eOn
@@rst::cite:t:`goswamiNEBOrchestration2026`@@ @@rst::cite:t:`goswamiRMSDProjections2026`@@ @@rst::cite:t:`goswamiGaussianProcessSaddle2025`@@ @@rst::cite:t:`chillEONSoftwareLong2014`@@.

Where this prose and the included PEG disagree, these clauses win.
Requirement words in uppercase follow RFC 2119 and RFC 8174
@@rst::cite:t:`bradnerKeyWordsUse1997`@@ @@rst::cite:t:`rfc8174`@@.
Lowercase spellings of those words are not requirement words.

- CON-status.1 :: MUST :: A reader MUST accept every minor and every patch of major 4, and every minor of major 3, including minor 0 and a minor or patch it does not implement.
- CON-status.2 :: MUST :: A new implementation MUST accept version 2 and implicit version 1.
- CON-status.3 :: MUST :: The identity of this specification MUST be the triple major.minor.patch.
- CON-status.4 :: MUST :: Any change to normative text MUST increase at least the patch component of that identity.
- CON-status.5 :: MUST NOT :: A minor revision MUST NOT change the meaning of an existing key or of an existing section.
- CON-status.6 :: MAY :: A minor revision MAY add keys and sections. A reader of an earlier minor of that major MUST preserve an unknown key and MUST apply =CON-section.8= and =CON-section.9= to an unknown section.
- CON-status.8 :: MUST :: The words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, NOT RECOMMENDED, MAY, and OPTIONAL have the meanings in RFC 2119 and RFC 8174 only when every letter is uppercase. A lowercase spelling is ordinary English.

* File
:PROPERTIES:
:CUSTOM_ID: file
:END:

A file is a concatenation of frames. The names =.con=, =.convel=,
=.con.gz=, =.convel.gz=, =.con.zst=, and =.convel.zst= are informative.
Acceptance is =CON-file.10=.

- CON-file.1 :: MUST :: A CON file MUST be UTF-8. A line that is not UTF-8 MUST be =ValidationError=, except where =CON-num.10= names =InvalidNumberFormat=.
- CON-file.2 :: MUST NOT :: A CON file MUST NOT begin with a byte-order mark, and no frame may begin with U+FEFF. A reader MUST reject either case as =ValidationError=.
- CON-file.3 :: MUST :: Parsers MUST accept LF (=\n=) and CRLF (=\r\n=) line endings. A writer MUST end each line with LF and MUST NOT use a bare CR as its line ending.
- CON-file.4 :: MUST :: Parsers MUST ignore trailing spaces and tabs on every line.
- CON-file.5 :: MUST :: A label comparison MUST split both lines on ASCII spaces and tabs, drop empty words, and compare the words with ASCII case folding.
- CON-file.6 :: MUST NOT :: Writers MUST NOT insert an extra blank line between frames.
- CON-file.7 :: MUST :: A blank line MUST contain only characters of Unicode White_Space, and no other character.
- CON-file.8 :: MUST :: A line that is not UTF-8 and is not consumed as a numeric field MUST be =ValidationError=.
- CON-file.9 :: MUST :: A CR that is the last byte of the input MUST be read as a line ending, and the verdict is acceptance of that ending. =CON-file.3= defines a line ending as LF or CR LF. A final CR is the CR of a CR LF whose LF was not written, and only the last line may omit that LF. The bytes before that CR are the line. A line with no other bytes MUST be a blank line, so a trailing CR after a complete frame is the blank tail of =CON-frame.1=. It MUST NOT be read as a new frame, and it MUST NOT be read as a character of the previous line. A CR that is not the last byte is not this ending and stays in its line.
- CON-file.10 :: MUST :: This specification does not register a media type @@rst::cite:t:`rfc6838`@@. A reader MUST accept a file these clauses accept whether or not a media type is supplied beside it.
- CON-file.11 :: MUST :: A reader MUST NOT apply Unicode normalization @@rst::cite:t:`rfc3629`@@. A reader MUST NOT apply case folding except the ASCII case folding of label words in =CON-file.5= and the exact spellings of =CON-units.16=. A float spelling is not canonical: any spelling that =CON-num.6= accepts is enough.

* Frame and end of file
:PROPERTIES:
:CUSTOM_ID: frame
:END:

Each frame is a 9-line header, one coordinate block per atom type, then
the declared sections. There is no separate inter-frame marker. The rule is =CON-frame.7=.
A stray blank is that next line, so the header is short and =CON-frame.3= reports =IncompleteHeader=. That sentence is not a separate requirement.

- CON-frame.1 :: MUST :: After the last complete frame, the ignored tail MUST be at most one blank line as in =CON-file.7=, followed only by lines whose bytes are spaces, tabs, form feeds, or carriage returns. Any other following line MUST be read as the next frame.
- CON-frame.2 :: MUST NOT :: Readers MUST NOT silently drop a partial last frame.
- CON-frame.3 :: MUST :: One to eight header lines of a further frame MUST be reported as =IncompleteHeader=, except a type count of 0 at end of file whose lines 8 and 9 are absent.
- CON-frame.4 :: MUST :: Fewer coordinate rows than the header declares MUST be reported as =IncompleteFrame=.
- CON-frame.5 :: MUST NOT :: A blank line followed only by whitespace to end of file MUST NOT be read as a legacy velocity block.
- CON-frame.6 :: MUST :: A partial declared section MUST be reported as =IncompleteSection(name)=.
- CON-frame.7 :: MUST :: After a complete frame, including its declared sections or the legacy velocity block where that applies, the next line MUST be line 1 of the next frame, even when it is empty.
- CON-frame.8 :: MUST :: A file that contains no bytes MUST be read as zero frames.
- CON-frame.9 :: MUST :: At the start of a file, a reader MUST read the lines as the header of a frame. =CON-frame.1= applies only after a complete frame.

* Header

| Line | Content                                              |
|------+------------------------------------------------------|
|    1 | Free-form generator text, preserved                  |
|    2 | One JSON object, or free text for version 1          |
|    3 | Three lengths a, b, and c, in =units.length=         |
|    4 | =alpha beta gamma= in degrees                        |
|    5 | Free-form text, preserved                            |
|    6 | Free-form text, preserved                            |
|    7 | Type count, integer >= 0                             |
|    8 | Per-type counts, empty when line 7 is 0              |
|    9 | Masses in =units.mass=, empty when line 7 is 0       |

Line 1 and lines 5-6 have no further meaning. Preservation is =CON-header.2=.
An empty line 1 and an empty line 2 are =CON-header.4=. An empty line 2 does not start with ={=, so the frame is implicit version 1.
Angstrom and amu apply when =units= or that key is absent.

- CON-header.1 :: MAY :: Writers MAY leave lines 5 and 6 empty.
- CON-header.2 :: MUST :: Parsers MUST preserve line 1 and lines 5 and 6.
- CON-header.3 :: MUST :: Line 3 and the coordinate columns MUST be read in =units.length=, and line 9 in =units.mass=. Absent =units= or an absent key means angstrom and amu.
- CON-header.4 :: MUST :: Parsers MUST accept an empty line 1 and an empty line 2. An empty line 1 is preserved. An empty line 2 is implicit version 1.

** Line 2: Metadata
:PROPERTIES:
:CUSTOM_ID: metadata
:END:

Line 2 is one JSON object when the file is version 2 or newer.
A line that does not start with ={= after leading spaces and tabs are removed is implicit version 1. That test is =CON-line2.1=.
Metadata is line 2. Line numbers count from 1.

- CON-line2.1 :: MUST :: A line 2 whose first character, after leading spaces and tabs are removed, is ={= MUST be one UTF-8 JSON object and nothing else. A line that does not start that way is implicit version 1.
- CON-line2.2 :: MUST :: Malformed JSON on that line MUST be rejected.
- CON-line2.3 :: MUST :: A JSON object that omits =con_spec_version= MUST be rejected.
- CON-line2.4 :: MUST :: =con_spec_version= MUST be a JSON integer, the major version, and not a string. A JSON number that is not an integer MUST be =InvalidMetadataJson=.
- CON-line2.5 :: MUST :: JSON =con_spec_version= 0 or 1 MUST be rejected as =UnsupportedVersion=.
- CON-line2.6 :: MUST :: An unknown major MUST be rejected as =UnsupportedVersion=.
- CON-line2.7 :: MUST :: A reader of a known major MUST accept every minor and every patch of that major, including a minor or patch it does not implement.
- CON-line2.8 :: MUST :: Unknown keys MUST be preserved on rewrite as their JSON values @@rst::cite:t:`brayJavascriptObjectNotation2017`@@. The rewrite MUST NOT be required to preserve key order, insignificant whitespace, or the original spelling of a number, and it is not required to follow the JSON Canonicalization Scheme @@rst::cite:t:`rfc8785`@@. A JSON string MUST be preserved as that string. An escape that is not a JSON escape MUST be =InvalidMetadataJson= under =CON-line2.2=.
- CON-line2.9 :: MUST :: =con_spec_minor=, when present, MUST be a JSON integer >= 0.
- CON-line2.10 :: MUST :: An absent =con_spec_minor=, or an explicit 0, MUST mean minor 0.
- CON-line2.11 :: MUST :: =sections=, when present, MUST be an array of strings.
- CON-line2.12 :: MUST :: =validate=, when present, MUST be a boolean.
- CON-line2.13 :: MUST :: Reserved keys MUST use the types in this document.
- CON-line2.14 :: MUST NOT :: A line 2 object MUST NOT repeat the =con_spec_minor= key.
- CON-line2.15 :: MUST :: =con_spec_patch=, when present, MUST be a JSON integer >= 0. Any other type MUST be =InvalidMetadataJson=.
- CON-line2.16 :: MUST :: An absent =con_spec_patch=, or an explicit 0, MUST mean patch 0.
- CON-line2.17 :: MUST :: A reader of a known major MUST accept every patch of that major.
- CON-line2.18 :: MUST :: A reader MUST accept line 2 when the nesting depth of its JSON value, counting the outer value, is at most 127, and MUST reject a greater depth as =InvalidMetadataJson=. That rejection MUST NOT require stack space proportional to the depth.
- CON-line2.19 :: MUST :: A reserved key that must hold a finite number, and whose JSON number is not a finite binary64, MUST be =InvalidMetadataJson=.
- CON-line2.20 :: MUST :: A reader MUST apply the every-mode type check of a reserved key before the checks of =CON-validate.4=. A wrong type MUST be =InvalidMetadataJson=.
- CON-line2.21 :: MUST NOT :: A JSON number that is not a finite binary64, stored under a key this document does not reserve, MUST NOT reject the frame. The verdict is acceptance. An unreserved key has no numeric meaning in this format, and =CON-line2.8= preserves it as a JSON value, including a number a reader cannot store as a finite binary64. Rejecting the frame would turn an extension key into a parse error. A reserved key that must hold a finite number is =CON-line2.19=, and that verdict is =InvalidMetadataJson=.
- CON-line2.22 :: MUST :: =con_spec_minor=, =con_spec_patch=, and any other integer version field MUST fit in an unsigned 64-bit integer. A reader MUST reject a larger value as =InvalidMetadataJson=.
- CON-line2.23 :: MUST :: A JSON object MUST NOT repeat a name. A repeated name, in the metadata object or in any object it contains, MUST be =InvalidMetadataJson=. The reader MUST NOT keep one of the values.
- CON-line2.24 :: MUST :: This schema MUST be informative. These clauses decide acceptance. The schema carries this specification identity.
- CON-line2.25 :: MUST :: =CON-line2.18= is the resource limit on line 2. A reader MUST accept a frame the conformance corpus accepts. A reader MUST NOT reject a frame these clauses accept because of the byte length of the file.

** Cell
:PROPERTIES:
:CUSTOM_ID: cell
:END:

Line 3 is =|a| |b| |c|=. Line 4 is =alpha= =angle(b,c)=, =beta= =angle(a,c)=,
=gamma= =angle(a,b)=, in degrees. =a= lies along x and =b= lies in the xy plane.
eOn 3.6.0 reads that placement at =client/ConFileIO.cpp:659-681= and writes it at =:531-549=.
ASE =cellpar_to_cell= uses the same orientation by default (=ase/geometry/cell.py:50=, =ab_normal=(0,0,1)=).
=lattice_vectors= is three row vectors in =units.length=, =[a, b, c]=.

- CON-cell.1 :: MUST :: When =lattice_vectors= is present, readers MUST prefer it over lines 3-4.
- CON-cell.2 :: MUST :: A writer that emits =lattice_vectors= MUST write lines 3-4 consistent with that matrix at the precision the writer is using.
- CON-cell.3 :: MUST :: An absent =pbc= key MUST be read as periodic in all three directions.
- CON-cell.4 :: MUST :: =pbc=, when present, MUST be a length-3 array of booleans.
- CON-cell.5 :: MUST :: =lattice_vectors=, when present, MUST be three length-3 arrays of finite numbers.
- CON-cell.6 :: MUST :: When =lattice_vectors= is absent, a reader MUST build the cell from lines 3 and 4. The angles are converted from degrees to radians, ~a=(|a|, 0, 0)~, ~b=(|b| cos gamma, |b| sin gamma, 0)~, and ~c=(|c| cos beta, |c| (cos alpha - cos beta cos gamma) / sin gamma, |c| sqrt(1 - cos^2 beta - ((cos alpha - cos beta cos gamma) / sin gamma)^2))~. The square root is the z component of =c=. A construction that is not a real cell MUST be rejected on the angles line, as =CON-cell.7= requires.
- CON-cell.7 :: MUST :: When =lattice_vectors= is absent and each angle is in (0, 180) degrees, a reader MUST evaluate the radicand of =c_z= in binary64 and MUST NOT contract a multiply and an add into a fused multiply-add. With alpha, beta, and gamma the angles in radians, the operations in order are cos alpha, cos beta, cos gamma, sin gamma, cy = (cos alpha - cos beta * cos gamma) / sin gamma, and radicand = 1 - cos beta * cos beta - cy * cy. A radicand greater than -1e-12 MUST be accepted, and a negative radicand in that window MUST set =c_z= to 0. Any other radicand, including a NaN radicand, MUST be =ValidationError= on the angles line.

** Counts

A type count of 0 is a frame with no atoms.
Lines 8 and 9 are whitespace only, no coordinate block and no section follow, =sections= is absent or empty, and the legacy velocity fallback does not apply.
That frame is legal with =validate= true.
A per-type count of 0 is InvalidCount when the type count is 1 or more.
ASE 3.29.0 =write_eon(Atoms())= writes type count 0, an empty line 8, and an unterminated empty line 9 (=ase/io/eon.py:277-307=).
=ase.io.eon.read_eon= then raises =IndexError= at =images[0]= (=ase/io/eon.py:188=). The =StopIteration= from the ninth =next()= is caught inside that function (=:177-179=).
=ase.io.read(path, format="eon")= raises =StopIteration= from =ase/io/formats.py:821= (=next(_iread(...))= on a read that yields no image).

- CON-count.1 :: MUST :: A type count of 0 MUST be a frame with zero atoms: lines 8 and 9 contain only spaces and tabs, no coordinate block and no section block follow, =sections= is absent or empty, and the legacy velocity fallback does not apply. Any other character on line 8 or 9, including other Unicode White_Space, MUST be =InvalidCount=.
- CON-count.2 :: MUST :: A zero-atom frame of that form MUST be accepted in every mode, including =validate= true. =CON-validate.3= independently requires the =sections= key when =validate= is true.
- CON-count.3 :: MUST :: When the type count is 1 or more, each per-type count MUST be an integer >= 1, and any other count token MUST be =InvalidCount=.
- CON-count.4 :: MUST :: At end of file, when line 7 is 0, omitted lines 8 and 9 MUST be read as empty, and =CON-frame.3= MUST NOT report that frame as =IncompleteHeader=.
- CON-count.5 :: SHOULD NOT :: Writers SHOULD NOT write a zero-atom frame for a consumer that predates v3.1.
- CON-count.6 :: MUST :: The coordinate blocks MUST follow header order.
- CON-count.7 :: MUST :: The total atom count MUST equal the sum of line 8.
- CON-count.8 :: MUST :: Component numbers in labels MUST start at 1.
- CON-count.9 :: MUST :: A count token MUST be an integer in 0 through 2^64-1. An integer outside that range MUST be =InvalidCount=.
- CON-count.10 :: MUST :: On a count line, a token that is not an unsigned integer MUST be reported as =InvalidCount= before the field-count check of =CON-num.9= is applied to that line. A count line is a sequence of unsigned integers. A token that is not one is not a field of that line, so the line has no field count to check. The verdict names the token. That class is =InvalidCount=, including when the line also has the wrong number of tokens.

* Coordinates

One block per type: a symbol line, a =Coordinates of Component N= label,
then one atom line per atom of that type. Columns are whitespace-separated.

| Column | Token   | Meaning                         |
|--------+---------+---------------------------------|
|      1 | float   | x, in =units.length=            |
|      2 | float   | y, in =units.length=            |
|      3 | float   | z, in =units.length=            |
|      4 | integer | Constraint flag                 |
|      5 | integer | Atom id. A writer MAY omit it. When it is omitted the reader applies =CON-id.9=. When it is present the ids MUST be unique within the frame (=CON-id.3=). |

- CON-coord.1 :: MUST :: In every mode, the label of a coordinate block MUST equal =Coordinates of Component N= under =CON-file.5=, with N starting at 1, and any other label MUST be =ValidationError=.
- CON-coord.2 :: MUST :: A coordinate block MUST be a symbol line, then the label of =CON-coord.1=, then one row per atom of that type.

** Per-direction constraints (column 4)
:PROPERTIES:
:CUSTOM_ID: constraints
:END:

Column 4 is an integer token. Bit 0 is x, bit 1 is y, bit 2 is z.
Spec 1 (no JSON on line 2): 0 is free, 1 is fixed in all three directions.
Spec 2 and later: 0 through 7 are the bitmask, and 1 is x only.
Writers of spec 2 and later emit 7 for all-fixed.

- CON-mask.1 :: MUST :: Column 4 MUST be an integer token with no sign and no decimal point.
- CON-mask.2 :: MUST :: In spec 1, readers MUST treat 0 as free and 1 as fixed on x, y, and z.
- CON-mask.3 :: MUST :: In spec 1, any other column-4 token MUST be =InvalidFixedFlag=.
- CON-mask.4 :: MUST :: In spec 2 and later, values 0 through 7 MUST be read as the bitmask above.
- CON-mask.5 :: MUST :: A float spelling, a sign, or a value outside the legal set MUST be =InvalidFixedFlag= in every mode, including when =validate= is absent or false.
- CON-mask.6 :: MUST NOT :: A spec 2 or later writer MUST NOT emit 1 to mean all-fixed.
- CON-mask.7 :: MUST :: A spec 2 or later writer MUST emit 7 for an atom fixed on x, y, and z.
- CON-mask.8 :: MUST :: Bit 0 of column 4 MUST be x, bit 1 MUST be y, and bit 2 MUST be z. The bitmask of =CON-mask.4= is this order.

** Atom index (column 5)
:PROPERTIES:
:CUSTOM_ID: atom-index
:END:

Column 5 is the atom id. No base is implied.
Grouping by type reorders atoms relative to a pre-group sequence.
eOn 3.6.0 stable-sorts by ascending id when the ids are unique, and keeps file order when any id repeats (=client/ConFileIO.cpp:147-176= =matter_order=, called at =:691=).
v3.4.0 has the same function.

- CON-id.1 :: MUST :: Column 5, when present, MUST be parsed as an integer in 0 through 2^64-1, and MUST NOT be parsed through binary64.
- CON-id.2 :: MUST NOT :: Readers MUST NOT assume that ids start at 0 or at 1.
- CON-id.3 :: MUST :: A writer MAY omit column 5. When column 5 is present, the ids MUST be unique within the frame. When it is omitted, the reader applies =CON-id.9=.
- CON-id.4 :: MUST :: Readers MUST accept repeated ids.
- CON-id.5 :: MUST :: The pre-grouping order of a frame MUST be ascending column-5 id when the ids are unique, and file order otherwise.
- CON-id.6 :: MUST :: A reader MUST expose column-5 ids unchanged.
- CON-id.7 :: MUST :: A reader or consumer that returns atoms in pre-grouping order MUST use =CON-id.5=.
- CON-id.8 :: MAY :: A reader MAY return atoms in file order together with their column-5 ids.
- CON-id.9 :: MUST :: A 4-column atom line MUST use the 0-based position of that atom in the frame as its id.
- CON-id.10 :: MUST :: =ids_persistent=, when present, MUST be a JSON boolean. Any other type MUST be =InvalidMetadataJson=.
- CON-id.11 :: MUST :: When =ids_persistent= is true on any frame, it MUST be true on every frame, every frame MUST hold the same set of column-5 ids, and each of those ids MUST occur once in a frame. Column 5 of a historical file is an index of one frame, so cross-frame identity is not the default. =ids_persistent= true is the file opting into that identity: the same id is the same atom in every frame. A reader MUST reject a file that breaks this rule as =ValidationError= on the last line of the frame that breaks it. A writer MUST NOT emit such a file.
- CON-id.12 :: MUST NOT :: When =ids_persistent= is absent or false on every frame, a reader MUST NOT treat an id in one frame as the same atom in another frame. The verdict is that the reader returns the ids and does not match them across frames. =CON-id.4= applies inside a frame.
- CON-id.13 :: MUST :: A read of a frame followed by a write of that frame MUST preserve each column-5 id.

* Sections
:PROPERTIES:
:CUSTOM_ID: sections
:END:

A section is present exactly when its name is in =sections=.
An empty =sections= array means no section follows, and it disables the
legacy velocity fallback. With no =sections= key, one blank line that
begins a complete velocity block is a velocity section. A blank line
that does not begin that block is line 1 of the next frame. That fallback
is the only undeclared section, and =CON-frame.5= limits it.
Minor 1 reserves the names in the table below.
A vector row has arity 3 and a scalar row has arity 1.
Those integers count value fields only.

** Section declaration

- CON-section.1 :: MUST :: On disk, a section MUST be treated as present exactly when its name is listed in =sections=, aside from the legacy velocity fallback.
- CON-section.2 :: MUST :: Exactly one blank line MUST precede each section block.
- CON-section.3 :: MUST NOT :: Writers MUST NOT put a blank line between the component blocks inside a section.
- CON-section.4 :: MUST :: Each component block MUST be a symbol line, a label, and one data row per atom of that type.
- CON-section.5 :: MUST :: The per-atom energy section name MUST be =energies=.
- CON-section.6 :: MUST NOT :: =atom_energies= MUST NOT be used as a section name.
- CON-section.7 :: MUST :: An unknown section name MUST be reported as =UnknownSection= when the frame minor is not newer than the minor this reader implements.
- CON-section.8 :: MUST :: When the frame minor is newer than the minor this reader implements for that major, the reader MUST skip an unknown section whose value-field count is given by =section_arity=. For major 4 that minor is 0. For major 3 that minor is 1.
- CON-section.9 :: MUST :: If that minor is newer and =section_arity= does not give the value-field count, the reader MUST report =UnknownSection=.
- CON-section.10 :: MUST :: Adding a reserved section name MUST increase =con_spec_minor=.
- CON-section.11 :: MUST NOT :: Adding a reserved section name MUST NOT require a new major.
- CON-section.12 :: MUST :: =section_arity=, when present, MUST be an object mapping section names to integers >= 1, each the number of value fields on a data row, excluding the flag and the optional id.
- CON-section.13 :: MUST :: An entry for a reserved section MUST equal 3 for a vector row and 1 for a scalar row. A reader MUST reject any other value because the row does not have the number of fields that section requires.
- CON-section.14 :: MUST :: A data row of an unknown section MUST hold that arity of value fields, then the flag, and an optional id, so the row has arity+1 or arity+2 tokens.
- CON-section.15 :: MUST :: The label of any section MUST be its name compared under =CON-file.5=, followed by =of Component N=. When =validate= is not true, a label that does not match MUST be =IncompleteSection=. When =validate= is true, that label MUST be =ValidationError=.
- CON-section.16 :: MUST :: A writer whose minor is greater than the minor that reserves the section table MUST list in =section_arity= every section it emits that the table does not name. That reserving minor is 0 for major 4 and 1 for major 3.

| Name            | Label                         | Row                                           |
|-----------------+-------------------------------+-----------------------------------------------|
| =velocities=    | =Velocities of Component N=   | =vx vy vz= flag id                            |
| =forces=        | =Forces of Component N=       | =fx fy fz= flag id                            |
| =energies=      | =Energies of Component N=     | energy flag id                                |
| =charges=       | =Charges of Component N=      | charge flag id                                |
| =spins=         | =Spins of Component N=        | spin flag id                                  |
| =magmoms=       | =Magmoms of Component N=      | =mx my mz= flag id                            |
| =displacements= | =Displacements of Component N=| =dx dy dz= flag id, =units.length=            |
| =spreads=       | =Spreads of Component N=      | =sx sy sz= flag id, =units.length=, each >= 0 |

Identity columns repeat the coordinate flag and id. A mismatch is =CON-section.17=. Calling a zero spread a classical point is informative. The value rule is =CON-section.20=.

- CON-section.17 :: MUST :: When =validate= is not true, a reader MUST ignore an identity-column mismatch after the row has the right number of fields.
- CON-section.18 :: SHOULD :: The =energy= metadata value SHOULD equal the sum of the =energies= rows.
- CON-section.19 :: MUST NOT :: A mismatch between that sum and =energy= MUST NOT reject the frame.
- CON-section.20 :: MUST :: Each =spreads= value MUST be finite and >= 0. A value that is not MUST be =ValidationError=.
- CON-section.21 :: MUST NOT :: When =validate= is not true, a reader MUST NOT reject a section because of its symbol line, including a blank symbol line.
- CON-section.22 :: MUST :: Section blocks MUST follow the coordinate blocks in the order listed in =sections=. A label that does not match the next listed section MUST be =IncompleteSection=.
- CON-section.23 :: MUST :: Two or more blank lines before a section block make the second blank line the symbol line of that section. The following line is then its label, and a label that fails =CON-section.15= MUST be =IncompleteSection=.
- CON-section.24 :: MUST :: A name MUST NOT appear twice in =sections=. A repeated name MUST be =InvalidMetadataJson=.
- CON-section.25 :: MUST :: The reserved section names MUST be =velocities=, =forces=, =energies=, =charges=, =spins=, =magmoms=, =displacements=, and =spreads=, with the labels and rows of the table in this section.

** Validation mode
:PROPERTIES:
:CUSTOM_ID: validation-mode
:END:

- CON-validate.1 :: MUST :: =validate= true MUST add the checks in =CON-validate.4=.
- CON-validate.2 :: MUST NOT :: =validate= true MUST NOT relax a check that already applies in every mode.
- CON-validate.3 :: MUST :: When =validate= is true, =sections= MUST be present, and an empty array is legal.
- CON-validate.4 :: MUST :: In that mode, readers MUST reject a non-positive cell length, an angle outside (0, 180) degrees, a non-positive mass, an unrecognized symbol other than =X=, a section symbol mismatch, or an identity column that does not match the coordinate row, as =ValidationError=. A bad reserved-key type is =InvalidMetadataJson= under =CON-line2.13= and =CON-line2.19=. A coordinate label is =CON-coord.1= in every mode. A section label is =CON-section.15= in every mode.

** Frame topology (bonds)
:PROPERTIES:
:CUSTOM_ID: bonds
:END:

=bonds= is optional frame topology, not a section.
Each entry is =[i, j]= or ={"i": i, "j": j}= with an optional integer =order=.
Indices are 0-based into coordinate-block order, not column-5 ids.

* Units (required)
:PROPERTIES:
:CUSTOM_ID: units
:END:

=units= maps a dimension to a unit expression: names combined with =*=, =/=, =^=, and parentheses.
Version 3 requires =length= and =energy=.
Velocity is length/time taken from =units=.

The natural time unit used by eOn and by ASE is the symbol spelling =(u*Å^2/eV)^0.5= (=CON-units.5=).
The older spelling =(amu*angstrom^2/eV)^0.5= mixes a name with symbols. It is an alias of the same unit, not the spelling a new frame uses.
CON 4 uses the CODATA 2018 adjustment @@rst::cite:t:`tiesingaCodataRecommendedValues2021`@@ and no later edition. Every derived constant, including this natural unit and its value in femtoseconds, is computed from the one table in =CON-units.18=. A later edition would be a change to that table and to nothing else.
Under those constants =units.rs= parses it as about 10.180505710759414 fs.
eOn 3.6.0 hard-codes 10.1805055 fs (=include/eon/ParametersOptions.h:26=).
That literal is not a constant of CON 4.
The relative difference is about 2e-8.
A velocity is a length divided by a time. In major 4 that time is =units.time= (=CON-units.10=). In major 3 and earlier that time is this natural unit (=CON-units.8=). =units.velocity= does not replace that time (=CON-units.21=).
A writer that canonicalises the expression by inserting spaces is not using the pinned spelling.
=kcal= is the thermochemical kilocalorie, exactly 4184 joule @@rst::cite:t:`nistSP811Conversions`@@. The SI Brochure does not define the calorie. =kcal= is not a CODATA value. =mol= is the mole, the Avogadro constant of the 2018 edition. Unit symbols are case sensitive, as the SI Brochure requires in section 5.2 @@rst::cite:t:`bipmSI2019`@@.

A writer that records this unit on a frame of major 3 or earlier MUST use the historical spelling. A reader MUST NOT treat a unit name and a unit symbol as interchangeable by changing case.

- CON-units.7 :: MAY :: Version 2 MAY carry =units=.

eOn =.convel= output at 6 digits after the decimal (=kConvelPrecision= in =client/ConFileIO.cpp:43=) is fixed-decimal and lossy.
The kinetic-energy loss for that rounding was measured on one 336-atom Pt slab at 300 K (one Maxwell-Boltzmann draw) as 5.8e-7 relative.

Cell numbers are the =boxl= and =angles= lines, the extended XYZ =Lattice= string, the PDB =CRYST1= record, the CON-bin cell column, and the cell or lattice an API caller passes to a builder or a column writer. A float token is an optional =+= or =-=, a significand with at least one digit, an optional fraction (a leading dot is allowed), and an optional exponent. An integer token is one or more ASCII digits and nothing else.

* Conformance
:PROPERTIES:
:CUSTOM_ID: conformance
:END:

A product is a reader, a validating reader, a writer, a consumer, or a round trip @@rst::cite:t:`w3cTestGuidelines`@@.
Optional compression is =CON-compress.4= and =CON-compress.5=.
Passing is the conformance corpus: the verdict, the class, and the line the manifest names.

- CON-profile.1 :: MUST :: A reader MUST apply every requirement this document addresses to a reader, in every mode.
- CON-profile.2 :: MUST :: A validating reader MUST be a reader. =validate= true MUST add the checks of =CON-validate.4= and MUST NOT relax a check that applies in every mode.
- CON-profile.3 :: MUST :: A writer MUST apply every requirement this document addresses to a writer.
- CON-profile.4 :: MUST NOT :: A consumer MUST NOT be required to apply a reader check. A consumer MUST NOT replace the velocity time unit. That rule is =CON-units.15=.

The major version moved from 3 to 4 because the meaning of =units.time= changed.

Version 3.0 defined the old meaning in =CON-units.8= and =CON-units.9= of that text: in versions 1, 2, and 3.0, velocities MUST be read as =units.length= per the natural time unit, and length is angstrom when =units.length= is absent. Any =units.time= on versions 1, 2, and 3.0 MUST NOT be trusted.

Version 3.1 defined the new meaning in =CON-units.10= of that text: from minor 1 onward, =units.time= MUST be authoritative for velocities.

That change altered the meaning of an existing key inside one major, so it is not a minor revision (=CON-status.5=). Major 4 carries the version 3.1 meaning: =units.time= is authoritative for velocities. Every minor of major 3 carries the version 3.0 meaning: velocities are =units.length= per the natural time unit, and =units.time= MUST NOT be trusted. A reader of major 3 MUST NOT apply =units.time= and MUST NOT reject a velocities section for an absent =units.time=.

The specification identity is major.minor.patch (=CON-status.3=). Any change to normative text increases at least the patch (=CON-status.4=). This text is 4.0.4.

Version 3.1, dated 2026-10-11, is the last stable text before major 4. Every normative change since that text is one of the following, and each is carried by the version named with it.

Changes in 4.0.0:

- =units.time= is authoritative for velocities in major 4 (=CON-units.10=). Every minor of major 3 keeps the version 3.0 meaning (=CON-units.8=, =CON-units.9=). The change of an existing key is why the major increased (=CON-status.5=).

=line-end= is LF, CR LF, or a CR that is the last byte of the input.
The end of the input is also a =line-end=, and only the last line may use it, so an omitted ending does not join two lines.
A CR that is not a =line-end= is a character of its line, including a title and line 5.
Line 9 is =mass-line=, the float masses of CON-header.3, and it may be empty.
Lines 3 and 4, line 8, the masses and a coordinate row may begin with spaces or tabs.
After the last frame, a tail line is spaces, tabs, form feeds and carriage returns, and that last line may omit LF (CON-frame.1).
Section blocks follow the coordinate blocks in the order of the =sections= array.
A JSON object does not repeat a name.
=MeV= and =meV= are different unit names.

* Informative annex
:PROPERTIES:
:CUSTOM_ID: informative-annex
:END:

This annex is not normative. It records names used by one implementation and keys one importer writes. A conforming reader follows the numbered clauses, not this annex.

One C ABI returns an IEEE NaN from a getter when a number is absent. =rkr_frame_energy= does this when the frame has no =energy= key. That NaN is an in-memory sentinel. It is not a CON number, and =CON-num.4= forbids writing it to a file.

The default numeric text of a conforming writer is the mode that =CON-num.6= requires: parsing the written token returns the same binary64 value. A fixed-decimal mode is =CON-num.7=. The C binding's writer for the default mode is =create_writer_from_path_round_trip_c=.

The error table names the class a reader reports when a row does not have the number of fields that row requires, which is the failure =CON-section.13= and =CON-num.9= require.

The keys =chemfiles_atom_names=, =chemfiles_atom_types=, and =chemfiles_atom_properties= are not reserved. One importer stores display names, atomic types, and per-atom properties under those keys, in that importer's atom order. A reader preserves them as unknown keys under =CON-line2.8=. A later revision that reserves an extension namespace does so by a minor that adds keys (=CON-status.6=), and does not treat these three spellings as part of the core language.
