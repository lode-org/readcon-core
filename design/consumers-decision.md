Five independent ballots, one persona each, were read in full:

The vote is unanimous, 5–0. Every ballot ranks A above B above C, and every ballot expected the others to pick A. The mean confidence is 0.832. The critiques those ballots answered are in `design/consumers-critique.md` (`860571e`). The designs are `design/consumers-A.md` (`97d352e` on `design/consumers-a`), `design/consumers-B.md` (`06044cc` on `design/consumers-b`), and `design/consumers-C.md` (`80cf36a` on `design/consumers-c`).

A is the base. The plan below takes that base and adopts the pieces the ballots name from B and from C. The eight factual errors in the critique hold in every ballot, and each one is corrected in the work items. This document does not tag or publish anything.

## What A is

No new crate. Consumers call readcon-core 0.17.1 and readcon-db 0.1.9. The spelling is `ConFrameWriter::new`: RoundTrip, canonical left off. eOn deletes `kConPrecision` and `kConvelPrecision`. New corpus ids are FNV-1a of the canonical path only, shared by the C++ mirror and `eon/concorpus.py`. Streaming appends buffer up to 64 serialized frames and extend that batch once, which is the call shape that can emit a `0xFD 0x03` group. `dlopen` stays. A missing `libreadcon_db` skips and does not fail the AKMC step. Windows keeps the mirror compiled out. The `.con` file is the resume. Forces stay opt-in. `matter2con` stays `with_velocities=false`. `mode_cp.dat`, `eon_hess_ckpt`, the binary `RESTART`, rgmin's conjugacy `Restart`, and `BandSession::restart` stay on the writers they have. chemparseplot `con_io` is the Python facade. rgpycrumbs does not grow a second writer. Neither plot package opens LMDB. The three `chemparseplot.api` names exist before rgpycrumbs moves. rgmin and rgsaddle default and `capi` builds do not link readcon. seams moves last, both wraps in one commit.

## Grafts the ballots require

### From B

- `eon/process_catalog.py` stops passing `17`. The saddle text is `write_con_string([frame])` with precision omitted, the same RoundTrip spelling `savecon` already uses once the wheel is 0.17.1. Canonical stays at the writer default. B's `canonical=True` does not travel with this line.
- `displacement.con` is a new geometry. `seed_dimers` clears the calculator on the displaced atoms before `ConFrame.from_ase`, writes with precision omitted and canonical left off, and the reloaded file has no forces section (`has_forces` false). Positions equal the peak plus `0.01 * mode`, compared with `array_equal`. `pos.con` stays `con_io.write_con_frames` of the parsed peak frame. `direction.dat` stays `np.savetxt` with `fmt="%18.12f"`. `frame_with_positions` is the edit that keeps `dx` / `fx` / `sx` when a splitter only translates, or when energy changes through `frame_with_energy`. It is the wrong helper for this seed. A rotation or a reorder leaves forces, displacements, and spreads unset, and eOn recomputes. `restoreFileForces` would trust peak forces on the moved geometry and skip the potential.
- One golden byte string, generated by `ConFrameWriter::new` on the tagged 0.17.1 writer. Downstream jobs download those bytes and `cmp` them. A consumer that vendors a private copy and re-encodes the expected text fails. In readcon-core, a writer built with precision 17 is asserted different, once, on a value RoundTrip preserves and 17 digits do not.
- The cpmdc import path calls `cpmdc_restart_set_cell` together with `cpmdc_restart_set_coordinates` and `cpmdc_restart_set_velocities`. The conversion multiplies by `CPMDC_RESTART_ANGSTROM_PER_BOHR` (`0.529177210859`) on the way to angstrom and divides by that same macro on the way back, matching `print_triples` and `patch-positions`. B's factor `1/0.529177210859` is the reciprocal (OpenCPMD `cnst%fbohr`) and does not travel. `CPMDC_BOHR_TO_ANGSTROM` (`0.529177210903` in `src/cpmdc_params.h`) does not travel. The coefficient records stay byte-identical to the input. The test states that the original bohr bits do not survive the trip. The cell graft is B's alone: C's `cpmdc_restart_apply_con` names `set_coordinates` and `set_velocities` and does not name `set_cell`. The critique's sentence that both B and C patch the cell does not match the designs.
- rgmin's ASE adapter keeps raising on `restart=`. `python/rgmin/ase.py` is unchanged. `tests/python/test_ase.py` `test_todict_and_restart_refusal` stays the proof, on its JSON fixture. A `.con` path that moves atoms would be a second meaning of `restart` in the class that refuses one today.

Dynamics velocities stay off this cutover, which is the boundary B's own dynamics resume would have crossed. `matter2con` remains `with_velocities=false`. An old `dynamics.con` remains a geometry history. ## The eight errors, corrected

1. **readcon-ops.** A describes `frames.py`, `_from_conframe`, `as_frame`, `_is_protocol`, `_is_conframe`, and `lengths_angles_to_cell`. The eOn pin `4d7881a` is `src/readcon_ops/match.py` and `wulff.py`. The public names are `identical`, `internal_motion`, `rotate`, `rotational_match`, `spacegroup`, and `wulff_vertices`. A frame is any object with `r`, `box`, `names`, `copy`, and `__len__`. `eon/structure.py` `Structure` already has `r`, `box`, and `names`, and `eon/atoms.py` passes that object to `spacegroup` and `rotational_match`. Ops `main` `39787cc` does contain `frames.py` and `as_frame`. It is a sibling of the pin, not a descendant: both have parent `83865d8`, and `39787cc` drops the `np.ascontiguousarray` conversion of positions and atomic numbers that `4d7881a` passes into IRA. **Correction:** drop the ops section. The pin stays at `4d7881a`. Do not add `cell` to `Structure`.

2. **seams handle exchange.** A says seams frees an `rkrdb_get_frame` handle from the db's core, and prefers `rkrdb_get_positions`. `sinp::readConCorpus` calls `rkrdb_get_frame_text`, closes the database, parses with seams' `read_con_string_iterator`, then `cloudFromHandle` on that local handle and `free_rkr_frame`. The tree has no `rkrdb_get_frame` call. The `meson.build` comment is a constraint, not a description of a live exchange. The live bug is real: `cloudFromHandle` keeps the SoA only when `xyz[1] == atom.y` and `xyz[2] == atom.z`, and otherwise copies `atom.x/y/z`. **Correction:** keep the text path. Delete the heuristic in the wrap bump. Do not switch `readConCorpus` to `rkrdb_get_positions`. The coordinate check is `rkr_frame_xyz_f64` of the frame seams parsed.

3. **extend symbols.** A treats `rkrdb_extend_trajectory` and a batch-frame dlsym as something 0.1.9 might grow, and soft-skips when `rkrdb_extend_trajectory` is missing. Both `rkrdb_extend_trajectory_frame` and `rkrdb_extend_trajectory` are in `include/readcon-db.h` on tag `v0.1.8` (`0001a2c`) and on `0725c94`. Rust `ConCorpus::extend_trajectory_frames` is on main. Python `ConCorpus.extend_trajectory` binds `extend_trajectory_path_units`. What is absent is `extend_trajectory_str` / `rkrdb_extend_trajectory_str`. A's account that Python `append_trajectory_frames` imports the installed wheel and calls `write_con_string` is right. **Correction:** use the existing path symbol, or the new string symbol, on a 64-frame batch. Do not describe those two C entry points as future. Soft-skip only when the loaded library actually lacks a symbol. Add the string form in 0.1.9. A path extend of a growing movie duplicates frames, so the mirror does not point `extend_trajectory` at the movie it is still appending.

4. **Bohr factor.** B converts bohr to angstrom with `1/0.529177210859`. `include/cpmdc_restart.h` defines `CPMDC_RESTART_ANGSTROM_PER_BOHR` as `0.529177210859`. The comment's `1/0.529177210859` is OpenCPMD `cnst%fbohr`, the reciprocal. `print_triples` multiplies by the macro. `patch-positions` divides by the macro. `CPMDC_BOHR_TO_ANGSTROM` `0.529177210903` is a different constant. **Correction:** multiply by `CPMDC_RESTART_ANGSTROM_PER_BOHR` on the way to angstrom, divide by it on the way back. Do not use the params-header constant.

5. **Canonical key order.** B assigns the client/server byte split to canonical key order and turns `canonical=True` on. The split is `DecimalPlaces(17)` and `DecimalPlaces(6)` against RoundTrip. `header.metadata` is a `BTreeMap`. `refresh_metadata_cache` inserts keys from that map and writes sections in a fixed order. `self.canonical` only disables the metadata cache and is not read while the bytes are emitted. On 0.17.1 the flag does not produce a second spelling, and the comment says it will sort keys and reorder sections the day it is implemented. Python writers that omit precision already leave `canonical=false`. The production Python path that still passes a precision is `eon/process_catalog.py`: `readcon.write_con_string([frame], 17)`. **Correction:** that call becomes `write_con_string([frame])` with precision omitted and canonical left at the default. Do not pass `canonical=True` on the client, on `process_catalog`, on `write_con_frames`, on `atoms_to_con`, on `write_band`, or on any rgpycrumbs `write_con`.

6. **One-frame extend does not group.** B says a dynamics or band trajectory fills a 64-frame group, and its eOn change calls `rkrdb_extend_trajectory_frame` once per frame. `group_prepared` returns when `prepared.len() < 2`. `pack_aligned` emits `0xFD 0x03` only for a run with more than one frame inside that call, and only when the group is shorter than the per-frame values. It does not join a later call to a group already committed. **Correction:** buffer up to 64 serialized frames and extend that batch once. Do not describe a one-frame extend as grouping. Do not describe the next stored band as joining a previous group's run.

7. **`coords_array` is the atom list.** C names `coords_array`, `velocities_array`, and `forces_array` as the numeric read of a parsed frame, and says `to_ase` uses `coords_array`. Those three methods walk `Atom` fields, which is why an in-place edit shows up. The SoA copies are `xyz`, `vel`, and `frc` (`positions.f64_slice()` when `inner` is set). `to_ase` (`ase_from_pyconframe`) copies `atom.x/y/z` and does not call `coords_array`. `atom_ids_array`'s docstring says "atomic numbers"; the values are `atom_id`. `from_ase` and `frame_with_energy` leave `inner` unset, so a later `xyz` on those objects falls through to the atom walk. C's offer to retarget `coords_array` onto the SoA if a witness fails would collapse the two contracts. **Correction:** witnesses use `xyz` / `vel` / `frc` and `rkr_frame_xyz_f64`. Leave `coords_array` as the atom-list view. Do not retarget it. `eon/structure.py` `from_conframe` takes `frame.xyz` for coordinates. Ids stay on `atom_ids_array`.

8. **Identical re-append is `TrajExists`.** C says identical stored text makes `append_trajectory_str` succeed. `commit_prepared` returns `TrajExists` as soon as `traj_meta` has the id, with `replace_meta = false` and no byte compare. `workflow_dedup_identical_ingest` stores one file under two trajectory ids and dedups in `unique_frame_keys`. eOn's mirror ignores the status, so a second insert of the same id fails quietly today. **Correction:** do not specify identical-text success. Do not pretend append replaces frame 0. A replace-frame-0 API is a later call, with a caller, and it is not this release. A second `append_trajectory_str` of an existing id is `TrajExists` even when the text matches. New runs use a new id or a new `readcon.db`. Do not rehash a live campaign during a job. One id rule: path only, for checkpoints and for movies.

## Why this order

The release ballot numbered chemparseplot, then rgpycrumbs, then rgpot, then rgsaddle, then cpmdc, then seams, and left rgmin off the numbered path. The order in the work section is the one this plan ships: readcon-db `0.1.9` prep, eOn client and server, cpmdc, rgpot, rgsaddle, the rgmin optional feature, chemparseplot, rgpycrumbs, seams last.

rgpot's own parser deletion does not wait on chemparseplot's api names. rgpycrumbs does wait on those names, because `eon/plt_con.py` imports them at module level. cpmdc's bridge waits on the `0.17.1` C ABI, which is why it can follow eOn without waiting on the mirror. eOn still lands before any consumer whose witness is an eOn-written file. The core tag sits in front of the db tag even though the numbered list starts at the db prep: a `0.1.9` crate that pins `readcon-core = "=0.17.1"` cannot publish before that crate is on the registry.
