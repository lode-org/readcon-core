This note records a spot-check, five independent critiques, and a neutral comparison.

No persona casts a ballot here. A ranked vote counts only from a later session that holds one persona and one ballot. Nothing below is a tally or a merged plan.

The bar used while reading, from Rohit: a feature counts once a production caller uses it; the working behavior is the baseline a change has to beat; the result has to be the current state of the library, which is readcon-core 0.17.1; fix the code that is wrong rather than describing a fallback that hides it.

## Factual errors

1. **A specifies a readcon-ops adapter that the pinned tree does not contain.** eOn's pixi rev `4d7881a` is real. At that commit the package is `src/readcon_ops/match.py` and `wulff.py`. The public names are `identical`, `internal_motion`, `rotate`, `rotational_match`, `spacegroup`, and `wulff_vertices`. A frame is any object with `r`, `box`, `names`, `copy`, and `__len__`. There is no `frames.py`, `_from_conframe`, `as_frame`, `_is_protocol`, `_is_conframe`, or `lengths_angles_to_cell`. `pyproject.toml` depends on numpy, spglib, and minimage, and the package docstring says it does not read a file. `eon/structure.py` `Structure` already has `r`, `box`, and `names`. `eon/atoms.py` passes that object into `spacegroup` and `rotational_match`. A's ops section, including the warning about adding `cell` to `Structure` and the proposed `as_frame` bit test, describes an API that is not in the pin.

2. **A describes a seams handle exchange the current decoder does not perform.** `sinp::readConCorpus` calls `rkrdb_get_frame_text`, closes the database, parses the text with seams' `read_con_string_iterator`, then `cloudFromHandle` on that local handle and `free_rkr_frame`. The tree has no `rkrdb_get_frame` call. The comment in `meson.build` is a constraint: the db crate vendors its own core, and seams does not free that handle with this build's `libreadcon_core`. The live bug A does name is real: `cloudFromHandle` keeps the SoA only when `xyz[1] == atom.y` and `xyz[2] == atom.z`, and otherwise copies `atom.x/y/z`.

3. **A treats a one-frame extend symbol as something 0.1.9 might grow.** `rkrdb_extend_trajectory_frame` and `rkrdb_extend_trajectory` are in `include/readcon-db.h` on tag `v0.1.8` and on `0725c94`. Rust `ConCorpus::extend_trajectory_frames` is on main. What is absent, and what C correctly asks to add, is `extend_trajectory_str` / `rkrdb_extend_trajectory_str`. Python `ConCorpus.extend_trajectory` is `extend_trajectory_path_units`. Python `append_trajectory_frames` imports the installed `readcon` wheel and calls `write_con_string`. That part of A is right.

4. **B's Bohr-to-angstrom factor is the reciprocal of the constant the restart tool already uses.** `include/cpmdc_restart.h` defines `CPMDC_RESTART_ANGSTROM_PER_BOHR` as `0.529177210859`. The comment says this matches OpenCPMD `cnst%fbohr`, which is `1/0.529177210859`. `print_triples` multiplies by the macro to print angstroms. `patch-positions` divides by the macro to store bohr. B's `export-con` step says to convert bohr to angstrom with ``1/0.529177210859``. A second constant, `CPMDC_BOHR_TO_ANGSTROM` `0.529177210903`, sits in `src/cpmdc_params.h` and is a different number. A and C name the restart macro and multiply by it.

5. **B assigns the client/server byte split to canonical key order.** The client writes through `ConFrameWriter(path, compression, precision)` with `kConPrecision = 17` and `kConvelPrecision = 6` (`client/ConFileIO.cpp`). That is `FloatFormat::DecimalPlaces`. `eon/fileio.py` `savecon` calls `write_con_string([frame])` with precision omitted. `chemparseplot` `write_con_frames` and the rgpycrumbs `write_con` calls do the same, and the Python default is `canonical=false`. `FloatFormat::default` is `RoundTrip`. `create_writer_from_path_c` passes `precision = None`, which constructs `ConFrameWriter::new`, the same RoundTrip default. `header.metadata` is a `BTreeMap`. `refresh_metadata_cache` inserts keys in that order and writes sections in a fixed order. `self.canonical` turns off the metadata cache and is not read by the byte path. On 0.17.1, `canonical=True` does not produce a second spelling. The production Python path that still passes a precision is `eon/process_catalog.py`, `readcon.write_con_string([frame], 17)`. A and C do not name that call. B does, and then also turns canonical on, which is a separate and currently empty switch.

6. **B says a dynamics or band trajectory fills a 64-frame group, and its eOn change extends one frame at a time.** `group_prepared` returns immediately when `prepared.len() < 2`. `pack_aligned` emits `0xFD 0x03` only for a run with more than one frame inside that call, and only when the group is shorter than the per-frame values. `rkrdb_extend_trajectory_frame` prepares one frame. A movie appended one frame per step stays a sequence of `0xFD 0x01` or raw UTF-8 values. A full-file `append_trajectory_str` / `rkrdb_append_trajectory` of many frames in one call can group. A one-frame extend cannot. A's 64-frame buffer is the design that matches the codec. C's `trajectory_append` groups when the caller hands it an aligned run in one call. eOn's `matter2con(..., append=true)` hands it one frame.

7. **C names the atom-list walk as the numeric read of a parsed frame.** `ConFrame.coords_array`, `velocities_array`, and `forces_array` always copy `Atom` fields. The SoA copies are the getters `xyz`, `vel`, and `frc`, which use `positions.f64_slice()` when `inner` is set. `disp` and `spread` walk atoms even as getters. `to_ase` (`ase_from_pyconframe`) copies `atom.x/y/z`. It does not call `coords_array`. `atom_ids_array`'s docstring says "atomic numbers"; the values are `atom_id`. On a frame just built by `from_con_frame`, the atom fields were filled from the parse, so a fresh-frame compare can pass while an edited frame diverges. C's risk note that the bits might differ, and that the library can be fixed later if a witness fails, leaves the wrong accessor in the contract.

8. **C says an identical re-append is success.** `append_trajectory_str` commits with `replace_meta = false`. `commit_prepared` returns `TrajExists` as soon as `traj_meta` has that id. The bytes are not compared. `workflow_dedup_identical_ingest` stores one file under two trajectory ids and dedups in `unique_frame_keys`. eOn's mirror ignores the return of `rkrdb_append_trajectory_str`, so a second insert of the same id fails quietly today. Identical-text success would be new code in front of that call.

## Persona 1: eOn production maintainer

I keep a preempted AKMC or minimization alive. The file a job already opens is the resume. The corpus is a copy. A missing `libreadcon_db` must not fail the step. Windows already compiles the mirror out. I will not take a link line that turns that soft failure into a loader error, and I will not put a second `libreadcon_core` on `PATH`. That abort (`STATUS_ENTRYPOINT_NOT_FOUND`) is already written into `client/meson.build`.

What production resumes today is small, and it is the baseline.

- A minimization or Monte Carlo with `main.checkpoint` loads `pos_cp.con`. `relaxMatter` rewrites `{prefix}_cp` from the coordinates it has, and from cached forces only when the potential is clean and `write_con_forces` is on. L-BFGS pairs and FIRE velocity start empty. That empty stepper is the resume we ship. A design that starts writing optimizer pairs into a CON section changes every reader, including seams, to parse a file the stepper does not need.
- A saddle search loads `displacement_cp.con` only together with `mode_cp.dat`. The mode is `%.17g` text from `saveMode`. `direction.dat` in the seed tools is the same kind of sidecar. Leave both.
- A Hessian resumes from `eon_hess_ckpt`. `modes.con` is a result (displacements), as `instanton_centroid.con` is a result (spreads). Neither is the column checkpoint.
- Dynamics has no mid-run resume. `dynamics.con` and `final.con` are `matter2con`, which passes `with_velocities=false`. Velocities exist on the `matter2convel` path at precision 6. A new "resume dynamics from the last movie frame, with velocities" is a new job behavior. It can land after the writer cutover. It does not belong in the commit that changes every checkpoint byte.

The writer cutover itself is required. The client spells numbers as 17 and 6 decimal places. The server `savecon` already omits precision, so on a 0.17.1 wheel it is RoundTrip. Those two files stop matching the moment the wheels move and the wrap stays on 0.16.0. `process_catalog.py` still passes `17`. That call writes the saddle text the catalog reloads. Any eOn change that forgets it leaves the production catalog on `DecimalPlaces`. A and C forget it. B names it.

Forces stay opt-in. The client comment says ASE-class readers reject a forces section, and `restoreFileForces` will trust a forces section that is present. A checkpoint that grows a forces section because the writer learned how is a behavior change on every minimization. RoundTrip of the sections we already emit is the change. Emitting sections we currently suppress is a different change.

Append safety stays. A gzip or zstd movie is rewritten as a whole file because a concatenated gzip member is invisible on read. An uncompressed tail this process did not write is parsed first, and a parse failure returns `AppendError` with the bytes untouched. C keeps that check. A keeps the scratch file and is right that RoundTrip does not need a new buffer API. Deleting the scratch is a later FFI.

The mirror's content-hashed id and its refusal to run on a streaming append are why movies never become one trajectory. A path-only id, shared by the C++ and Python FNV (same offset, prime, and canonical path bytes, no NUL), is the fix for the id. The 64-frame group is a property of one call that contains an aligned run. Buffering up to 64 serialized frames and extending once, which is A's mirror, matches `group_prepared`. Calling `rkrdb_extend_trajectory_frame` once per step, which is B's mirror, stores single frames forever. C's crate has the same limit when `matter2con` passes one frame. The buffer sits under the append lock that already forbids a potential evaluation. A crash may drop unflushed corpus frames. The `.con` file remains the copy the next process opens. The AKMC step still succeeds when `dlopen` fails. I will not fail a production step to prove a group.

Old `readcon.db` directories were keyed by path plus text. A new path-only id does not see those rows. Leave the old directory readable. Do not rehash it inside the client during a run.

`MassMismatch` is the builder refusing two masses for one symbol, which is what CON line 9 already stores as one mass. Collapse to the first mass of the symbol before `build`, log it, and test two Cu masses. A silent in-memory mass that differs from the file is the bug.

`InvalidUnits` on a velocity frame without `units.time` must come back as `IoStatus::InvalidArgument`, which `frame_from_matter` already catches. The natural time label is `(amu*angstrom^2/eV)^0.5`. An abort on a convel write is a failed HPC step.

A's ops work does not belong in this cutover. The comparison package at the pin we already run takes `Structure` as it is. Churning that pin to chase `frames.py` is a release with no caller.

C's deletion of `dlopen` in favor of a linked `readcon-xfer` makes the corpus a load dependency of `eoncbase` and stacks a second core into the process. The writer we need is the `ConFrameWriter` constructor that takes no precision. That symbol is in the core we already link. A new repository on the client link line is a regression in how the binary starts, paid before a single checkpoint byte improves.

B's dynamics resume, in the same change as the spelling cutover, couples a new file (`dynamics.con` last frame, with velocities) to the approval regeneration. I want `ApproveConFileIO` to move once, old 0.16 fixtures to still load, and one existing short minimization to keep the energy tolerance it already uses. A new dynamics campaign can start on the new writer after that. An old movie stays a geometry history. B says that last sentence, and then implements the resume in the same step. Split them.

Seams is the reader I must not break, and it is last. Its current corpus path already re-parses text with its own core. Pointing it at `rkrdb_get_positions` during the wrap bump can observe a cooked blob the corpus comment says is not the file. The coordinate bit check belongs on `rkr_frame_xyz_f64` of a frame seams parsed. The `xyz[1] == atom.y` heuristic is a real mis-read on some frames and can die in that same bump, after the fixtures load.

cpmdc's binary `RESTART` stays the wavefunction. A CON sidecar that multiplies by the reciprocal of `CPMDC_RESTART_ANGSTROM_PER_BOHR` writes a file the client will treat as angstroms and will not. B's factor fails this bar. The coefficient records stay byte-identical. The original bohr bits do not survive a trip through angstroms, and the test has to say so.

Ballot: withheld. A later session casts this persona's ranked vote.

## Persona 2: Rust numerics and API designer

rgmin and rgsaddle are libraries a host calls. eOn's Xtsci optimizer and `XtsciBand` are those hosts. A file format inside `Solver::step` or `BandSession::restart` couples a conjugacy reset to a parser. Both names already mean "drop stepper memory." A geometry file needs another name.

rgmin has no structure type. `Report` is a scalar and a `3N` vector. Symbols, masses, and a cell are host data. The ASE adapter raises on every `restart=`, and the test that locks that uses JSON. The C ABI speaks DLPack through `dlpk`. Default CI does not link readcon. That link line is the regression to protect: `cargo test` and the `capi` row must stay free of `readcon_core`.

rgsaddle reads one frame, copies positions with `as_f64_row`, and has a local triclinic rebuild beside `lattice_vectors()`. The `readcon-db` feature is a comment. Default CI builds `--features capi` only. `MolecularFrame` has positions, masses, and a cell. It does not have symbols. A CON writer that invents `X` is a conforming-looking file with the wrong species. The signature takes the symbols, in the same order as the coordinate vector.

What I want from an API, in this order:

- The read pin moves to 0.17.1 because 0.14 accepts values 0.17.1 rejects (NaN, Inf, a non-integer column 4). `tests/io_cells.rs` is the cell regression. Fix the fixture. Do not relax the parser.
- `cell_from_header` calls `cell_vectors` / `lengths_and_angles` and deletes the local `cy` / `cz_squared` block. One formula.
- A write function is a free function the host calls. `Solver::step` and `rgsaddle_band_step` do not open paths. `BandSession::restart` stays the in-memory wipe. The C surface `rgsaddle_band_restart` stays that wipe.
- Symbols and masses are arguments. Length mismatch is an error. A non-finite `Report.value` omits the energy key, because `set_energy` of a non-finite value is `NonFiniteValue`.
- The position buffer is the frame's f64 slice, one copy into the owned `Array1` the stepper mutates. A per-row `as_f64_row` into a second `Vec<[f64; 3]>` is the copy to delete. `positions_mut` on the way out is the matching write. `build_with_permutation` matters when a parallel array (a mode, a band image in Matter order) has to survive species grouping. The host that keeps that array uses the map. A writer that only has coordinates and a symbol vector in the same order does not need a second sort to rediscover it.
- `readcon-db = "0.1"` can resolve to the 0.1.8 tag and pull `readcon-core = "=0.16.1"` next to a direct 0.17.1 pin. The feature that exists and has no call should pin `=0.17.1` or leave the dependency out until the call exists. A floating `0.1` is a downgrade waiting for the resolver.

A puts an optional `readcon` feature on rgmin, exact `=0.17.1`, with `write_checkpoint` and `read_checkpoint` in a module the default build does not compile. `Report` gains no path field. The minimizer does not gain a required parser, and it does not gain LMDB. That is the right shape. The byte test against a shared golden has to pass symbols, masses, the cell, the fixed mask, and the header. `Report` alone cannot build `restart_exact.con`. The function's signature already says so. Keep the ASE adapter raising. A `.con` path that starts moving atoms is a second meaning of `restart` in the same class that today refuses JSON.

A's rgsaddle `write_restart`, `write_band`, and `store_band` are additive, gated, and off the `capi` job. `store_band` calls `append_trajectory_frames_with_float_format` once, so a band under 64 images can group when the group shrinks. That matches the codec, and it is still a unit-test caller until eOn or another host calls it. I will not describe it as a production corpus. The read-side pin and `frames_from_con` / `read_nth_frame` are the part a host can use as soon as the golden exists. `read_all_frames` to keep image `k` is the call to delete.

B leaves rgmin's `Cargo.toml` alone and writes the host contract next to `Lbfgs::with_capacity`. The ASE refusal test stays the proof. That matches the library as it is shipped: eOn and rgsaddle own the geometry file, and a writer inside rgmin has no production caller until one of them uses it. B's rgsaddle API is `frames_from_con` plus `write_band_con`, with `BandSession::restart` unchanged and the C ABI left without a disk format. The optional corpus append waits on the db release. I can accept a crate that does not grow a dependency for a file the host already writes. I do not accept `as_f64_row` in a loop as the long-term copy, and B keeps that loop. The 0.17.1 slice is the fix, and it is independent of whether the write function lives in rgmin or in the host.

B's `canonical=True` on `write_band_con` is the wrong switch. The Rust default `ConFrameWriter::new` is RoundTrip with canonical off, and the flag does not change the bytes. The rgsaddle writer should be `ConFrameWriter::new`. A test that the precision-17 constructor differs belongs next to the golden, once, in readcon-core.

C replaces rgsaddle's `readcon-core` dependency with a new `readcon-xfer` crate and turns the unused `readcon-db` feature into an alias. `frame_from_con` then depends on a facade whose job is restart, checkpoint, and trajectory. The header, the masses, and `lattice_vectors` are still what the function needs, so the facade has to hand back a `ConFrame` and the saddle code keeps doing the real work. The chemfiles feature is left as "a later change." That is an unused flag. rgmin grows `src/geom.rs` behind `xfer`, which is the same optional-module idea as A, and then the Python ASE adapter starts honoring a `.con` restart and appending a `.con` trajectory. The Rust default row stays clean. The Python behavior does not. `test_todict_and_restart_refusal` survives only because its fixture is JSON. A caller who passes a path and expects the raise will see positions move and FIRE or LBFGS start with empty history. Documenting the wheel as lazy does not make that the old contract. The C optimizer header stays free of CON in all three designs. Keep it that way. A C program that wants a file links the core, or links whatever crate actually writes, on its own.

`positions_dlpack` exists on the builder and the frame. rgmin already speaks DLPack. That is an interop for a host that has a tensor. It is not a reason to put CON inside `rgmin_minimize`, and it is not a reason to copy into a fresh array before the export. A's note on that is the right limit.

Ballot: withheld. A later session casts this persona's ranked vote.

## Persona 3: Python downstream user

I plot and I write the files eOn reads next: `neb.con`, `pos.con`, `displacement.con`, `centroid.con`, `ipath_*.con`. chemparseplot is the library. rgpycrumbs is the CLI. ## Persona 4: File-format and reproducibility reviewer

The authoritative record is the CON UTF-8. A corpus is an index of that text. A cooked numeric blob is a cache, and `get_positions` says it is not equivalent to the file. A restart that reads the cache can disagree with a restart that reads the file. xxh3-128 is over the UTF-8, so the hash follows the text and ignores the compression. The 64-frame group is an internal value. Callers keep using `(traj_id, frame_idx)`. `get_frame_text` is the conforming read. `rkrdb_get_positions` is the wrong witness for a bit-exact restart.

RoundTrip is the spelling. `FloatFormat::default` is RoundTrip. The no-precision C constructor, the explicit round-trip C constructor, Rust `ConFrameWriter::new`, and Python `write_con` / `write_con_string` with precision omitted all land there. `DecimalPlaces(17)` and `DecimalPlaces(6)` are different spellings. eOn uses both today. `process_catalog.py` still requests 17. Canonical mode is documented to sort keys and reorder sections. The metadata map is already a `BTreeMap`, section order in `write_frame` is fixed, and the flag is not consulted while emitting bytes. A conformance rule that says "set `canonical=True`" standardizes a switch that currently changes nothing and will change bytes later if someone implements the comment. Leave it off. Add one test, in readcon-core, that a writer built with precision 17 differs from `ConFrameWriter::new` on a value RoundTrip preserves and 17 digits do not. Signed zero and a subnormal-scale value (`f64::from_bits(1)` or `f64::MIN_POSITIVE` taken from bits, not from a short decimal) belong in that fixture. A tolerance on energy is a dynamics regression. It is not a restart check.

The fixture is one byte string, generated by `ConFrameWriter::new` on 0.17.1 and consumed as bytes. It needs two species so grouping is visible, one mass per symbol, a non-orthogonal cell, a fixed axis, a finite energy, a force row, and a velocity variant that carries `units.time = (amu*angstrom^2/eV)^0.5`. Line 1 `Generated by eOn` pulls the client header into the comparison. Downstream jobs download those bytes. A consumer that vendors a private copy and re-encodes the expected text will go green while the writer drifts. B's rule on that point is the one I want. A's per-repo checked-in copy is acceptable only if the bytes are the artifact and the test is `cmp`, not a second encoder.

Minor 1 and `default_v3_units_json()` are part of what `build` stamps. A velocity frame without `units.time` fails closed. Two masses for one symbol fail `MassMismatch`. Those are conformance, and the callers collapse or set the label before `build`. A test owns each error. Old 0.16 files still have to parse. A float fixed-flag, a NaN, or `time: fs` on a minor-1 velocity frame fails at resume. Repair the file. Do not widen the parser.

`get_frame_text` of a grouped frame equals the stored UTF-8. A raw untagged value from an older database still decodes. `select` keys and the xxh3 index do not move when the value encoding changes, because the hash is over the text. Repacking a live campaign in place during a run is out of scope. `set_trajectory_units` rewrites stored numbers. It is not a way to "fix" a restart corpus after the fact.

A's preference that seams call `rkrdb_get_positions` avoids a handle free that the current code does not perform, and it steps onto the cache. The current path, text then seams' own parser, is the one that compares to the file. Keep it through the wrap bump. Delete the first-atom float heuristic on its own, with a bit check on coordinates. `applyConCell` stays the seams box. Replacing it in the same commit as the wrap makes a sheared-cell failure ambiguous.

C's three equalities are the right statement: the UTF-8 from the Rust writer, from `write_con_string`, and from `get_frame_text` after a group decode; the xxh3-128 of that UTF-8; the f64 bits from `rkr_frame_xyz_f64` and from the Python column getter. C then points the Python side at `coords_array`. That fails the third equality as a column check. The getter is `xyz`. C also refuses `get_positions` for restart, which is correct, and says a later cook must keep using `get_frame`. Hold that.

C's identical-text success is not the database contract. A second `append_trajectory_str` of an existing id is `TrajExists` whether or not the text matches. A checkpoint protocol that needs replace-frame-0 needs a new call. Pretending append already replaces, or already succeeds on identical text, writes a conformance test the library will fail.

Bohr is outside the CON equality. The CON file holds the f64 produced by multiplying bohr by `CPMDC_RESTART_ANGSTROM_PER_BOHR`. RoundTrip preserves that f64. It does not preserve the original bohr bits, because the multiply is a new value and the inverse divide is not an exact inverse for every input. The binary test is `memcmp` on the records the patch did not touch, plus a bit compare of the CON against the converted f64 computed in one place. B's reciprocal fails the unit, so the CON would not be the angstrom file eOn reads. There is a second constant in `cpmdc_params.h` (`0.529177210903`). The restart bridge uses the restart macro. A does not patch the cell back; B and C call `cpmdc_restart_set_cell`. A geometry step that updates the cell in the CON and leaves the binary cell records alone has two cells. The coefficient `memcmp` still passes. The cell has to be in the contract.

H5MD export already lives in readcon-db. None of these designs should grow a second restart container. The CPC-style artifact is the CON fixture and the group-decode equality. Trajectory history stays addressable by frame index. Optimizer state, `mode_cp.dat`, `eon_hess_ckpt`, CPMD coefficients, ChemGP HDF5, and UMA weights stay on their current writers. Putting them in a CON section makes every reader, seams included, depend on a parser change for data the ionic restart does not need.

A path-only trajectory id is what makes `frame_idx` a sequence. The old id mixes path and text, so each rewrite is a new one-frame trajectory and a streaming append never joins it. New writes use the path id. Old rows stay readable under the keys they have. Two ids in one process, which is C's split between checkpoint (path plus text) and movie (path only), means a resumed job and a plotted movie disagree about which key is current. One id rule for new writes.
