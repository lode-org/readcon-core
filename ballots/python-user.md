## Why A, then B, then C

A is the plan that keeps the facade, the file, and the writer default, and that makes the import `plt_con.py` already performs succeed.

`con_io` stays the only CON read and write in chemparseplot. `read_first_atoms` becomes `read_first_frame` then `to_ase`. `write_con_frames` keeps precision omitted and canonical left off. `frame_with_positions` is the geometry edit that copies `Atom` rows and leaves `fixed`, `atom_id`, `mass`, velocities, forces, displacements, and spreads in place, which is what an unmoved or purely translated image needs. `from_ase` stays the path for a structure that was never a `ConFrame`. rgpycrumbs deletes its private `write_con` wrapper and calls that module. `pos.con` is `write_con_frames` of the parsed peak frame, which is the restart `SaddleSearchJob` opens. The three api names are added before rgpycrumbs bumps, with `.con` going through `con_io` and `fmax` taken from the force column. `parse/trajectory/neb.py` `load_trajectory` stays the extxyz / `.traj` reader. `format="eon"` reads under `parse/eon` and `gpr_optim`, and the fixture writers in both packages, move in the pin commit. Neither package gains readcon-db. rgpot's floor moves in pixi, `_read_eon_con` is deleted, and the potential does not open a corpus. Pins move in one commit per repository, after a 0.17.1 wheel exists. Until that wheel is on PyPI, `readcon>=0.17.1` does not resolve, and a script floor that does not resolve is a broken `uv run`.

B is second because the seed contract and the catalog call are real, and the plot packages still have a `.con` they can open when the database is absent. B then standardizes the wrong switch. `write_con_frames`, every rgpycrumbs `write_con`, `atoms_to_con`, and `process_catalog.py` pass `canonical=True`. On this writer `header.metadata` is a `BTreeMap`, sections are emitted in a fixed order, and `self.canonical` only disables the metadata cache. The flag does not change bytes today. The day the comment is implemented, every plot file diverges from `ConFrameWriter::new`, which is the spelling `savecon` already uses once precision is omitted. B also lets `load_movie_and_table`, `load_profile_rows`, and `plt_kmc` call `get_frame_text` when a database happens to sit beside the job. After the trajectory id becomes the path alone, that read can show a different history than the file. The file is the copy I can open. B adds a readcon floor to rgpot's core `pyproject.toml`. That file has no readcon dependency. Every install of the potential would pull a CON library the potential does not call. B keeps rgpycrumbs on its own `write_con` instead of `con_io`, so the boundary test and the CLI can drift again.

C is last because it breaks the two production paths this persona actually runs. It does not add `load_trajectory`, `plot_con_overview`, or `plot_con_overlay`. `plt_con.py` imports those names at module level, and the sentence that a `.con` load goes through `con_io` does not change the import that fails. `write_con_frames` also appends to a corpus, and rgpycrumbs pixi gains readcon-db, so a missing database fails the plot. The numeric contract is `coords_array`, which walks atoms. The column copy on a parsed frame is `xyz`. C's risk note that the library can later retarget `coords_array` onto the SoA collapses the reason that method exists: an in-place edit of `atoms[i].x` shows up there, and `xyz` stays the parsed column. `frame_with_energy`'s constructor clears `inner`, so those two views are allowed to diverge after an energy edit. Aligned images stay `from_ase`, which drops displacements and spreads and, on 0.17.1, writes the peak forces onto the moved positions because `to_ase` attached a `SinglePointCalculator` and `Atoms.copy` keeps it. `eon/restoreFileForces` will trust those forces. The ASE adapter in rgmin starts loading a `.con` where `Optimizer.read` raises today. `test_todict_and_restart_refusal` survives only because its fixture is JSON. A caller who passes a path and expects the raise will see positions move, and FIRE or L-BFGS will start with empty history. C also leaves `tests/test_cli_plotting.py` `_write_con_file` on `ase.io.write(..., format="eon")`. That helper becomes a red test the moment the floor is 0.17.1, or a green test that never parsed a legal frame.

The gap under 0.83 is A's seed sentence and A's ops section. `displacement.con` is allowed to be `from_ase` of the shifted atoms or `frame_with_positions`, and the helper as specified leaves forces in place. That is the stale-force bug B's calculator clear fixes. The ops section describes an API the eOn pin does not contain. Those are repairs. They are not a reason to turn canonical on, to read a corpus from a plot, or to skip the three api names.

## The eight errors, as checked

3. **Holds.** `rkrdb_extend_trajectory_frame` and `rkrdb_extend_trajectory` are in `include/readcon-db.h` on tag `v0.1.8` and on `0725c94`.
