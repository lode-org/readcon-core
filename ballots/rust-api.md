# Ballot: Rust numerics and API designer

Persona: rgmin and rgsaddle. The libraries a host calls. Clean Rust APIs, the C ABI those crates already ship, and no dependency the stepper does not use.

Trees checked for this vote: `design/consumers-A.md` at `97d352e`, `design/consumers-B.md` at `06044cc`, `design/consumers-C.md` at `80cf36a`, and the critique at `860571e`. Consumer pins are the ones that critique names. readcon-core is tag `v0.17.1` (`96fd38f`); `main` is two commits later and the writer, the Python accessors, and `cell_vectors` are the same on both.

## Vote

`Vote: A > B > C`

Confidence: 0.84

Expected others: A

A is the API I would ship for these two crates. B is the host contract I would write beside it. C adds a library neither crate needs and changes a refusal the tests already lock.

## What I verified

All eight errors in the critique are in the trees.

1. readcon-ops `4d7881a` is `src/readcon_ops/match.py` and `wulff.py`. The public names are `identical`, `internal_motion`, `rotate`, `rotational_match`, `spacegroup`, and `wulff_vertices`. The package docstring says it does not read a file. `pyproject.toml` depends on numpy, spglib, and minimage. There is no `frames.py`, `_from_conframe`, `as_frame`, `_is_protocol`, `_is_conframe`, or `lengths_angles_to_cell`. eOn's pixi pin is that rev. `eon/structure.py` `Structure` has `r`, `box`, and `names`. `eon/atoms.py` passes that object to `spacegroup` and `rotational_match`. A's ops section describes an API the pin does not contain.

2. `sinp::readConCorpus` calls `rkrdb_get_frame_text`, closes the database, parses with seams' `read_con_string_iterator`, then `cloudFromHandle` on that local handle and `free_rkr_frame`. The tree has no `rkrdb_get_frame` call. The `meson.build` comment is the constraint it states: the db crate vendors its own core, and seams does not free that handle with this build's `libreadcon_core`. The live bug is real. `cloudFromHandle` keeps the SoA only when `xyz[1] == atom.y` and `xyz[2] == atom.z`, and otherwise copies `atom.x/y/z`. A tells seams to stop a handle exchange the decoder does not perform, and then prefers `rkrdb_get_positions`.

3. `rkrdb_extend_trajectory_frame` and `rkrdb_extend_trajectory` are in `include/readcon-db.h` on tag `v0.1.8` (`0001a2c`) and on `0725c94`. Rust `ConCorpus::extend_trajectory_frames` is on both. `extend_trajectory_str` and `rkrdb_extend_trajectory_str` are on neither. Python `ConCorpus.extend_trajectory` calls `extend_trajectory_path_units`. Python `append_trajectory_frames` imports the installed `readcon` wheel and calls `write_con_string`. A is right about that wheel call. A is wrong to treat `rkrdb_extend_trajectory` as a symbol 0.1.9 might still have to grow, and to soft-skip when it is missing. It is already the symbol eOn can `dlsym`. What 0.1.9 still has to add, if a caller must append text with no path, is the str form C names. A C function that extends many in-memory frames in one call is also absent. The Rust slice method is not.

4. `CPMDC_RESTART_ANGSTROM_PER_BOHR` is `0.529177210859`. `print_triples` multiplies by it to print angstroms. `patch-positions` divides by it to store bohr. The header comment identifies OpenCPMD `cnst%fbohr` as `1/0.529177210859`, which is the reciprocal of the macro the tool actually multiplies by. `CPMDC_BOHR_TO_ANGSTROM` in `src/cpmdc_params.h` is a different number, `0.529177210903`. B's `export-con` converts bohr to angstrom with ``1/0.529177210859``. A and C name the restart macro and multiply by it.

5. The eOn client constructs `ConFrameWriter(path, compression, precision)` with `kConPrecision = 17` and `kConvelPrecision = 6`, which is `FloatFormat::DecimalPlaces`. `eon/fileio.py` `savecon` calls `write_con_string([frame])` with precision omitted. chemparseplot `write_con_frames` and the rgpycrumbs `write_con` calls do the same, and the Python default is `canonical=false`. `FloatFormat::default` is `RoundTrip`. `create_writer_from_path_c` passes `precision = None`, which is `ConFrameWriter::new`. `header.metadata` is a `BTreeMap`. `refresh_metadata_cache` inserts keys from that map and writes sections in a fixed order. `self.canonical` turns the metadata cache off and is not read while the scratch is filled. On 0.17.1, `canonical=True` does not produce a second spelling. The production Python path that still passes a precision is `eon/process_catalog.py`, `readcon.write_con_string([frame], 17)`. A and C do not name that call. B does, and then also turns canonical on.

6. `group_prepared` returns immediately when `prepared.len() < 2`. `pack_aligned` emits `0xFD 0x03` only for a run with more than one frame inside that call, and only when the group is shorter than the per-frame values. `rkrdb_extend_trajectory_frame` prepares one frame. `Dynamics::run` and every other `matter2con(..., append=true)` hand the writer one new frame. A movie appended one frame per step stays a sequence of `0xFD 0x01` or raw UTF-8. A full-file `append_trajectory_str` or `rkrdb_append_trajectory` of many frames in one call can group. B says a dynamics or band trajectory fills a 64-frame group, and its eOn change extends one frame at a time. B's later claim that a short band shares a group with the next stored band of that trajectory is the same mistake across calls. A's 64-frame buffer matches the codec. C's `trajectory_append` groups when the caller hands it an aligned run in one call.

7. `ConFrame.coords_array`, `velocities_array`, and `forces_array` copy `Atom` fields. The SoA copies are the getters `xyz`, `vel`, and `frc`, which use `positions.f64_slice()` when `inner` is set. `disp` and `spread` walk atoms even as getters. `to_ase` copies `atom.x/y/z`. It does not call `coords_array`. `atom_ids_array`'s docstring says "atomic numbers"; the values are `atom_id`. C names `coords_array` as the numeric read of a parsed frame, including inside `to_ase`, and its risk note says the library can later make those three methods read the SoA if a witness fails. That collapses the documented reason `coords_array` exists, which is that an in-place atom edit shows up.

8. `append_trajectory_str` commits with `replace_meta = false`. `commit_prepared` returns `TrajExists` as soon as `traj_meta` has that id. The bytes are not compared. `workflow_dedup_identical_ingest` stores one file under two trajectory ids and dedups in `unique_frame_keys`. eOn's mirror calls `rkrdb_append_trajectory_str` and ignores the status, so a second insert of the same id fails quietly today. C's contract that identical stored text is success is new code in front of that call.

## Why A

rgmin and rgsaddle stay libraries. A file format inside `Solver::step`, `minimize`, or `rgsaddle_band_step` would couple a conjugacy reset to a parser. Both `Restart` and `BandSession::restart` already mean "drop stepper memory." A keeps those names and puts the file on a free function.

A's rgmin feature is the shape I want. `readcon = ["dep:readcon-core"]` with `readcon-core = "=0.17.1"`, not in `default`. `src/con_checkpoint.rs` exists only with the feature. `write_checkpoint` takes the `Report`, the symbols, the masses, and the cell, and it errors when `coords.len() != 3 * symbols.len()`. A finite `Report.value` is `set_energy`. A non-finite value omits the key. `read_checkpoint` returns the position slice and the energy, which the host passes back as `init`. `Report` gains no path field. There is no readcon-db and no LMDB on the minimizer. `include/rgmin.h` does not grow. The ASE adapter keeps raising. A `.con` path that starts moving atoms would be a second meaning of `restart` in the class that today refuses JSON. A does not add that meaning.

A's rgsaddle changes are the numeric ones. The read pin moves to 0.17.1 because 0.14 accepts values 0.17.1 rejects, and `tests/io_cells.rs` is fixed if a fixture relied on that, not the parser. `cell_from_header` calls `cell_vectors` and deletes the local `cy` / `cz_squared` block, so an orthogonal rounding crumb that the writer already clamps does not become a saddle-only rejection. `frame_from_con` copies `positions.f64_slice()` once into the owned `Array1`. The per-row `as_f64_row` into a second `Vec<[f64; 3]>` goes away. `write_restart` and `write_band` fill `positions_mut` from that slice and take the symbols in the same order. They do not invent `X`. `build_with_permutation` is for a host that must keep a parallel array through species grouping. A writer that already has coordinates and symbols in one order does not sort again to rediscover the map. `read_nth_frame` is the indexed read. `read_all_frames` to keep image `k` is the call that does not land. `store_band` calls `append_trajectory_frames_with_float_format(..., FloatFormat::RoundTrip)` once, so a band under 64 images can group when the group shrinks. The `readcon-db = "0.1"` requirement, which can resolve to the 0.1.8 tag and pull `readcon-core = "=0.16.1"` beside a direct 0.17.1 pin, becomes 0.1.9 with `=0.17.1`. Default CI stays `--features capi`. The new job is a separate feature invocation.

That optional writer is not a production feature until eOn or another host calls it. I will not describe `store_band` as a campaign corpus. The read pin, the one copy, and `read_nth_frame` are what a host can use as soon as the golden exists. Landing the function in the right shape, off the default link line, does not change `cargo test` or the `capi` row. Leaving the loop and the local cell formula in place until a caller appears would freeze the copy I am voting to delete.

`positions_dlpack` is the interop for a host that already has a tensor. It is not a reason to put CON inside `rgmin_minimize`, and it is not a reason to copy into a fresh array before the export.

The writer these functions call is `ConFrameWriter::new`. No precision argument. Canonical stays off. The flag does not change bytes today, and the comment says it will sort keys and reorder sections the day someone implements it. A test that `DecimalPlaces(17)` differs from `ConFrameWriter::new` belongs once, in readcon-core, next to the golden.

A's rank is this API. It is not permission to implement the three errors above. The ops package at the pin we already run compares `Structure` as it is. Churning that pin to chase `frames.py` has no caller. seams keeps text, then its own parser, through the wrap bump. The `xyz[1] == atom.y` heuristic can die in that bump, with a bit check on `rkr_frame_xyz_f64` of a frame seams parsed. `rkrdb_extend_trajectory` is used as the symbol that already exists. The 64-frame buffer is what makes a group. It is not a request for 0.1.9 to invent the path extend.

## Why B is second

B leaves rgmin's `Cargo.toml` alone and writes the host contract next to `Lbfgs::with_capacity`. The ASE refusal test stays the proof. That matches the library as it is shipped: eOn and rgsaddle own the geometry file, and a writer inside rgmin has no production caller until one of them uses it. I accept that sentence. I do not accept it as a reason to keep the wrong numeric read.

B's rgsaddle API is `frames_from_con` plus `write_band_con`. `BandSession::restart` stays the wipe. `src/capi.rs` does not grow a disk format. The corpus append waits on the db release. Those boundaries are right. The body is not. `frame_from_con` keeps the `as_f64_row` loop, and B calls that loop the Rust equivalent of `rkr_frame_xyz_f64`. The equivalent of the column pointer is `f64_slice()`. The per-row copy is the one to delete, and it does not depend on whether the write function lives in rgmin or in the host. The local `cy` / `cz_squared` block stays, so rgsaddle keeps a second lattice formula, including the orthogonal rejection `cell_vectors` no longer has. `write_band_con` sets `canonical=True`. That is the wrong switch. `ConFrameWriter::new` is RoundTrip with canonical off, and the flag does not change the bytes.

B's corpus story does not match the codec I checked. One `rkrdb_extend_trajectory_frame` per dynamics step never fills a group. A later band does not join a group written by an earlier call. The eOn change that would implement that story also turns velocities on for `dynamics.con` and reads the last movie frame when `main.checkpoint` is set, in the same commit as the spelling cutover. That is a new job behavior on a file that is a geometry history today. The bohr factor on `export-con` is the reciprocal of the constant `print_triples` multiplies by, so the CON would not be the angstrom file the client reads.

B is second because the host boundary and the untouched C ABI are real, and because it is the only design that names `process_catalog.py`'s explicit `17`. It is not the numeric API.

## Why C is last

C replaces rgsaddle's `readcon-core` dependency with a new `readcon-xfer` crate and turns the unused `readcon-db` feature into an alias of that facade. `frame_from_con` then depends on a crate whose job is restart, checkpoint, and trajectory. The header, the masses, and `lattice_vectors` are still what the function needs, so the facade hands back a `ConFrame` and the saddle code keeps doing the real work, still through `as_f64_row`, still through the local cell block. The chemfiles feature is left as a later change. That is an unused flag. The C ABI we already install is `include/readcon-core.h` and `include/readcon-db.h`. A second header is another link line, which is the regression the default and `capi` rows exist to prevent.

rgmin grows `src/geom.rs` behind `xfer`, which is the same optional-module idea as A, and then the Python ASE adapter starts honoring a `.con` restart and appending a `.con` trajectory. The Rust default row stays clean. The Python behavior does not. `test_todict_and_restart_refusal` survives only because its fixture is JSON. A caller who passes a path and expects the raise will see positions move, and FIRE or L-BFGS will start with empty history. Documenting the wheel as lazy does not make that the old contract. `Optimizer.read` refuses every restart today. That refusal is the baseline.

C's numeric read of a parsed frame is the atom list. `coords_array` is the wrong witness for a bit check, and `to_ase` does not call it. Identical-text success is not `append_trajectory_str`. A second insert of an existing id is `TrajExists` whether or not the text matches. The C optimizer headers stay free of CON, which is the one boundary C shares with A and B and the reason C is a design I can still mine rather than a design I can rank above B.

## What the final plan must take from B and from C

From B, the plan keeps these and drops the rest of B's rgsaddle and eOn writer:

- The host contract, stated next to `Lbfgs::with_capacity`. rgmin returns the accepted point through the stepper API the host already has. `Solver::step` and `minimize` do not open paths. A's `write_checkpoint` is the function a host calls when it wants a file. It is not a production caller until that host uses it, and the ASE refusal test stays the proof that `restart=` still raises.
- `frames_from_con` as the explicit full-band read, separate from `read_nth_frame` for image `k`. A host that needs every image calls the first. A host that needs image `k` does not parse the others.
- `neb_bead` on a band frame, so the image index is in the header and file order is the fallback.
- `eon/process_catalog.py` moves in the writer commit. `readcon.write_con_string([frame], 17)` becomes `write_con_string([frame])` with precision omitted and canonical left off. A and C forget that call. It is the saddle text the catalog reloads.
- One golden byte string, generated by `ConFrameWriter::new` on 0.17.1 and downloaded by the consumer jobs. The test is `cmp`. A per-repo re-encoder is not a witness.
- `cpmdc_restart_set_cell` on the way back into the binary `RESTART`, so a geometry step does not leave the CON cell and the coefficient file's cell as two cells. The conversion multiplies and divides by `CPMDC_RESTART_ANGSTROM_PER_BOHR`. It does not use B's reciprocal, and it does not use `CPMDC_BOHR_TO_ANGSTROM`.
- For `displacement.con`, clear the calculator before `from_ase`, and require `has_forces` false on the reloaded file. `frame_with_positions` is the edit that keeps forces and displacements when those sections are still true. One helper that always preserves forces cannot serve both files.
- Dynamics velocities stay off this cutover. `matter2con` remains `with_velocities=false`. A resume from the last `dynamics.con` frame is a later job, after `ApproveConFileIO` has moved once.

From C, the plan keeps these and does not create `readcon-xfer`:

- `extend_trajectory_str` / `rkrdb_extend_trajectory_str` in readcon-db 0.1.9, for a caller that must append text without a path. `rkrdb_extend_trajectory` and `rkrdb_extend_trajectory_frame` are already in the 0.1.8 header. Python `append_trajectory_frames` stops importing the wheel and calls `append_trajectory_frames_with_float_format(..., RoundTrip)` inside the crate, which is the part of A that is already right. A one-frame extend still does not group. The 64-frame buffer is how a group appears.
- The three equalities, with the Python side on the column getters. The UTF-8 from `ConFrameWriter::new`, from `write_con_string` with precision omitted, and from `get_frame_text` after a group decode are one byte string. The xxh3-128 of that UTF-8 is the stored hash. The f64 bits from `rkr_frame_xyz_f64` and from `xyz` / `vel` / `frc` match on a frame just parsed from that UTF-8. `coords_array` stays the atom-list view. `get_positions` and `rkrdb_get_positions` are not the restart witness. Cooked SoA stays labeled non-authoritative.
- The uncompressed foreign tail is parsed before concatenate. A parse failure returns `AppendError` and leaves the bytes untouched. A's scratch file stays until a later FFI. RoundTrip does not need a new buffer API to delete it.
- `include/rgmin.h` and `include/rgsaddle.h` stay free of CON. A C program that wants a file links `libreadcon_core`, or links the crate that actually writes, on its own. `rgsaddle_band_restart` stays the in-memory wipe. Symbols are an argument of every write. A missing symbol vector is an error, not the element `X`.

I am not adopting B's canonical flag, B's one-frame extend as a grouping strategy, B's bohr reciprocal, B's dynamics resume inside the spelling commit, C's facade crate, C's ASE `.con` restart, C's identical-text success, or C's `coords_array` contract.
