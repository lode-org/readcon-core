## The grammar that is already law

CON UTF-8 is the record. A corpus is an index of that text. xxh3-128 is over the UTF-8, so the hash follows the text and ignores the compression. Callers address `(traj_id, frame_idx)`. `get_frame_text` is the conforming read. `get_positions` prefers a cooked RCSO blob, and `corpus.rs` says that blob is not fully equivalent to CON.

`FloatFormat::default` is `RoundTrip`. `ConFrameWriter::new`, `create_writer_from_path_c` (`precision = None` → `ConFrameWriter::new`), `create_writer_from_path_round_trip_c`, and Python `write_con` / `write_con_string` with precision omitted all land there. `with_precision` is `DecimalPlaces`. eOn's client constructs `ConFrameWriter(path, compression, precision)` with `kConPrecision = 17` and `kConvelPrecision = 6`. That is a different spelling. `eon/fileio.py` `savecon` already omits precision. `chemparseplot` `write_con_frames` and the rgpycrumbs `write_con` calls do the same, and the Python default is `canonical=false`.

`header.metadata` is a `BTreeMap`. `refresh_metadata_cache` inserts keys from that map and writes sections in a fixed order. `self.canonical` turns the metadata cache off and is not read while the bytes are emitted. On 0.17.1, `canonical=True` does not produce a second spelling. The comment that says the flag sorts keys and reorders sections is ahead of the emitter. A conformance rule that turns the flag on standardizes a switch that changes nothing now and will change bytes the day the comment is implemented.

`build` stamps `con_spec_minor` 1 (`CON_SPEC_MINOR`) when the caller did not, and inserts `default_v3_units_json()`: length `angstrom`, energy `eV`, mass `amu`, no time key. A minor-1 frame with velocities and an empty `units.time` fails the writer with `InvalidUnits`. The natural time label is `(amu*angstrom^2/eV)^0.5`. Two masses for one symbol fail `MassMismatch`. Column 4 is an integer token. NaN and Inf are rejected. Old 0.16 files still have to parse. Repair a file the new parser rejects. Do not widen the parser.

The 64-frame group is an internal value. `group_prepared` returns immediately when `prepared.len() < 2`. `pack_aligned` emits `0xFD 0x03` only for a run with more than one frame inside that call, and only when the group is shorter than the per-frame values. A one-frame extend stays `0xFD 0x01` or raw UTF-8. A full-file append of many frames in one call can group.

H5MD export already lives in readcon-db (`src/export_h5md.rs`). This adoption does not grow a second restart container. Optimizer pairs, `mode_cp.dat`, `direction.dat`, `eon_hess_ckpt`, CPMD plane-wave coefficients, ChemGP HDF5, and UMA weights stay on their current writers. Putting them in a CON section makes every reader, seams included, depend on a parser change for data the ionic restart does not need.

The production baseline that this cutover must keep:

- Forces stay opt-in. The client comment says ASE-class readers reject a forces section, and `restoreFileForces` trusts a forces section that is present.
- `matter2con` passes `with_velocities=false`. A dynamics movie is a geometry history. Velocities exist on the `matter2convel` path. Writing velocities into `dynamics.con` in the same commit as the spelling change is a section-grammar change.
- The mirror `dlopen`s `libreadcon_db`. A missing library returns without changing `IoStatus`. Windows compiles the mirror out (`#if !defined(_WIN32)`). `client/meson.build` already records `STATUS_ENTRYPOINT_NOT_FOUND` for a second `readcon_core.dll` on `PATH`.
- An uncompressed append whose tail fails to parse returns `AppendError` and leaves the file alone.
- `append_trajectory_str` commits with `replace_meta = false`. `commit_prepared` returns `TrajExists` as soon as `traj_meta` has that id. The bytes are not compared.
